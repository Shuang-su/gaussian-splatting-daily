## SplatTransform 将 SOG v3 设为默认输出

默认输出切换后，新导出的 SOG 使用 v3 表示。生产交付应先查查看器的读取版本，并用既有页面回读新文件再决定是否切换默认。

旧查看器兼容性是本期主要风险。保留可重转的源文件与已验证的写入器版本。

[来源](https://github.com/playcanvas/splat-transform/pull/370)

## SPZ v4 增加可跳过的逐点属性块

SPZ v4 使用 zstd 可跳过帧承载任意逐点属性，旧 v4 读取端仍可读取主体。需要这些扩展属性的应用应验证解析、保存和重新导出。

旧 reader 能打开并不保证它会保留扩展属性。

[来源](https://github.com/nianticlabs/spz/pull/107)

## Blender 5.3 正式加入原生高斯支持

Blender 5.3 可从 PLY、SPZ、USD 和 glTF 导入高斯，并在 Workbench、EEVEE、Cycles 中渲染。用户可以在熟悉的三维创作环境里安排扫描与其他对象；这一版本尚不支持原生高斯导出，不能据此认为格式往返已经完整。

[报道与来源](https://radiancefields.com/blender-5-3-ships-with-native-gaussian-splat-support) · [原始材料](https://developer.blender.org/docs/release_notes/5.3/)

## QGIS 高斯支持进入众筹阶段

Lutra Consulting 与 North Road 为 QGIS 的二维、三维视图高斯支持发起众筹，计划通过 3D Tiles 交付，并以 2027 年版本为目标。当前是筹资与实施计划，不能写成已经可以在正式 QGIS 中使用。

[报道与来源](https://radiancefields.com/lutra-and-north-road-crowdfund-gaussian-splats-for-qgis) · [原始材料](https://www.lutraconsulting.co.uk/crowdfunding/qgis-3d-reality-capture-animation)

## Niantic Spatial 测试可移动的扫描物体

Niantic Spatial 的场景变化测试功能从扫描中拆分可移动物体，并附上碰撞信息和估算物理属性，供仿真使用。它让同一采集环境可以产生不同布局；物理属性是估计值，不是从图像直接测得的真值。

[报道与来源](https://radiancefields.com/niantic-spatial-makes-splat-objects-movable-in-simulation) · [原始材料](https://www.nianticspatial.com/blog/introducing-object-interaction)

## BurnerSphere 保存艺术装置的昼夜高斯

《Do Baskets Dream of Shores or Sea》将越南篮船与灯笼组合成 Burning Man 装置，并通过白天、夜间两份高斯在 BurnerSphere 展示。不同光照下的作品被分别记录，适合作为活动结束后仍可进入的空间档案。

## SOG 导出稳定性两端同时修复：SuperSplat 处理 device loss，SplatTransform 限制 k-means 单次 GPU 工作量

Editor 在压缩设备丢失后销毁缓存 device、给出可重试错误，下一次导出重建设备；转换器同时销毁泄漏的 Compute 对象，并按 centroid range 拆分 SH palette k-means，避免长 command buffer 触发 macOS GPU watchdog。

:::details[发布内容与使用条件]

- **一手来源**：[SuperSplat PR #1094](https://github.com/playcanvas/supersplat/pull/1094) / [`c061d0d`](https://github.com/playcanvas/supersplat/commit/c061d0d6a56c730487f90e7683eee09422864e56)、[SplatTransform PR #372](https://github.com/playcanvas/splat-transform/pull/372) / [`65ad6e2`](https://github.com/playcanvas/splat-transform/commit/65ad6e235549655ad7945e93c82c7846d207cc1b)。
- **新增**：Editor 在压缩设备丢失后销毁缓存 device、给出可重试错误，下一次导出重建设备；转换器同时销毁泄漏的 Compute 对象，并按 centroid range 拆分 SH palette k-means，避免长 command buffer 触发 macOS GPU watchdog。
- **实际影响**：对 627K splat 的 Apple GPU 导出故障是直接修复；#1094 让失败可恢复，#372 从根因降低 watchdog 风险。建议立即对 Mac 大场景 SOG export 做回归。
- **可运行性**：可实际测试；MIT；WebGPU；**可信度 B**。作者报告 M4 Max 大 palette 用例 2.19→2.09 s / 3.42→3.23 s，小用例 56→50 ms，主要收益是稳定性而非数量级加速。

:::

[原始发布](https://github.com/playcanvas/supersplat/pull/1094)

## X-Gaussian 新增真实 CT 数据、预训练模型和全套配置，研究原型首次形成可复跑的真实扫描路径

FIPS Pine、Seashell、Walnut 的 50-view training / 100-view held-out 数据与 Hugging Face 权重；加入真实扫描 config、FDK 初始化缓存和 conservative voxel culling。

:::details[发布内容与使用条件]

- **时间 / 一手来源**：2026-11-09；commit [`5bc233d`](https://github.com/caiyuanhao1998/X-Gaussian/commit/5bc233d062e100d9ddd78dff9cd769768b418f59)，[仓库](https://github.com/caiyuanhao1998/X-Gaussian)。
- **新增**：FIPS Pine、Seashell、Walnut 的 50-view training / 100-view held-out 数据与 Hugging Face 权重；加入真实扫描 config、FDK 初始化缓存和 conservative voxel culling。
- **口径**：作者列出的 3D 指标以 full-view FDK 为伪参考，并非实测 CT ground truth；不能和有真值合成集直接横比。
- **可运行性**：代码 + 权重 + 数据可跑；Linux、CUDA 11.8、Python 3.9、PyTorch 2.1.2、GCC 11，约 30k + 1k steps；**根目录未检到 LICENSE，许可待确认**；**可信度 B**。

:::

:::details[发布内容与使用条件]

- **一手来源**：[`2d018a2`](https://github.com/harry7557558/spirula-studio/commit/2d018a2fe85b8c1c4d7750689033774a6de6e736)、[`4c099ab`](https://github.com/harry7557558/spirula-studio/commit/4c099abdf5d689c1ccf7708af330a8df424fde17)、[`337cbea`](https://github.com/harry7557558/spirula-studio/commit/337cbea311bbf3ca3c8271789c1847d4e88484bb)。

- **可运行性**：可实际测试；GPL-3.0；Vulkan/CUDA；**可信度 B**。

:::

## visloc-rs CUDA backward 改为 per-warp staging，训练步 raster backward 约快 15%

每个 warp 独立 staging 32 splats，以 `__syncwarp` 代替 block-wide 协调，并从该 warp 最后 blended entry 反向遍历。

:::details[发布内容与使用条件]

- **一手来源**：[PR #500](https://github.com/rsasaki0109/visloc-rs/pull/500)，merge commit [`8640046`](https://github.com/rsasaki0109/visloc-rs/commit/8640046f6df0a9138c1b1f7ad0d75dd6aa957443)。
- **新增**：每个 warp 独立 staging 32 splats，以 `__syncwarp` 代替 block-wide 协调，并从该 warp 最后 blended entry 反向遍历。
- **性能口径**：作者在 south-building 1.35M scene 报告 `raster_bwd` 约快 15%（每步约省 0.9 ms），30k steps 698 s vs 711 s；held-out 22.92 vs 23.02 dB 属运行波动范围，未宣称质量提升。
- **可运行性**：可实际测试；MIT OR Apache-2.0；Rust/CUDA；**可信度 B**。

:::

[原始发布](https://github.com/rsasaki0109/visloc-rs/pull/500)
