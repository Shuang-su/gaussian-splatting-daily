## SplatTransform 加快 SOG 打包，同时修复 PLY 读取

SplatTransform 在开发分支[合入 SOG 生成优化](https://github.com/playcanvas/splat-transform/pull/340)。它一方面改进没有半精度着色支持时的聚类计算，另一方面让下一块数据的 GPU 运算，与当前块的 CPU 编码、写入重叠进行，减少等待。

作者使用 NVIDIA A10G 转换一个 500 万高斯的场景，普通 SOG 的处理时间从 51.0 秒降至 31.8 秒；一组多级细节数据的流式合并从 144.5 秒降至 69.9 秒。代价是同时驻留更多数据，后者的 CPU 内存峰值由 1.95 GB 升至 2.16 GB，GPU 峰值由 130 MB 升至 260 MB。

收益也与设备有关。M4 Max 使用另一条半精度计算路径，普通 SOG 转换时间变化很小，流式合并则从 56.4 秒降至 44.4 秒。新增的 `--lod-file-count` 还允许为不同细节层设置文件打包粒度，方便在请求数量、单文件大小和加载速度之间取舍。

另一项 [PLY 读取修复](https://github.com/playcanvas/splat-transform/pull/341)支持正确解码普通大端二进制 PLY，并明确拒绝尚不支持的 ASCII PLY，避免把输入静默读成错误数值。大端压缩 PLY 仍不在支持范围内。

截至本期观察时间，正式版本仍是 3.8.0，上述变化只在主分支。对已有大场景发布流程，适合固定同一批输入，同时比较转换耗时、峰值占用和生成文件；作者的 A10G 结果不能直接套用到其他显卡。

## SuperSplat 为独立头显调整预算，加入双手操作

SuperSplat Viewer [修正了对独立头显的设备判断](https://github.com/playcanvas/supersplat-viewer/pull/322)。Quest、Pico 浏览器可能被识别成 Linux 桌面环境，继而使用 400 万个高斯的桌面预算，而头显还需要为双眼绘制画面，负担明显更高。

新实现将独立头显的流式场景默认预算设为 100 万，保留用户显式设置，并结合注视点渲染和可选的较低分辨率。作者在 Quest 3 的一个场景中测得，质量模式从 9.7 fps 提升至 30.7 fps，性能模式为 40.3 fps。Pico 当时只有识别逻辑，尚无真机验证；单文件场景也不适用流式预算。

同批更新[加入双手移动、旋转和缩放](https://github.com/playcanvas/supersplat-viewer/pull/323)：握住两侧控制器，或用手部追踪做握拳动作，可以把大型环境缩成面前的模型。退出 XR 后会恢复原始位置，避免影响相机、碰撞和标注。操作时仍需重新排序，作者的 Quest 3 测试中帧率有所下降，松手后恢复。

此外，XR 的[细节选择改为只看距离](https://github.com/playcanvas/supersplat-viewer/pull/324)，避免刚转到眼前的区域仍沿用“身后内容”的低细节设置。固定总预算下，这也会重新分配各方向的细节；作者的脚本测量有所改善，但 Quest 3 对比中未观察到明显画面差别。

这些变化尚未进入当时的 Viewer 1.36.2。准备做头显导览的团队，可以把预算、双手操作和退出复位作为一组验证，尤其关注实际场景在连续转头和抓取时是否流畅。

## Spirula 让 GPS 在重建过程中约束相机位置

Spirula 的开发分支[将 GPS 纳入相机与场景重建过程](https://github.com/harry7557558/spirula-studio/pull/130)。过去，GPS 主要在重建完成后用于校准尺度与位置；现在，它还能帮助选择图像匹配对、优化相机位置，并拒绝明显偏离轨迹的注册结果。

这项改变针对的是林下、弱纹理等难以仅靠照片匹配的区域。如果某段航线被错误连接，事后整体对齐往往无法修复局部偏移。新默认模式会根据 GPS 信息选择约束方式：有可靠高度时使用完整位置，没有可靠高度时只约束水平方向；缺少 GPS 时保留原有流程。

更新也为保持水平的全景图加入方向先验，并处理了优化器在零旋转和小步调整时的问题。作者在一条困难航线上观察到相邻相机跳变减小，但公开结果中有一部分同时使用了后续接缝修复，不能全部归因于这一次提交。

截至本期观察时间，功能尚未进入 v2026.9.30 正式版，作者验证的平台为 macOS 和 Linux，Windows、CUDA 仍待验证。无人机与 360° 采集用户可以用同一条航线比较开启、关闭 GPS 约束后的相机轨迹和接缝，避免只看最终画面是否好看。

## LichtFeld 降低多个大型模型合并时的显存占用

LichtFeld Studio [优化了多模型的显示合并过程](https://github.com/MrNeRF/LichtFeld-Studio/pull/2620)。旧实现会把所有模型的球谐数据展开成一份浮点临时副本；新实现分批编码，并把量化输入的解码交给 GPU，减少额外占用。

作者将三个各含 500 万高斯的模型合并测试：量化输入的峰值显存从 5.4 GB 降至 3.7 GB，构建时间从 2.2 秒降至 0.13 秒；浮点输入的峰值也下降，但构建时间略有增加。后续[修复](https://github.com/MrNeRF/LichtFeld-Studio/pull/2621)还解决了预留内存容量与实际数据行数不同导致的失败。

这项改动适合多个分区或大型模型一起查看的场景，影响的是它们合成显示模型时的成本，并不表示单个模型的训练显存也会同幅下降。当时正式安装版仍为 v0.5.3，使用这一优化需要对应开发分支。

## LuluSplat 提供 Windows 版，通过 Vulkan 在本机训练

[LuluSplat v1.1.2](https://liquiduslabs.com/lulusplat/) 已提供 Windows 下载，让原先偏向 Apple 设备的一体化训练流程扩展到 Vulkan 显卡。软件可从照片、普通视频、360° 视频或已有 COLMAP 重建开始，完成相机解算与训练，导出 PLY、SPLAT。

Windows 版使用 Vulkan，Mac 版使用 Metal，均提供 Vanilla 和 MCMC 训练方式。软件还支持批处理、命令行和 MCP，适合需要连续处理多个采集项目的用户；媒体和训练过程可保留在本机。

当时官方给出的 Windows 门槛为 Windows 10／11 x64，以及支持 Vulkan 的 2016 年后 GPU。下载免费，但项目自身源码与软件许可未公开，不能因它使用开源组件就按开源产品集成。具体旧显卡能处理多大场景，仍需结合显存和训练数据判断。

## Gausser 将高斯资产接入 Cinema 4D 动画工具

Cinema 4D 插件 [Gausser 1.0.0](https://aescripts.com/gausser/) 支持导入 PLY、SPLAT 和 SPZ，并通过 Fields、效果器、变形器、力场与 Cloner 操作高斯资产。它让扫描场景可以参与熟悉的动效制作流程，例如逐渐显露物体、改变形态或随场景运动。

插件为 Standard、Redshift、Octane 和 Arnold 准备几何与材质，并可导出包含颜色、裁切与效果器结果的资产。导出格式与实时播放器的兼容情况，仍应按实际项目验证，不能仅凭扩展名判断全部效果都能保留。

Gausser 是面向 Cinema 4D 2026 及以上版本的商业插件，支持 Windows x64 与 Apple Silicon，提供 14 天试用。官方版本记录显示它于 9 月 30 日发布，本期补充收录。

## 两个实验项目探索可变光照与单图重建

[sun-conditioned-3dgs](https://github.com/hsiang0117/sun-conditioned-3dgs) 尝试让同一份高斯几何根据太阳方向改变外观，并把某个固定方向烘焙成普通 PLY。现阶段只有短时、小分辨率实验，完整训练的质量和成本仍待评估；它采用的上游许可也不是宽松商用许可。

[giro](https://github.com/kevinraymond/giro) 则把单图生成环绕视频、检查轨迹、分割、相机重建与高斯训练串联起来。它会先判断生成的视频是否形成可靠环轨，必要时补齐缺口或重新生成，再继续训练，反映出自动化流程中“发现失败”的重要性。

giro 当时仍是个人研究原型，要求 Linux 与两张 24 GB NVIDIA 显卡等环境。代码采用 MIT，所用模型各有许可；少量样例的成功，尚不足以说明任意照片都能稳定得到可用资产。
