# 高斯日报正文改版、历史补图与标签整理

## 1. 目标与本轮边界

以提交 `5454fed721c99a98b1e439351a3afa56df6f329f` 为起点，在独立分支 `codex/daily-article-layout` 完成 9 月 18—30 日全部 13 期的正文重排、视觉调整和配图补充。先完成 9 月 30 日的完整阅读流程，再应用到其余日报。

正文采用具体事件组织。原有 13 项继续承担研究覆盖检查，并逐步整理为分类、项目和来源属性。本轮以视觉与内容组织为主，保留原分析、事实限制、人工判断和增量，不统一改写行文风格。

本轮完成本地页面、标签数据、评论组件与新版每日任务说明；专题页面、组合筛选、真实 GitHub 评论接入和定时任务切换留到后续。现有首页方向、每日与每周 RSS 继续沿用。

## 2. 文章视觉与阅读结构

以 https://sspai.com/post/115197 的实际样式与批注为依据：

- 系统无衬线字体顺序包含 system-ui、PingFang SC、Hiragino Sans GB、Microsoft YaHei；正文常规字重，标题 600。
- ≥768px 正文 17px / 30.6px，最大宽度 680px；<768px 为 15px / 27px，左右边距 24px。
- 事件标题桌面 24px、手机 20px，取消可见分类序号，直接写项目和具体变化。
- 正文链接浅色 #0097FF、暗色 #33ACFF；默认无下划线，悬停与键盘焦点明确提示。
- 日期牌顶部 #DA282A；数字区浅色白底，暗色 #39393C、浅色文字；桌面 72px、手机 64px，圆角 16px。
- 每条主要事件结束后细分隔线与留白；图片、图注及讨论入口在分隔线之前。
- 往期独立背景区域展示此前最近 5 期，16px 圆角卡片、40px 日期牌、完整标题、右侧缩略图和“查看全部”。

顺序：封面与日期牌 → 标题、短摘要与日期 → 今日最值得看 → 主要新闻 → 简讯 → 论文与补充分析 → 本周重要内容 → 来源与纠错 → 本期讨论 → 往期日报与订阅。

页面只保留一个“今日最值得看”导读区。主要事件按阅读顺序编号，标题下恢复原有核心判断；接续简讯、论文、分析和本周重要内容跳转；较长论文与分析子目录在同一区域展开，不再重复 13 栏目录。

同一事件散落的工具、训练、社区内容合并，长篇人工分析保留在关联事件或“分析与实践”。编号仅用于导读与顺序步骤。短更新有独立来源、定位和讨论入口；无简讯时隐藏。主新闻与简讯不固定条数：按既定优先级为主，结合编辑判断，避免仅因篇幅短而降级。

本周重要内容按北京时间从周一到报告日期，只选此前日报，按优先级与日期排序、去重最多 5 条，排除本期展开事件和未来信息，无候选则隐藏。导读判断与正文共用内容数据，取消构建器机械插入“标题、优先级、可运行性、判断”。保留图片预览、目录定位及原生滚动。

## 3. 内容接口与标签体系

规范 Markdown 是唯一正文来源。允许重排 13 期标题与段落，但建立迁移对应，保留事实、来源、9 月 18 日下午增量、论文 marker 与人工分析。

增加可选事件布局和元数据：稳定 ID、正文锚点、标题、展示分组、判断、标签；正文 HTML、导读、评论入口、RSS 从同一模型派生。旧格式兼容。现有事件 ID、栏目锚点保留，移动或改名用映射，不由新标题重建身份。schema v1、source_count 的 arXiv marker 含义、首次归档论文身份、RSS GUID 和旧主题 URL 不变。

标签分为：

- 技术与生产环节：3DGS、动态高斯、采集、SfM、训练、分区训练、编辑、渲染、压缩、格式、LOD、流式加载、SLAM、XR、Avatar 等，可设父子关系。
- 项目与产品：OOOSplat、Spirula Studio、LichtFeld Studio、PlayCanvas Engine、SuperSplat Editor / Viewer、SplatTransform、LCC 等，稳定 ID、标准名称、别名与官方入口。
- 内容与来源属性：论文、版本发布、代码更新、标准、硬件、应用案例及官方、社区等；许可和可运行状态单独保留。

LCC 是 XGRIDS Lixel CyberColor 产品家族，Studio / Scene Editor / Model Editor 为子项目，软件与 .lcc 格式分别记录，参考 https://docs.xgrids.com/en-us/06-lixel-cybercolor/。13 期事件支持多个分类与项目，新标签没有对应页时不生成无效链接。独立项目页和组合筛选不在本轮。

## 4. 配图、评论与每日任务准备

逐条主要新闻检索对应版本的官方界面、项目演示、论文方法或结果图，重点补工具与应用；合适则插入段落，不合适保留文字，不为数量重复无关场景或海报。图注明确项目、用途和出处；旧演示注明，不作为当日功能、性能或未来状态证据。原图、来源、尺寸、校验值与 640 / 960 / 1600px WebP 保留，使用锁定 Sharp，不放大。必要标注完整显示，预览与失败回退复用。

评论组件按 giscus + GitHub Discussions 准备（https://giscus.app/zh-CN）。每事件末尾原位展开，按“日报 ID + 事件 ID”绑定，整期按日报 ID，标题修改不变身份。按需加载、保留展开状态、支持深浅主题、键盘、失败与返回阅读位置。本地验收样本明确标记有评论、空评论、失败；普通页面无样本或虚构计数，未配置服务隐藏提交框。预留仓库、分类、主题和回链，不启用 Discussions、不安装 App、不创建真实讨论。

准备原“3DGS / 4DGS 每日深度情报”任务新说明：研究继续检查原范围，成稿按事件，填写判断、分类、项目、来源与配图结果。校验由强制 1—13 编号改为研究覆盖与事件完整性；无新增和不可访问分开，历史只保留可证明的检查记录，不补造检索过程。准备图片附件和出处的受限校验；产品代码、schema、工作流独立审查。本轮只完成模板、校验与本地样例；原 08:00 调度和已保存说明不切换，待进入发布链后单独读回。

## 5. 验收与交付

先验收 9 月 30 日从封面到往期卡片，再检查 13 期。覆盖 375 / 390 / 430 / 550 / 768 / 1024 / 1440px 和浅色、暗色、系统外观。逐段核对迁移前后内容、判断、来源、增量、marker、事件身份，旧链接有效，导读和正文同序，构建无重复插入或遗漏。
