## 头图尺寸与 iPad 留白修复

用户指出 10 月 1 日的竖图把卡片撑高，以及 iPad 左侧留白不匹配。实测 1441px 时，其他四张卡片为 588px 高，竖图为 1409.14px；图容器的百分比高度仍受图片固有尺寸影响。图片现在完全填入独立比例区域，五张封面都保持同宽度下相同的卡片高度、标题分区和跨界日期牌。

本地冻结参考站已保存 `.feed__main` 两侧 44px 的 CSS，并有 768 / 1024px 的采集与截图记录；本次偏差来自移植和验收。原站实时 DOM 核对确认 820px 竖屏为 x=0、宽80px 的图标栏，列表 x=124、宽652px，左右各44px。此前本地页面使用左16px、栏宽64px、间距32px，列表从112px开始。修正也覆盖横屏与桌面三栏：1180px 时列表 x=330、宽520px、栏间距56px；1441px 时左右栏各200px、栏间距106px。

补验逐张选择五期轮播，检查 14 个实际 CSS 宽度的浅色/暗色，共 140 组，包含三个断点两侧。全部组内卡片/图片高度、日历位置和列表起点变化为 0，无横向溢出，日报元信息保持一行。430px 时临时阻断 ARKit 封面变体，失败提示、日期和标题仍在相同尺寸区域内；恢复请求并重载后图片正常，正常重载无浏览器警告或错误。视口模拟及网络规则均在交付前恢复。

尺寸模拟曾被旧标签页尺寸覆盖，先清除旧覆盖并检查实际 `innerWidth` 后才记录有效结果；无效测量未纳入 140 组。浏览器测量辅助脚本的一处解析函数不被只读环境支持，修正后重新完整运行；不是产品运行错误。
