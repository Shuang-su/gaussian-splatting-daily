## 2. SuperSplat / PlayCanvas 工具链

PlayCanvas Engine 的相关变化来自通用 3D 管线，而非 Gaussian renderer：[KHR_materials_diffuse_transmission #9558](https://github.com/playcanvas/engine/commit/cd55dc0a6cdb141282e2d58de76684480f3f8371) 为 glTF 导入、StandardMaterial、WebGL GLSL、WebGPU WGSL 与 glTF 导出补齐 diffuse transmission 的强度/颜色/纹理/vertex color，并从背面法线计算透射光，纳入 AO、metalness 和 shadow。对“splat 背景 + 叶片、纸张、灯罩等 mesh 前景”的混合场景有直接价值，但它不会改变 splat 排序或显存。

另外，[GPU pass timings #9842](https://github.com/playcanvas/engine/commit/5a00edc2202655b91049165def1dc54575b572d0) 保留每个 GPU pass 的独立、稳定顺序并加入 inspector profiling 脚本，[frame attribution #9838](https://github.com/playcanvas/engine/commit/642495d3f4ad0dbea0a979eb11050ad2c6188589) 标记异步 timing 属于哪一帧，[公开 RenderPass/CameraFrame hooks](https://github.com/playcanvas/engine/commit/831b13973f883888c6df0fbdc544cd3982fe97c1) 让应用更容易在 GS 前后插入自定义 pass。建议 WebGS 应用在升级 Engine 时回归混合透明、WebGPU/WebGL 一致性、GPU timing 与自定义后处理；不必回归 SuperSplat 文件格式。

## 3. 可实际运行的开源项目

### LichtFeld Studio：批量训练从脚本约定变成受监督 CLI

[6a7c00d1](https://github.com/MrNeRF/LichtFeld-Studio/commit/6a7c00d1fffce27e2f1e725299ca7569655cdc84) 新增 `batch-train`：可从目录、数据集或 manifest 解析多个 job，复用单场景训练参数，并把每个训练放进独立子进程。POSIX 用独立 process group，Windows 用 suspended child + Job Object；Ctrl+C、第二次强制停止与超时会传递到整个子进程树。`dry-run` 不触发 GPU preflight，可先检查解析结果。

[bf8f64f6](https://github.com/MrNeRF/LichtFeld-Studio/commit/bf8f64f66562e825d767d293d29eddc7fb485aeb) 随即加固：manifest 相对路径以文件所在目录解析；缺失/空数据集在任何 job 启动前失败；负 crop 值和 `-r4` 不再吞掉下一个数据集；共享/单 job 参数不能暗中覆盖 data/output 路径；viewer、resume、render 等会离开 headless training 的选项被拒绝；超时先温和终止，60 秒后清理整个进程树；summary/report 写失败也让 batch 失败。生产用法应同时锁定这两个 SHA，不要只锁首个功能提交。

### OOOSplat：0.7.1 是主线策略，不是可下载 release

[fbea2599](https://github.com/ooolabdev/ooosplat/commit/fbea25999948fcbf2b874fccebd8b13c02f8e198) 将应用版本与双语文档推进 0.7.1，但 GitHub Releases 仍只有 0.7.0 prerelease；因此当前只能从 main 构建或等正式包。普通精细档的策略 v2 上限为 `round(0.5 × sqrt(2462476 × 0.063362106 × X_eff / meanTrackLength))`，只计已注册训练图、排除 alpha=0 像素；全景继续用有效球面稀疏点数×40，并移除旧 10M 硬上限。这个值是增密 ceiling，不是最终 splat 数承诺。

明确 GPU OOM 才允许一次 80% 上限重试；取消、崩溃、DeviceLost、资源/文件错误不冒充 OOM，分辨率、steps、LR 与 densification 参数不变。作者报告 498 个 Rust、600 个前端和 7 个诊断测试通过，90 张真实图片只读核算得到 2,220,679 上限；同时明确没有完成桌面高分辨率完整训练、真实 OOM、macOS/Linux 端到端验收。值得 staging 验证，不宜替换 0.7.0 生产包。

### splatkit：移动端 sort 与 raster traffic 同时降载

[6592f2e1](https://github.com/Xget7/splatkit/commit/6592f2e1b824c1797b3d190ccaabbdf973e66015) 让 Metal、Vulkan、React Native、Android/iOS 默认使用 16-bit relative depth key，32-bit 变为显式选择。radix sort 从四个 8-bit pass 降为两个；配套提交让 close layers 以 near plane 之上的 float steps 编码，并让 Metal 从 key indices 开始排序，删除 identity value buffer 初始化。

维护者测试说明近景图像与 32-bit 的结果高于 50 dB，但没有给设备、场景和分辨率矩阵；当场景需要区分超过 65,536 个 near-depth step 时，远处会出现相同 key，应使用 32-bit。另一个 [6bd95add](https://github.com/Xget7/splatkit/commit/6bd95addea2866d738027c4bcb6232d0f9a3e662) 把顶点 RGB 压成 10:10:10 + 2-bit scale，并以 log2 opacity 复用 depth 通道，目标是减少 tiler/raster 传输；没有独立 FPS/功耗数字，必须在目标手机上测。

固定检查 [nerfstudio-project/gsplat](https://github.com/nerfstudio-project/gsplat)、[WebODM/OpenSplat](https://github.com/WebODM/OpenSplat) 与 [graphdeco-inria/gaussian-splatting](https://github.com/graphdeco-inria/gaussian-splatting)：本窗口没有新的代码、权重或正式 release。

## 6. Compression / Format / LOD / Streaming

- **文件格式**：SuperSplat、splat-transform 和 supersplat-viewer 没有 SOG/SPZ/PLY/GLB/glTF 新编码。PlayCanvas 的 glTF diffuse transmission 是 mesh material extension，不是 Gaussian extension。
- **运行时带宽**：splatkit 的 16-bit key 与 packed vertex 是 GPU sort/raster traffic 优化，不改变 SPZ/SOG/PLY 文件大小，也不提供 LOD 或网络 streaming。
- **训练预算**：OOOSplat 的 effective-pixel budget 控制允许增长的 splat ceiling，不是压缩 codec；全景取消 10M 上限反而可能增大输出，需独立做 SPZ/SOG 导出与移动端加载预算。
- **标准**：未核实到 Khronos glTF Gaussian extension、OpenUSD、3D Tiles、MPEG GSC 或 W3C WebGPU 在窗口内发布新的正式文本/tag。不能把论文或仓库草案写成标准落地。

### 尺度校准成为一等工作流

## 8. Avatar / Human / Generative 3D

### CGR-GS：代码、权重、数据准备路径都已公开

<!-- arxiv:2610.35152 -->
[CGR-GS（arXiv:2610.35152）](https://arxiv.org/abs/2610.35152) 是 NeurIPS 2026 的 sparse-view human GS：从 clothed mesh 的 normal/color 局部熵构造 complexity prior，用 3D offset head 让 Gaussian 脱离固定 pixel patch，并按 complexity 采样局部 patch。官方 [仓库](https://github.com/DCVL-3D/CGR-GS_release) 只有两个主提交但包含训练/评测源码、安装脚本与 rasterizer submodule；[v1.0](https://github.com/DCVL-3D/CGR-GS_release/releases/tag/v1.0) 提供 1,250,369,958 字节 checkpoint（SHA-256 `99cfa266…63b7d`）。

**编辑摘要：** 本期四篇论文中唯一达到“代码+权重可跑”的条目；真正价值是把 Gaussian 密度与人体局部复杂度绑定，但 THuman2.0、mesh 预处理和混合许可使它更适合研究复现而非直接产品化。

安装目标是 Python 3.10、PyTorch 2.5.0、CUDA 12.4、xformers，并需申请 THuman2.0；官方评测为 4 source / 16 target views、100 subjects，报告 PSNR 32.42、SSIM 0.9766、LPIPS 0.0201。原创代码 Apache-2.0，但 diff-gaussian-rasterization 继承非商用研究限制，因此整体不能简单标成“Apache 商用可用”。

### VidEdit3D：方法有吸引力，代码仍是占位

<!-- arxiv:2610.35756 -->
[VidEdit3D（arXiv:2610.35756）](https://arxiv.org/abs/2610.35756) 先用 TGR 选择 target-supported views 和闭合平滑轨迹，再以 Wan2.1 为基础的 FAVE 传播单视图 anchor edit，最后 RS-GS 只更新目标 Gaussian。项目页展示增加、删除、外观修改和参考图编辑；[GitHub](https://github.com/2hiTee/VidEdit3D) 目前只有 README、素材、license，明确写着“Code will be released soon”。依赖还涉及 diffusers 0.34.0、Wan 权重、Nerfstudio/GaussCtrl，今天只能评为研究原型。

**编辑摘要：** 视频扩散把多视角一致性从逐视图编辑改写为轨迹视频传播，方法方向值得跟踪；但仓库尚无实现，今天不能评估显存、时长、编辑漂移或对不同 3DGS trainer 的兼容性。

## 10. 研究论文

### SG-Splat：pose-free 的几何稳定性

<!-- arxiv:2610.35361 -->
[SG-Splat（arXiv:2610.35361）](https://arxiv.org/abs/2610.35361) 将 geometry 与 Gaussian appearance/attributes 解耦；FGPR 使用 flow/correlation 与 differentiable bundle adjustment 改 pose，RGC 用 depth residual correction 稳定几何，并以 GT/predicted pose 双路径训练。论文在 DL3DV、RealEstate10K 评测；arXiv/作者公开页没有代码、权重或可运行 demo，评级 P2、论文无代码。

**编辑摘要：** 论文瞄准 pose-free 3DGS 最容易累积的几何漂移，解耦思路清晰；没有代码时还无法判断 flow/BA 的额外成本、失败恢复和真实手机视频上的鲁棒性。

### CVTSplat：用自适应 Voronoi cells 替代 Gaussians

[CVTSplat（arXiv:2610.35347）](https://arxiv.org/abs/2610.35347) 在 SDF 零等值面附近建立非均匀 adaptive centroidal Voronoi cells，并提供 GPU nearest-neighbor、Voronoi construction 与 rasterizer。作者摘要称 Voronoi construction 相对通用方法快 5–10×，单 GPU 在 DTU/BlendedMVS 约 2.5 分钟训练；但摘要没有完整 GPU、分辨率、cell 数、质量/速度对照口径，且无代码，因此不能把数字外推为 3DGS 的直接替代。

**编辑摘要：** 这是四篇中最接近“表示范式变化”的条目，因为 primitive 不再是 Gaussian；但性能数字缺少完整口径且实现未公开，现阶段只能作为几何表示方向观察，不能进入部署候选。

CGR-GS 与 VidEdit3D 见第 8 节。本期 4 个 arXiv ID 按标题/ID 去重，均来自 2026-10-27 批次；CGR-GS 是“代码+权重可跑”，VidEdit3D 是“项目页+代码占位”，SG-Splat/CVTSplat 是“论文无代码”。

## 13. 今天最值得实际测试/部署的项目

### 1) LichtFeld Studio batch-train + scale

- **为什么**：批量训练、失败/超时报告和米制尺度是从研究脚本进入生产流水线的关键缺口；本轮同时给了 GUI、CLI、Python/MCP 路径。
- **门槛**：GPL-3.0、master、C++23/CUDA/Vulkan build；锁定 `6a7c00d1 + bf8f64f6 + 186ac29 + 8d047d9d + 79440e8f`，不要只跟浮动 master。
- **测试**：先 `--dry-run` 验 manifest；再跑 3 个小场景覆盖成功、坏数据、超时、Ctrl+C、输出冲突；用已知 1 m 物体比较 manual/AprilTag scale；对同一 3DGUT 数据记录峰值 VRAM、steps/s 与画质。
- **预期收益**：多场景作业可审计、失败更可控，碰撞/XR/地图尺度更一致；风险是 master 变动快，尺度精度仍受标定/检测质量约束。

### 2) splatkit 16-bit sort + packed vertex

- **为什么**：这是 Metal/Vulkan 同步的默认路径更新，可能直接降低移动端排序 pass 与 tile traffic。
- **门槛**：MIT；iOS/Android/React Native 原生构建，准备支持 60/90/120 Hz 的至少两类设备。
- **测试**：同一 SPZ/PLY 以 16/32-bit 渲染 close thin layers、透明树叶、超远景；记录 GPU time、FPS、功耗、温升、图像 PSNR/SSIM 和闪烁；验证 FPS cap 与系统 refresh rate。
- **预期收益**：排序和 raster 带宽下降；风险是远深度 key collision 和颜色/opacity 量化在极端场景暴露。

### 3) CGR-GS v1.0 checkpoint

- **为什么**：本期唯一同时具备论文、真实源码、环境脚本和公开权重的新 human GS 项目。
- **门槛**：Linux/Conda、Python 3.10、PyTorch 2.5/CUDA 12.4、xformers；1.25 GB checkpoint；THuman2.0 需申请；整体仅建议研究用途。
- **测试**：先复现 4→16 views 的 100-subject evaluation，再记录单人预处理、推理延迟、峰值显存与非 THuman 服装/手指/脸部退化；不要只复述 README 指标。
- **预期收益**：可快速判断 complexity-aware density 是否值得移植到现有人体重建；风险是 mesh/数据准备重、许可混合且暂无独立复现。

OOOSplat 0.7.1 建议作为 staging 第四项：等正式 release 前只比较策略与失败语义，不替换现有 0.7.0 安装包。
