## 2. SuperSplat / PlayCanvas 工具链

### SuperSplat v3.5.1：40M live splats 以上强制 LOD

- [PR #1064](https://github.com/playcanvas/supersplat/pull/1064) 统计未删除的 live splats；超过 40,000,000 时，发布场景的 **Generate LODs** 会被强制开启并禁用开关，纯动画更新不显示该限制。原因是单文件 SOG 走 SplatTransform/WASM WebP encoder，维护者测得约 45M–50M 会耗尽内存。
- 架构影响：这不是渲染器的新 LOD 算法，而是 Editor 发布边界的安全阀。大型场景会被引导到分层 SOG/streaming 路径，避免导出阶段 OOM；已删除 splats 不计数，符合实际 payload。若流水线依赖“超大单文件 SOG”，v3.5.1 会改变 UI 行为，应改为 LOD 发布或在命令行拆分。
- **升级判断：值得马上升级。** 它把可预测的 40M 阈值显式化，比在 WebP 编码末端失败更安全。证据 A（release）/B（PR）。

## 3. 可实际运行的开源项目

### Gaussian-Splat-Lite v1.2.0

- **用途/格式：** Three.js 的 WebGPU/WebGL2 3DGS renderer，读取 PLY、SPZ、SOG、RAD，含 GPU sort、stochastic rendering、streaming LOD 与 GIS/ECEF 高精度路径。
- **代码变化：** native WebGPU radix 由 4-bit 改 8-bit；fast/normal/stochastic 分别 3/4/2 passes，稳定处理相同 depth key；XR 两眼共用 generation/culling/sort，WebGPU 一次 compute 投影双眼；新增无 velocity texture 的 camera/depth reprojection TAA；RAD/SOG 对 408/425/429/5xx 和 worker loss 自动重试，等待间隔逐步增加、上限 30 秒，并非重试总截止时间；SPZ v4 Zstd window 上限 128 MiB；>4M splats 减少闲置纹理。
- **门槛：** `three >=0.186.0`，Node `^20.19 || >=22.12`；浏览器需 WebGPU 或 WebGL2。仅在重建 WASM decoder 时需要 Rust 1.87。
- **兼容风险：** 删除 `autoStochastic`、旧 stochastic passes、`render()`/offscreen capture env-map 路径与非 XR `ArrayCamera`；streaming scheduler 通过 `setCamera(camera)` 注册相机，再调用无参数的 `update()`；未注册相机时 `update()` 会抛错。建议先跑格式矩阵和 XR/移动浏览器回归，再升级生产包。

### LocusGS

- [代码仓库](https://github.com/leo-frank/LocusGS) 在 10 月 2 日公开完整模型/训练/评估实现，机构为国防科技大学，Apache-2.0。训练脚本覆盖 DL3DV 与 RealEstate10K，默认 bf16/Accelerate，示例含多 GPU 训练和单 GPU 评估。

## 5. Viewer / Editor / Web / Mobile / XR

- Web/XR 的主要可用变化来自 **SuperSplat Viewer v1.37.0** 与 **Gaussian-Splat-Lite v1.2.0**：前者更偏发布/共享 Viewer 与独立头显交互，后者更适合 Three.js 嵌入和自定义 renderer。若要评估 WebGS 工程路线，建议同一 SOG 场景对比首屏、steady-state FPS、GPU memory、LOD 抖动、picking 和双眼一致性。

## 6. Compression / Format / LOD / Streaming

- **SOG：** SuperSplat 对 >40M live splats 强制 LOD，是格式/发布路径上的运维边界；SplatTransform 3.9.0 则把 streamed SOG 加速推到 npm。两者结合意味着 PlayCanvas 正把“超大单文件”转向分层 streaming，而不是继续扩大单文件 encoder 的容忍度。
- **SPZ：** Gaussian-Splat-Lite 将 SPZ v4 Zstd window 提到 128 MiB，解决大字典/窗口文件的浏览器解码兼容；这不代表格式本身新增 LOD 或随机访问。
- **PLY：** SplatTransform 3.9.0 修正 big-endian binary PLY；ASCII 现在失败得更早、更明确。导入网关应仍把 PLY encoding 纳入验收，而不是只看扩展名。
- **标准状态：** 未核实到 glTF Gaussian extension、OpenUSD、3D Tiles、MPEG GSC、Khronos 或 W3C/WebGPU 在窗口内新的正式提案里程碑。今天没有可报告的跨生态标准落地。

### LichtFeld Studio 正确性修复组

- [#2686](https://github.com/MrNeRF/LichtFeld-Studio/pull/2686) 新增 `--eval-space distorted|undistorted`；默认在原始畸变参考空间比较：2× 渲染后按原镜头模型逆 warp，使用 validity mask。训练预处理改为一次 full-resolution area resample + Lanczos-3/8×8 quadrature，并让 mask/depth/normal 同步对齐。维护者报告 8K 图像一次性约 0.24 s、残差中位数 <0.3 px，且无 `--undistort` 路径 bit-identical。

### Spirula mapping 与 AMD 风险

- [PR #131](https://github.com/harry7557558/spirula-studio/pull/131) 在昨天 GPS mapping 基础上加入 seam weld：对有 ≥100 verified matches、共享 3D 点少、邻居交集低的相邻 capture frame 检测重复点并融合，再做求解；同时用 60–150 m GPS block 检查向 BA 提示 4%–8% 的短尺度段。作者单条 canopy 航线上多处 seam 从约 2.14–4.51 m 降到 0.52–1.80 m，但阈值只在少数数据调过，默认应视为实验性。

### What Builds the Scene? Luminance Dominates Geometry Formation in 3D Gaussian Splatting

<!-- arxiv:2610.00749 -->

- [arXiv 2610.00749](https://arxiv.org/abs/2610.00749)，提交 2026-09-30；**论文无代码，P2，A**。
- **编辑摘要：** 11 个场景×4 次运行中，luminance-only 建几何、再拟合外观，平均只比 RGB 低 0.085 dB；chroma-only 几何低 3.9–5.5 dB。若后续被复现，可能影响 densification/feature allocation 的设计，但目前不能直接改生产 trainer。

### A Compact Explicit 4D Representation for Dynamic Scenes（Sparc4D）

<!-- arxiv:2610.01229 -->

- [arXiv 2610.01229](https://arxiv.org/abs/2610.01229)，提交 2026-10-01；**论文无代码，P2，A**。
- **编辑摘要：** 单目视频+已知相机的 feed-forward autoencoder，以静态共享特征和稀疏 temporal slots 表示 4D state，decoder 输出 2D Gaussian surfels。32-frame MultiCamVideo 报告 0.95M values、PSNR 21.70（MoVieS 20.40）；尚无代码/权重，不能验证质量—压缩权衡。

### Affine-Aligned Atlas for Canonical Gaussian Construction in Video Representation

<!-- arxiv:2610.01114 -->

- [arXiv 2610.01114](https://arxiv.org/abs/2610.01114)，提交 2026-10-01；**论文无代码，P2，A**。
- **编辑摘要：** 在 canonical Gaussian 构建前用逐帧 affine transform 吸收全局相机运动，参数增量很小，面向大幅 camera motion；需要等代码确认其对真实 rolling shutter、非刚体和长序列漂移的鲁棒性。

### MEGA: Object-Level Watertight Mesh Extraction from 3D Gaussians

<!-- arxiv:2610.01707 -->

- [arXiv 2610.01707](https://arxiv.org/abs/2610.01707)，提交 2026-10-01；**论文无代码，P2，A**。
- **编辑摘要：** 先在 3DGS 中分割对象，再通过空间视觉蒸馏渲染对象视图，训练 mask-guided neural surface，目标是 object-level watertight mesh。对资产导出有价值，但目前没有可跑工具。

### 3DROID: A Dataset for 3D Reconstruction in Robotics

## 13. 今天最值得实际测试 / 部署

### 1) Gaussian-Splat-Lite v1.2.0：WebGPU/XR/streaming 回归

- **为什么：** 今天唯一同时覆盖 WebGPU sort、XR 双眼共享、stochastic TAA、SOG/SPZ/RAD streaming 和大场景内存的可安装开源更新。
- **门槛：** Node 20.19+/22.12+、Three.js 0.186+、支持 WebGPU/WebGL2 的浏览器；准备同一场景的 PLY/SPZ/SOG 与至少一台 XR 设备。
- **预期收益：** 更低 GPU sort 时间、更少双眼重复工作、更稳的流式重试和更大 SPZ 兼容；**风险是 API 删除多**，先建立 v1.1.x 对照，不要直接替换生产包。

### 2) PlayCanvas 三件套发布版本：锁版验证生产链

- **为什么：** 昨天只能追 `main` 的改动今天都进入 Editor v3.5.1、Viewer v1.37.0、SplatTransform 3.9.0，适合做可复现的端到端基线。
- **门槛：** 一个 5M–10M SH3 PLY 和一个 >40M live splat 工程；Quest/Pico 如有则再跑 XR。记录转换时间、峰值 RAM/VRAM、首屏、steady-state FPS、picking 与 LOD 切换。
- **预期收益：** SOG 构建缩短、big-endian 输入不再静默损坏、移动 XR budget/交互可用、Engine 2.23 debug overlay 恢复；>40M 发布会被强制走 LOD，这是预期行为。

### 3) LichtFeld #2686/#2688：重算一组带畸变评估

- **为什么：** 这两项可能改变历史指标结论，价值高于再跑一个普通训练 benchmark。
- **门槛：** 从 `master` 构建 LichtFeld，选一组 `FULL_OPENCV` 或明显畸变数据、带前景 mask 的场景；保留旧版 PSNR/LPIPS 与图像对齐可视化。
- **预期收益：** 去掉 15–33 px 级参考空间错位和 mask 面积偏差，得到能与真实成像空间对应的指标。若团队依赖排行榜或回归阈值，应在升级后重新建立基线。
