## 3. 可实际运行的开源项目

### inference.rs：原生 Rust/CUDA 训练器进入主分支

[commit 3840a10c](https://github.com/christopherthompson81/inference.rs/commit/3840a10c1fc4ccb6a5f3233baba10e649ae23cf5) 将 HY-World 2.0 的单卡 3DGS 阶段移植到 `inference-recon`，CLI 已生成正式文档：

```text
inference splat --data world/gs_data --out world/splats --lpips lpips_vgg.safetensors
```

输入必须是 HY-World `gs_data`：`images/`、`depths/`、`normals/`、`cameras.json`、`points.ply` 与 `sky_points.ply`；输出标准属性的 `splats.ply` 和含计数、验证 PSNR、坐标变换的 `splats.json`。依赖 Rust 1.94、CUDA build 和单独准备的 LPIPS-VGG safetensors。它不是任意照片直接重建工具，也没有 COLMAP 摄像机估计。

实现包括 kNN scale 初始化、Adam、L1+SSIM+LPIPS、disparity、render-depth normal、scale-ratio、gsplat 默认 densification 和 MaskGaussian gate/prune。作者在 283 views、8000 steps、RTX 3090 的单一户外场景上报告 20 分 29 秒、2.45M Gaussians、验证 PSNR 24.57 dB；参考训练器为 24.19 dB、16.5 分钟。这个数字只证明画质对齐，不代表 Rust 端更快，且尚无独立复现。评级 P1 早期可测。

### BT-3DGS：CT 投影的二叉树 Gaussian 重建

[MedAPT-group/BT-3DGS](https://github.com/MedAPT-group/BT-3DGS) 在 [59e45d7d](https://github.com/MedAPT-group/BT-3DGS/commit/59e45d7d52ba64548f244b11704bc3a3f2eb216f) 一次性公开模型、trainer、Hydra config、验证、测试和 `r2splat` C++/CUDA 后端。它从中心单 Gaussian 出发，以 binary tree 保存父节点历史并 densify，另有 conventional、distillation 和 LoD student 路线。

安装建议 Python 3.10、PyTorch 2.5.1 + CUDA 12.1、可用 nvcc 与 C++ compiler；CPU build 仅用于测试，不支持重建。数据必须预处理为 cone-beam CT 的 `meta_data.json`、投影数组和参考 volume；仓库没有原始 DICOM/扫描器标定入口，也不附数据、权重或 benchmark。导出以参数 pickle 为主，ASCII PLY 只用于点预览。评级 P1 研究原型，医学/工业 CT 团队值得测试，通用 3DGS 用户不应把它当普通照片 trainer。

## 5. Viewer / Editor / Web / Mobile / XR

### LichtFeld SteadySplats viewport

[PR #3728](https://github.com/MrNeRF/LichtFeld-Studio/pull/3728) 是今天 Viewer/Editor 方向最重要的更新。它增加 stochastic 与 SteadySplats refinement 模式：基于 STBN 采样、复用 stationary tile groups、保存 color/occluder/reuse/history，并对透视背景样本做重投影；默认最多 16 帧 refinement，GUI、settings、Python property metadata 和 IPC 使用同一常量。

工程细节决定它是否值得马上测：

- 关闭 stochastic 后，basic mode 会在 render timeline 上释放 SteadySplats 专用缓冲；920×948 的维护者案例从残留 0.64 GiB 回到 0.49 GiB。
- 额外成本约为 history `160 B/像素`、1 MiB STBN，以及 `4 B/Gaussian` 的独立 sort-index；这不是“免费抗噪”。
- Catmull-Rom 历史采样负值被 clamp 到 0，避免黑白阶跃旁的负颜色继续反馈。
- mesh、camera frustum 或 align surface picking 要求每帧精确深度时会自动退回 alpha blending；所以混合 mesh/splat Editor 场景不能假设一直处于 stochastic 模式。
- STBN 在 build 时由 host tool 可重复生成，不再提交 1 MiB binary blob；生成器还验证 byte histogram。

建议立刻在静止相机、慢速轨道、突然跳转、透明前景、高频细节和 mesh overlay 六类场景做画质/显存/收敛帧数矩阵；不要只看静止截图。

相机路径方面，[#3784 / 6bf29fc1](https://github.com/MrNeRF/LichtFeld-Studio/commit/6bf29fc14359d21cb403f91e90ea6339340ce568) 平滑 sequencer camera interpolation，[#3817 / cdbf0b3f](https://github.com/MrNeRF/LichtFeld-Studio/commit/cdbf0b3fbf50c4994d5e247e6ed87cec18d47e51) 随后修正平滑旋转插值；做 camera animation 的用户应把两者作为一组验证。

移动端、WebXR、Unity、Unreal、Godot、Three.js、Babylon.js、Cesium、MapLibre/Mapbox 的一手来源中，本窗口未发现新的 GS release 或 API。

### LichtFeld：三项训练正确性修复

1. **尺度初始化**：[85670566](https://github.com/MrNeRF/LichtFeld-Studio/commit/856705660dc7724adbf9d36627db23149e8b03af) 发现 `compute_mean_neighbor_distances` 已返回距离，旧代码却再次开平方。结果是场景坐标放大 10 倍，Gaussian 初始尺寸只放大 √10。修复后除 MRNF 外的策略恢复单位尺度不变性，并用真实点集的 1×/10× 测试锁定。
2. **opacity 梯度**：[23e04f4a](https://github.com/MrNeRF/LichtFeld-Studio/commit/23e04f4a09ff137c19fecc23d6fd9428bdf38765) 在共享 sigmoid/CUDA 正则、FastGS backward、gsplat backward 与 POPSpa 中保留饱和 logit 的有效梯度。对已经出现透明度卡死、POPSpa penalty 无反应的 run，这比调学习率更值得先验证。
3. **大图网络内核**：[4928725f](https://github.com/MrNeRF/LichtFeld-Studio/commit/4928725f3520ab314370501ff45863bc54492f0f) 把空间维从 CUDA `grid.y` 换到容量更大的 `grid.x`，覆盖 GEMM、1×1/3×3 conv、FP16 WMMA 与 LPIPS RGB conv。旧布局每 block 64 pixels、`grid.y` 上限 65,535，约在 4.19M pixels 后无法覆盖；新增 2400×2400 测试检查首行、中行和末行。

另有两项工作流改进：[#3812 / e8813de7](https://github.com/MrNeRF/LichtFeld-Studio/commit/e8813de784a932651dc1469e604050e6c548caee) 允许 New Project 对话框选择任意位置的 images folder，并为缺失图片给出禁用原因；[#3808 / 5797daf6](https://github.com/MrNeRF/LichtFeld-Studio/commit/5797daf6461a895074cca23108ec923d82bd1ed1) 给 crop toolbar 增加 Invert。

- **门槛**：master/未发 tag，GPL-3.0；现有 LichtFeld Vulkan/CUDA 构建环境。锁定 [e5e2ecaa](https://github.com/MrNeRF/LichtFeld-Studio/commit/e5e2ecaad15b09f496b709633d1e6697524f3647)。
- **测试**：alpha、stochastic、SteadySplats 三模式；静止/移动/跳转相机；0/8/16 refinement frames；有无 mesh/frustum；记录显存、GPU frame time、SSIM/LPIPS 和 ghosting。
- **预期收益**：低方差 Gaussian 的随机渲染更稳定，且能在关闭模式后回收额外内存；风险是运动和 overlay 场景会触发退化或 alpha fallback。

### 2) inference.rs `inference splat`

- **为什么**：Rust 主工程里第一次出现从 gs_data 到标准 PLY 的完整原生训练闭环，包含 backward、densification 和 pruning，而非只读 viewer。
- **门槛**：Rust 1.94、CUDA build、HY-World 2.0 `gs_data`、LPIPS-VGG safetensors；MIT。对普通 COLMAP 数据需要自行转换。
- **测试**：先用小规模 gs_data 跑 500–1000 steps 验证导出，再对同一数据跑 8000 steps 与参考 trainer 比画质、wall time、VRAM、Gaussian 数和坐标变换。
- **预期收益**：减少 Python/CUDA 扩展之间的跨语言拼接，方便嵌入 Rust 推理/世界生成栈；风险是单场景作者 benchmark、master 未发版、CUDA-only trainer。

### 3) gsflow Windows 安装与 34 帧 smoke pipeline

- **为什么**：今天修的是会把用户产物写到开发者目录的真实安装缺陷，且已有真机 smoke 测试路径，可低成本复查。
- **门槛**：Windows、Python 3.11+、约 20GB 空间；训练需 NVIDIA/CUDA，Blackwell 用 cu128；MIT。
- **测试**：在非默认盘符安装 core+gpu，执行 `doctor --json`，用短视频只跑 frames，再跑 mask/COLMAP/短训练；确认 `workspace_dir`、缓存、断点续跑和导出路径均落在安装目录。
- **预期收益**：把 Windows 3DGS 从手工环境拼装变成可诊断流水线；风险是依赖体积大、网络复用逻辑复杂、第三方尚未独立复现。

CT 团队可把 [BT-3DGS](https://github.com/MedAPT-group/BT-3DGS) 作为第四候选，但没有预处理数据、权重或论文 benchmark 时，不建议通用团队优先投入。
