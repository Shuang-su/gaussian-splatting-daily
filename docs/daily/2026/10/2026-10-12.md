## 2. SuperSplat / PlayCanvas 工具链

SuperSplat Editor、SuperSplat Viewer 和 SplatTransform 本窗口没有新 commit、merged PR 或 release；Editor selection/histogram、camera path、viewer export、SOG/SPZ/PLY 编码、streaming 和 stochastic rendering 均无新增。Discord 未直接读取。

PlayCanvas Engine 的新增是 [#9727](https://github.com/playcanvas/engine/pull/9727)。昨天的 #9726 只覆盖较简单的 VAO 生命周期；多 vertex-buffer draw 仍使用另一套 cache，导致 instancing、morph target 和 transform feedback 的 VAO 在 buffer 销毁后继续持有 GPU 引用，连同最后绑定的 index buffer 一起滞留。

新实现把多 buffer VAO 绑定到第一个 vertex buffer，并按其他 buffer object 建 key；销毁任一参与 buffer 都会删除引用它的 VAO。作者测试中，每轮创建/销毁 48 MB instanced vertex buffer 原先会增长约 48 MB，现在保持平坦；Chrome 两 buffer draw 的 setBuffers 微基准约 89ns→52ns。它对混合 GS+mesh、人物 instancing、动画遮挡代理和长时运行 editor/viewer 更重要，对纯静态 splat 场景影响较小。

Engine 出现 [v2.24.0-beta.8 tag commit](https://github.com/playcanvas/engine/commit/ad9ac93d9718c63cf1a861a5925b6145c11ca22b)，但官方 Releases 当前最新稳定版仍是 [v2.23.2](https://github.com/playcanvas/engine/releases/tag/v2.23.2)。#9727 尚未进入新的稳定 release，建议只在能固定 commit 的测试环境验证。

## 3. 可实际运行的开源项目

### DynaSem-GS：动态环境语义 Gaussian SLAM

仓库于 10 月 11 日创建，MIT，首次实现 commit [6e4fa4e4](https://github.com/Sun173558/DynaSem-GS/commit/6e4fa4e418f064119894deedecf2ddd6674cf3b2)。它把 frontend tracking/segmentation、backend mapping/BA 和可选 GUI 拆为三个进程；每个 Gaussian 同时保存 RGB SH 与 semantic SH。

默认使用 YOLO11m-seg 做实例分割，也可安装 MMSegmentation/Mask2Former。动态类像素在特征与 tracking 前被遮罩；RGB-D 模式还会比较观测深度与渲染深度。支持 TUM RGB-D、Bonn dynamic 和 RealSense，最终输出 point_cloud.ply 与 semantic_cloud.ply。

门槛是 NVIDIA CUDA 11.8、PyTorch 2.0.0，以及本地编译 diff-gaussian-rasterization/simple-knn；YOLO 或 Mask2Former 权重首次运行下载。仓库没有论文、预训练模型和速度/显存表，成熟度为“可运行的早期研究实现”，不应把 README 的 real-time 表述当独立 benchmark。

### Stillroom：本地房间 GS 与空间记忆

[Stillroom](https://github.com/aryasentry/stillroom) 是 MIT 的本地应用，照片/视频经 PyCOLMAP 4.2.1 建相机，再用 Brush 0.3.0 训练 Gaussian；前端固定 Three.js 0.186.1 与 Spark 2.3.1。除重建外，还能在场景中放置文字、图片、音频和视频，保存视角，并导出 portable ZIP。

作者在 Apple M3 16GB 上用 54 张合成房间图完成 3,000-step preview：588.69 秒、31,184 splats、约 7.36 MB PLY；54 张均注册，稀疏模型 reprojection error 0.300px。另有 232 backend、37 frontend unit、17 browser tests。证据严谨地声明这是有利的合成场景，不代表真实房间质量；Windows/Linux、Safari/Firefox、移动设备尚未实机验证。

### leafweave / plant3d：多光谱植物 GS

[leafweave](https://github.com/HiroGitea/leafweave) 内的包名为 plant3d。它先用 gsplat 训练 RGB 几何，再冻结位置/尺度/opacity 拟合 green/red/red-edge/NIR，随后用 SAM 将跨视图叶片 mask 投影到 Gaussians，输出 NDVI PLY、spectral checkpoint 与 per-leaf CSV。

依赖配置非常新：Python 3.12、PyTorch 2.14.1+CUDA 13、C++20、vendored gsplat 1.5.3，并默认 TORCH_CUDA_ARCH_LIST=12.0；非对应 GPU 必须先改配置。没有包含数据、权重或 notebook，但提供 Zenodo 数据下载与可运行命令。许可证限制非商业使用，不能直接并入商业平台。

作者结果也暴露了边界：houseplant 的 32px-block NDVI error 0.036，优于常数基线 0.041；但 whole-plant 0.023 劣于常数 0.018，三个植物整体尺度均未稳定胜过简单基线。实际价值主要是跨视角叶片关联和不同相机视点下的光谱融合，而不是已解决绝对植物指数测量。

## 5. Viewer / Editor / Web / Mobile / XR

Stillroom 是今天最完整的新 viewer/editor 信号：本地 WebGL viewer 支持 GLB、PLY、SPZ，能够在 splat 上近似拾取、拖动记忆 anchor、保存/恢复相机视角并离线归档。它适合“空间记录/导览”原型，但不是 SuperSplat 的 splat 几何编辑器；选择、删除、裁剪和压缩仍需外部工具。

PlayCanvas #9727 应在包含 instanced mesh、morph target、动态遮挡 mesh 或测量辅助物的 WebGS 页面测试。它不是 gsplat sorting/projection 改动，但能避免长期运行时 mesh 资源不断挤压 splat 的显存预算。

Spirula [#183](https://github.com/harry7557558/spirula-studio/pull/183) 让 GUI 与 CLI 的 eval 行为一致：仅在有 held-out views 时进入 evaluation phase，写 metrics.json 和可选 GT/render PNG；PNG 写入失败会让训练失败，而不是假装完成。

本窗口没有新的移动端或 WebXR 专项实现达到 P1。

## 7. Training / Reconstruction / SLAM / Robotics / Mapping

### LichtFeld：保存和终态结果的高风险修复

[#3283](https://github.com/MrNeRF/LichtFeld-Studio/pull/3283) 修复 CUDA 异步 splat snapshot 与随后 source-stream 写入之间缺少顺序约束的问题。现在 snapshot 开始时让所有源 stream 等待 snapshot-ready event，覆盖十个 tensor，包括 quantized SH；测试在修复前 8 次重复中 48/48 payload 被污染，修复后 byte-identical。没有 host sync 或逐帧成本，也不改 .licht 格式。

[#3278](https://github.com/MrNeRF/LichtFeld-Studio/pull/3278) 修复 IGS+ 在最后一轮恰逢 reset_every 时把全部 opacity cap 到 0.1、却没有后续 optimizer step 恢复的问题。默认设置下 3,000/6,000/9,000/12,000 iteration 都可能触发近透明终态。

[#3275](https://github.com/MrNeRF/LichtFeld-Studio/pull/3275) 使用包含 sparsification tail 的总 iteration 判断 checkpoint 是否完成；此前 3,000+4,000 的 run 在 4,600 保存会被误判完成并禁止 Resume。

[#3280](https://github.com/MrNeRF/LichtFeld-Studio/pull/3280) 让 controller training 的 freeze 真正覆盖 strategy hooks、refinement、topology publish、Morton reorder 和 SH-degree 更新，避免“梯度冻结但 MRNF/MCMC 仍改变 Gaussian”。

### Spirula：ROI、GPS、视频和 macOS GPU

[ROI commit e83bb8c7](https://github.com/harry7557558/spirula-studio/commit/e83bb8c7d90a467c47bbbd696a5e283214ebe544) 不再只用 Gaussian 中心判断 ROI，而会按 scale/rotation 对 ellipsoid 采样；中心在内时永远保留，默认额外采样用于边界 densification masking。这比点中心过滤更符合大型/扁平 splat 穿过 ROI 边界的情况。

[GPS commit 01fe9406](https://github.com/harry7557558/spirula-studio/commit/01fe94061169ce4db3518db83f99ff6e0ec2a519) 将最终 metric frame 与 mapping BA 实际使用的 GPS factor 来源统一，增加 distinct-position 检查，并由 GPS 自身散布推导默认误差半径，减少长航线使用固定步行阈值造成的错误拒绝。

[#168](https://github.com/harry7557558/spirula-studio/pull/168) 在 decode 后、scale/turn/lens cut/360 unwrap 前用 tetrahedral interpolation 烘焙 .cube；内建 extractor、preview 与 ffmpeg fallback 对齐。不要与已有的 D-Log M→linear 训练路径叠加，否则会二次变换色彩。

[#182](https://github.com/harry7557558/spirula-studio/pull/182) 允许 Vulkan 3DGUT occupancy moments 使用 equirectangular camera，并验证 2:1 全景及 longitude seam；直接补上 360° 数据 Vulkan meshing 的缺口。

[5959b851](https://github.com/harry7557558/spirula-studio/commit/5959b8514d43d6edbe90dda1f147fbbd58e503ce) 为 NN pipeline 按 kernel/pipeline 学习 submit rate，并在 macOS 26 设置 AGX_RELAX_CDM_CTXSTORE_TIMEOUT=1，应对长 GPU command buffer 被“Impacting Interactivity”终止。属于稳定性修复，不代表统一加速。

## 13. 今天最值得实际测试 / 部署

### 1) Stillroom 本地视频→房间→空间记忆链

**门槛：**MIT；Python 3.11–3.13、Node 22.12+/24、WebGL 浏览器；setup 会下载 PyCOLMAP 4.2.1 与 Brush 0.3.0。  
**测试：**用 30–90 秒稳定室内视频，比较 preview 3,000 steps 与 standard 7,000 steps；记录注册帧比例、总耗时、输出 splat 数、峰值内存、SPZ/PLY viewer 稳定性及 portable ZIP 回读。  
**预期收益：**验证“全本地捕获—重建—空间标注—归档”能否成为 WebGS 产品原型；最大风险是真实房间证据仍不足，Apple M3 之外未验证。

### 2) DynaSem-GS 在 Bonn dynamic 上复现

**门槛：**MIT；NVIDIA CUDA 11.8、PyTorch 2.0、编译两个 CUDA extension，首次下载 YOLO11m-seg；Mask2Former 需额外安装 OpenMMLab。  
**测试：**对 walking_static 同时运行 remove_dynamic 开/关，记录 ATE、跟踪丢失、静态地图污染、semantic PLY 完整性、FPS 与 VRAM。  
**预期收益：**若动态遮罩和深度一致性有效，可直接用于室内机器人/空间扫描；当前没有官方 benchmark，必须自行建立基线。

### 3) LichtFeld 保存/终态回归 + Spirula LUT

**门槛：**分别固定到 LichtFeld 含 c3835a95/f0226bc1 的 master，以及 Spirula 含 abdc29f8 的 master。  
**测试：**LichtFeld 在训练中触发 autosave 后立即继续修改，对保存前后十个 tensor 做 hash；用 3,000-step IGS+ 检查最终 opacity。Spirula 用同一段 DJI/Insta360 log 视频比较内建与 ffmpeg .cube 路径，检查抽帧 hash、色阶、SfM 注册与最终色彩。
