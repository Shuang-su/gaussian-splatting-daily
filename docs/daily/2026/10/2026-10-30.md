## 2. SuperSplat / PlayCanvas 工具链

### Engine：自定义 splat stream 与 MRT 生命周期对齐

[commit 3112d849](https://github.com/playcanvas/engine/commit/3112d8493e1fbec52235e2643d8b007000a64f72) 修的是 GSplatWorkBuffer.syncWithFormat() 的版本判断。GSplatStreams.getTexture() 本身也会同步格式；若应用在添加 stream 后先取得 texture，旧代码随后看到 stream 已是最新便跳过 render-target 重建，MRT 仍没有新 attachment，copy pass 也永远不会写这条 stream。

新实现保存独立的 render-target version，只要它落后于 stream format version 就重建 work-buffer render targets；测试覆盖额外 R8 stream 和“先调用 getTexture”顺序。它不改变 PLY/SPZ/SOG 解析，也不是 SOG v3 实现，但会直接影响运行时附加 semantic ID、selection mask、应用 blind data 或其他 per-splat attributes 的可靠性。**建议锁定此 SHA 回归 add-stream→getTexture→copy→readback，稳定版用户等待正式 release。**

固定检查 [SuperSplat](https://github.com/playcanvas/supersplat)、[SuperSplat Viewer](https://github.com/playcanvas/supersplat-viewer) 与 [SplatTransform](https://github.com/playcanvas/splat-transform)：窗口内仅有 ESLint/发布工作流整理，没有新的 Editor、selection、histogram、camera path、viewer export、WebXR、LOD、streaming 或格式功能。正式版本仍为 SuperSplat 3.7.0、Viewer 1.41.0、SplatTransform 3.10.3；无需为这些 CI 变化立即升级。

## 3. 可实际运行的开源项目

### OOOSplat：本地 agent 自动化进入可控闭环

[MCP commit](https://github.com/ooolabdev/ooosplat/commit/28dcaf8e5f4ee48229ac741b4a5f5020ba718c84) 的关键不只是能调用任务，而是把审批、恢复与导出边界写进协议：输入预检会返回稳定 key/options，缺少显式回答则 CONFIRMATION_REQUIRED 且不创建任务；resume_task(task_id, expected_run_id) 拒绝 stale run 或缺失 checkpoint；GUI 与 MCP 互斥锁防止同一模型被并发修改。

缺口同样明确：尚未完成完整 native desktop 的 Agent→saved edit→无预览导出/SPZ consent 手工 E2E，也未覆盖真实全流程 GPU generation、OOM/磁盘耗尽、WebGPU 视觉对比与 macOS/Linux。**可在 staging 接入本地 agent，不应开放远程端口或直接替代人工审批。**

## 6. Compression / Format / LOD / Streaming

[Gaussian-Splat-Lite 1.5.4](https://github.com/WilliamLiu-1997/Gaussian-Splat-Lite/releases/tag/v1.5.4) 是今天唯一形成正式版本号的格式/LOD 工具更新。1.5.2 把慢盘上的 pending writes 纳入 --memory-budget，并减少超预算模型的临时文件读取；1.5.3 将 SH2 codebook 上限提高到 174,763、SH3 提高到 327,680，代价是 conversion 更慢、输出可能更大；1.5.4 将 training probes 2→4、final probes 24→16，重新平衡聚类耗时与 view-dependent color。

主线后续 [commit 293d84cf](https://github.com/WilliamLiu-1997/Gaussian-Splat-Lite/commit/293d84cf85acf8b1cea5764e132d90d2e7d254da) 又把 RAD SH codebook copy/cache 移进 worker，避免 page decoder 切输入时的大块主线程复制，并继续计入 CPU memory budget；它**不在 v1.5.4 tag 中**。需要追求 UI responsiveness 时可测主线，否则生产锁定 1.5.4。

窗口内未核实到 Khronos KHR_gaussian_splatting、OpenUSD、3D Tiles、MPEG GSC 或 W3C WebGPU 的新批准版本。SOG v3 仍是昨日已归档的提案，不得把 OOOSplat 的 SOG export 或 GSL 的 SH codebook 误报为 v3 落地。

## 7. Training / Reconstruction / SLAM / Robotics / Mapping

### Spirula：加速幅度必须按 kernel 和数据口径拆开看

[projection backward commit](https://github.com/harry7557558/spirula-studio/commit/40a12c522307ebf7b996dce4d60bfaa4e852a5b0) 将动态 staging 改为固定索引和 coefficient reader；RTX 5070、5M splats、SH3 的固定 workload 中，FPBO 从 39.307 降到 14.442 ms/call，共享内存 49,152→1,024 B/workgroup。对应单次 Mip-NeRF 360 bicycle 训练从 6m55.579s 降到 4m15.364s。非 FPBO 路径只从 5m42.841s 到 5m23.475s（-5.6%），说明“38.6%”不能泛化到所有配置。

[SSIM/bilagrid commit](https://github.com/harry7557558/spirula-studio/commit/d78b6d1004ecbefc169b9be93212f039c02b4503) 在同一 RTX 5070 上报告 4946×3286 blur-tolerant SSIM 40.697→36.609 ms（-10.0%）、bilagrid/PPISP 35.788→26.184 ms（-26.8%）；[后续 commit](https://github.com/harry7557558/spirula-studio/commit/c884495c45d6ca9d555c984c6ac0e5fbc97462d3) 把 24×24 tile 在支持设备上扩到 512 threads，fp16 render + uint8 photo 同分辨率 36.246→31.766 ms（-12.4%）。仓库增加 fixed-input benchmark/parity 覆盖，建议在 AMD/Intel/Apple 与不同 footprint 分布复测，而不是只复刻 NVIDIA 数字。

### OpenSplat：decode 失败不再被吞掉

[e33f9dde](https://github.com/WebODM/OpenSplat/commit/e33f9dde8ef9c9d59852ffe4d12e0adddcf1fc1b) 用 worker 级 pinned host staging 依次复用 image/mask buffer，并缓存首个 decode error；acquire() 随后直接抛出 Image decode failed。对坏 JPEG、坏 mask 或尺寸不一致的训练集，这比后台 stderr 后继续等待更容易诊断。变更在 main，无 release tag；CUDA/ROCm/Metal/CPU 都应测试失败传播与退出清理。

### Rust mapping：SIFT 内存和融合定位小步前进

[visloc-rs merge b64b1002](https://github.com/rsasaki0109/visloc-rs/commit/b64b100295f22c1c273da2f7080f1014c68bb41d) 将 gsplat_photos 的 SIFT descriptors 改为 byte storage，维护者在 1024 px 设置报告 mall 7.8→4.5 GB；同日 [PR #410 merge](https://github.com/rsasaki0109/visloc-rs/commit/ff77322c6b3102d83b1b0ab8d3ce40b1dccbbbd7) 加入 gyro heading wheel odometry 与可选 ORB 前模糊。它是活跃研究型 SLAM/mapping 工具，数字来自作者特定 corridor/office/EuRoC 测试，尚不代表通用 Gaussian map pipeline。

## 13. 今天最值得实际测试 / 部署

### 1) OOOSplat MCP staging 闭环

- **为什么**：首次把输入预检、显式回答、任务生命周期、checkpoint resume 与四格式已保存模型导出串成受约束本地协议。
- **门槛**：从 main 构建桌面 App，设置中手动启用 MCP；仅绑定 127.0.0.1；准备普通/全景输入和一个已保存编辑模型。
- **测试**：缺答不得创建任务；错误 expected_run_id 必须拒绝；断连后任务继续；重启后只标 interrupted；SPZ range 调整需确认；失败不能留下半成品；symlink export 目录必须拒绝。
- **预期收益**：本地 agent 可编排重复性重建/导出，同时保留 GUI 互斥、隐私与审批边界。当前成熟度：可实际测试，不是生产无人值守。

### 2) LichtFeld 18k+ camera 大工程响应性

- **为什么**：autosave、camera capture、collision preparation/upload 与 checkpoint 清理形成同一类“大工程操作尾延迟”修复集合。
- **门槛**：GPL-3.0 master；准备大量 camera/nodes、collision 数据与多个 checkpoints；CUDA 训练环境和 Vulkan GUI。
- **测试**：记录 autosave p50/p95/p99、GUI 最长 stall、只改 1/32/65 个节点时的路径、打开工程取消/切换场景、碰撞预览失败隔离、prune 后 resume checkpoint 保留。
- **预期收益**：减少自动保存和大型碰撞预览造成的编辑器冻结，提高长时编辑稳定性。

### 3) Spirula Vulkan 训练 A/B

- **为什么**：变更覆盖 projection backward、SSIM、bilagrid/PPISP、optimizer 和 raster backward，且仓库提供 fixed-input benchmark 与 parity 工具。
- **门槛**：GPL-3.0 master、Vulkan SDK/MoltenVK；建议先用 RTX 5070 复刻作者基线，再测 AMD/Intel/Apple；同一数据集、seed、量化 level、FPBO 开关和 5M cap。

- **预期收益**：匹配作者口径时 FPBO 路径可能显著缩短；跨设备收益未知，需本地复测后再决定升级。
