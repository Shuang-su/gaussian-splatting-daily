## 3. 可实际运行的开源项目

### godotGS streaming 主线

[`godotGS`](https://github.com/klausi3D/godotGS) 是 MIT 的 Godot C++ module/public-alpha 工程。今天三项主干合并有实际价值：

- [#1130](https://github.com/klausi3D/godotGS/pull/1130) 把 streaming demand 限制到 renderer 可见距离；corridor 的 max visible chunks 从 1,561 降到 862，但作者也明确说明新旧 `residency_ratio` 定义改变，不能拿 0.37→0.19 当作退化或提升。
- [#1134](https://github.com/klausi3D/godotGS/pull/1134) 以 1,024-splat pages 做 best-fit contiguous allocation、释放时合并 free run、必要时按 LRU eviction 直到存在足够连续页。`vram_budget_mb` 从“近似提示”变成真正的 atlas ceiling；诊断新增 page capacity、fill、largest free run 与 fragmentation eviction。
- [#1097](https://github.com/klausi3D/godotGS/pull/1097) 把性能面板做成 engine-side `GaussianSplatPerformanceOverlay`，避免多 renderer 数值串线，未测量项显示 `n/a`。它还把 gizmo 属性重命名为 `debug/show_timing_gizmo`，无兼容 alias，属于 public-alpha API 变化。

门槛与风险：需要源码构建该 Godot fork/module；GPU 数据仅 RTX 3090/Vulkan/speed-trace；#1134 的 GPU A/B 不是 release template，量化 atlas 只由单测覆盖。10 月 3 日 nightly 在这些晚间 merge 之前发布，不能视为已包含三项变化。

LichtFeld 正式 [v0.5.3](https://github.com/MrNeRF/LichtFeld-Studio/releases/tag/v0.5.3) 仍停在 6 月。今天的 EXR、RGBA、CUDA stream 与 sampling 修复在 `master`，可源码测试；Node Editor 系列则合入 `dev`，门槛更高。

## 6. Compression / Format / LOD / Streaming

今天最实质的格式/流式变化来自 Godot 的运行时内存布局，而非新格式：

- 旧 atlas 每 chunk 固定 65,536 splats，平均 12.8k 的 corridor chunk 只有约 20% fill；#1134 以 1,024-splat page run 提升到作者测试约 94%。
- page run 必须连续；allocator 采用 best-fit、free coalescing 和受每帧 eviction budget 约束的 evict-until-fit，不做 compaction。碎片化在作者 corridor 中没有成为主要瓶颈，但真实场景 chunk 分布未验证。
- [`#1136` HLOD ADR](https://github.com/klausi3D/godotGS/pull/1136) 已接受：未来 `.gsplatworld` v2 拟用 adaptive-axis octree、内部节点预烘焙 splats、CPU 按 screen-space error/byte budget 选 cut、ancestor fallback 和 cross-fade。**这是设计记录，没有实现，且明确会涉及格式版本 bump。**

SOG、SPZ、PLY、compressed PLY、glTF Gaussian extension、OpenUSD、3D Tiles 与 MPEG GSC 在本窗口没有可核实的新 schema/release。PlayCanvas SOG/SplatTransform 状态沿用昨天，不重复计数。

## 13. 今天最值得实际测试 / 部署

### 1. godotGS streaming atlas A/B

**为什么：** 今天对大场景 Web/引擎式流送最接近“可量化改变”的更新，直接修正预算不生效与 slot 浪费。

**门槛：** 从 `master` 源码构建 Godot module；准备一个 chunk 数多、平均 chunk 显著小于 65,536 splats 的 `.gsplatworld`；最好使用 1 GiB/2 GiB 两档预算。先不要依赖 10 月 3 日 nightly。

**记录：** atlas pages used/capacity、fill ratio、largest free run、resident/drawn chunks、load/eviction、p95 frame、总 VRAM；在 5090D V2 上额外对比作者 RTX 3090 的“预算是否绑定”，不要只比 FPS。

### 2. LichtFeld HDR/RGBA/EXR 回归

**为什么：** #2710/#2715/#2717/#2702 修的是输入与 target 的正确性，尤其适合产品转台、透明背景、16-bit PNG/TIFF 与 DWAA/DWAB plate。

**门槛：** `master` 源码；同一组 8/16-bit RGBA、EXR ZIP/PIZ/DWAA/DWAB；固定背景、mask mode、resize 和训练 seed。

**记录：** first epoch/cache-hit alpha、透明边缘外漏、PSNR/SSIM/LPIPS、cold-load time、瞬时/稳定 VRAM。8K 16-bit TIFF 要预留额外 staging 显存。

### 3. Spirula ROI + Camera Repair 小规模验证

**为什么：** ROI 已在 master，可先验证大场景裁剪；Camera Repair 尚 open，适合在副本上判断是否能避免整套 SfM 重跑。

**门槛：** Vulkan/CUDA 源码构建；复制一份 DJI/360 数据；人为制造 2–5 个坏 pose/缺失注册帧。

**记录：** registered cameras、邻帧 pose jump、reprojection、模型连通性、ROI 内外 splat growth 和训练时间。PR #138 未合入前不要在唯一数据集上直接操作。
