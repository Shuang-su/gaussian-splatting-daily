### PlayCanvas Engine：beta.12 的 GS 显存修复值得马上测

- [#9763](https://github.com/playcanvas/engine/pull/9763) 把 order buffer 的增长从 unified work-buffer resize 移到 CPU sort 真正上传 order 的 `setOrderData`。WebGPU GPU-sort 因而只保留最小 4-byte 占位；4M/16M splats 的作者估算分别少约 18/74 MB。**架构影响**：不改 GPU projection、radix sort 输出、渲染质量或格式；改变的是资源生命周期和 peak/steady GPU memory。CPU sort 与 WebGL 继续按需分配 order buffer。建议在同一场景比较 `usedJSHeapSize` 无意义，应采 GPU allocation/浏览器进程显存与 resize 峰值。
- [`v2.24.0-beta.12`](https://github.com/playcanvas/engine/releases/tag/v2.24.0-beta.12) 还合入 [DynamicSkyEffect #9765](https://github.com/playcanvas/engine/pull/9765)：Preetham 大气、星月、flat/volumetric clouds、自动 envAtlas 和太阳/月亮灯同步；它可改善 GS 场景背景与照明一致性，但不是 relighting，且 camera-frame volumetric fog 不兼容，planar reflection camera 仍渲染 env-atlas sky。
- [Auto exposure default #9764](https://github.com/playcanvas/engine/pull/9764) 把 metering 亮度区间从 50–95% 改为 10–90%，修复亮天空让地面约暗 2 EV 的默认表现。升级后想保留旧画面必须显式设旧值；这会影响含大面积天空的 splat tour 输出一致性。
- [Vision Pro XR #9750](https://github.com/playcanvas/engine/pull/9750) 修复 teleport arc 尾部塌缩、转身后 camera world-position 漂移，并避免 look+pinch transient pointer 请求不存在的 controller model；新增 `currentGroundHeight`。适合 WebXR GS viewer 回归，但不是 GS 专用变更。
- 稳定版仍为 [v2.23.2](https://github.com/playcanvas/engine/releases/tag/v2.23.2)。依赖大规模 WebGPU GS 的项目可 pin beta.12 验证显存；生产项目不应把 beta tag 当稳定升级。

## 3. 可实际运行的开源项目

### InfiniSplat v2：今天可跑的最高优先级

- [官方仓库](https://github.com/zju3dv/InfiniSplat) 已提供 v2 目录、公开 [Hugging Face 权重](https://huggingface.co/Edisoneh/InfiniSplat-v2) 和 [Space](https://huggingface.co/spaces/Edisoneh/InfiniSplat2)；窗口内 [`d30c199`](https://github.com/zju3dv/InfiniSplat/commit/d30c1999ccb2efb001e4b91cc9822c1f649af613) 接入论文，[`a4d3f8b`](https://github.com/zju3dv/InfiniSplat/commit/a4d3f8befc178cb63acdf81fa593f99459aa20c5) 更新 Demo 链接。
- 安装要求 Python 3.10–3.12、NVIDIA CUDA GPU、CUDA PyTorch；官方验证组合为 H20、driver 570、PyTorch 2.7.1/cu128。还需 pin [Depth Anything 3](https://github.com/ByteDance-Seed/Depth-Anything-3) 特定 commit。核心 pipeline 不需要 rasterizer、FlashAttention 或 xformers；可选 PlayCanvas `splat-transform@2.6.0` 生成 HTML。
- 自有场景推荐 2–32 张重叠 JPG/PNG/WebP，默认长边 518；先用 2–4 张、224 测环境。可带 pose 或由 DA3 估计，输出 PLY；大输入 `--max-views 50` 受显存限制。
- **许可证风险**：PRL v1.0 对个人研究/教育免费；公司、大学或其他组织的项目使用（包括内部研发、测试、部署、生产）要求先注册。它不是常见 OSI 宽松许可证。

### LichtFeld Studio：从“偶尔不同”修到 byte-identical

- [#3556](https://github.com/MrNeRF/LichtFeld-Studio/pull/3556)：FastGS forward 保存 sorted primitive indices 时，源 sort buffer 可能与 phase arena 起点的目标重叠；重叠的异步 memcpy 会破坏源，导致整个 16×16 tile 跨运行变化。新分配顺序确保目标至少留出每 instance 16 bytes，且无新增 allocation/kernel/copy。作者在 MCMC bicycle 看到原来 20–25/25 views 不同、最高约 0.1 dB PSNR 波动；修复后三个 eval 进程 byte-identical，7k-iter 训练约 0.9% 变化在噪声内。
- [#3535](https://github.com/MrNeRF/LichtFeld-Studio/pull/3535)：Lanczos init 与 resample kernel 独立计算 support，浮点舍入可让后者读到未初始化 slot。共享 `lanczos_support()`、显式 round-to-nearest、unused slot 写 NaN；作者 initcheck 从 3200 次未初始化读降到 0，重复输出 byte-identical。
- [#3539](https://github.com/MrNeRF/LichtFeld-Studio/pull/3539)：8-bit `--undistort` derived cache 从 lossless JPEG2000 改为 JPEG q95；16-bit、mask/depth/normals 仍无损。首轮与即时载入一致，但 cache hit 存在 JPEG rounding，作者测试 PSNR >36 dB。它是空间/保真取舍，不是 bit-exact cache。
- [#3563](https://github.com/MrNeRF/LichtFeld-Studio/pull/3563) / [#3568](https://github.com/MrNeRF/LichtFeld-Studio/pull/3568)：Windows 超长 UNC 网络路径从最深存在目录逐级解析并在 share root 停止；短路径和非 Windows 恢复标准路径解析。测试含 160–320 字符 Unicode、network share 和 alternate spelling lock exclusion。
- [#3537](https://github.com/MrNeRF/LichtFeld-Studio/pull/3537) 将批量视频 metadata probe 移出 UI thread；[#3549](https://github.com/MrNeRF/LichtFeld-Studio/pull/3549) 把 eval mask 改为有序 pixel-set 列表并生成嵌套 JSON/FLIP map。稳定 release 仍为 [v0.5.4](https://github.com/MrNeRF/LichtFeld-Studio/releases/tag/v0.5.4)，以上均在 master。

## 5. Viewer / Editor / Web / Mobile / XR

## 6. Compression / Format / LOD / Streaming

- [`decb26f3`](https://github.com/WilliamLiu-1997/Gaussian-Splat-Lite/commit/decb26f3199d67e59f2c8fc9a05185f5e09d0cbb) 将 SOG selection 从按 upgrade ratio 的 budget heap 改为共享的 distance bands，新增 `lodBaseDistance`、`lodMultiplier` 和 `splatBudgetMode: target|limit`；同距离 transition 成组移动，避免预算临界时无关区域闪烁。它改变 LOD 选择语义，升级前应录制 camera path 对比 pop/flicker、splats budget 与网络请求。
- Gausify Orbit 的 SOG v2 export 使用 lossless WebP textures、k-means SH palette、相似 splat 合并和 SH trimming；README 的“通常 5–15× 小于 raw PLY”是作者经验，不是跨数据集 benchmark。新 GLB 路线是 TSDF/mesh/texture bake，不等价于 Gaussian 压缩。

<!-- arxiv:2610.20590 -->
- **MFGS**（[arXiv:2610.20590](https://arxiv.org/abs/2610.20590)）：把要传的对象前移为多视图 feature bitstream，并用 importance-guided selection 从同一 bitstream 适配不同 Gaussian budget。作者在 RE10K、ACID、DL3DV 相对 generate-then-compress 报告 99.76–99.86% BD-rate savings、GMACs -52–55%、约 12× end-to-end speedup。当前未找到公开代码、checkpoint、bitstream spec 或端侧 decoder，评级 P2+。

<!-- arxiv:2610.20254 -->
- **GLoD-LVSM**（[arXiv:2610.20254](https://arxiv.org/abs/2610.20254)）：连续 anchor field + geometry-grounded condenser，按预算初始化任意数量 anchors，并支持 decode 时 frustum culling；作者称相对 uncompressed base scene tokens -33.4%、1.23× render 且无质量损失，放宽质量后 -85.5%、3×。它不是已落地的 SOG/SPZ/glTF LOD，未发现代码/权重。
- 本窗口没有 SOG/SPZ/glTF Gaussian extension、OpenUSD、3D Tiles、MPEG GSC、Khronos/W3C WebGPU 的新正式 revision；不要把社区实现更新说成标准变更。

## 7. Training / Reconstruction / SLAM / Robotics / Mapping

- InfiniSplat v2 是 feed-forward reconstruction 今日主线：pose-conditioned 与 pose-free 均可运行；论文称 pose-conditioned 相对最强评测 baseline 平均 LPIPS/DISTS 分别下降 25.8%/32.9%。应分别用已知 COLMAP pose 与无 pose 输入对比，并记录图片数量、分辨率、显存、PLY 数量/大小和失败模式。
- Gausify Orbit web SfM 使用 AKAZE + WebGPU matching + incremental reconstruction/BA，不需 COLMAP；desktop 仍走 COLMAP 4。浏览器训练为 Brush WASM+WebGPU，作者称约为 native Brush 的三分之一速度，但未给统一硬件/数据集表，不外推。
- `incremental-sfm-gaussian-splatting` 的价值是可读的完整教学 pipeline 和诚实对照，不是替代 COLMAP：其单场景 custom SfM 初始化比 COLMAP 少 1.844 dB held-out PSNR，且两者 camera/points/coverage 都不同，不能把差异归因于点数。
- LichtFeld deterministic fixes 应加入 CI：同 checkpoint 同 views 多进程输出 hash、CUDA initcheck、不同编译/优化组合。它们不会自动提高平均质量，却能让回归数据可信。

## 13. 今天最值得实际测试/部署的项目

1. **InfiniSplat v2**：先跑官方 DTU 32-view example，再用同一自有场景做“已知 COLMAP pose / 无 pose”两组。门槛：NVIDIA CUDA、Python 3.10–3.12、PyTorch、pin DA3、下载权重；组织使用需完成 PRL 注册审查。预期收益：把多图到 PLY/HTML 的 scene-specific optimization 替换为单次前馈推理，并得到真实延迟/显存/质量基线。
2. **PlayCanvas beta.12 #9763 + Gaussian-Splat-Lite SOG LOD**：用 4M/16M 或可达到的最大场景，记录 WebGPU buffer allocation、浏览器进程显存、resize 峰值、LOD pop/flicker、budget adherence；再在 WebGL/CPU-sort 验证无行为回归。预期收益：大场景显存降低与更可控的距离 LOD。
3. **Gausify Orbit WebGPU → SOG/GLB**：用一段真实手机 orbit 和一段 AI orbit，分别测试 SAM2.1、web SfM、Brush 训练、SOG 体积/质量、GLB texture seams/holes/耗时；不要用 RMBG-1.4 做未审许可的商业评估。门槛：desktop Chrome/Edge WebGPU；本地源码构建另需 pnpm、Rust/wasm-pack。预期收益：零 CUDA 安装的端侧 capture-to-asset 闭环。
