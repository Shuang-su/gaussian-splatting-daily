## 2. SuperSplat / PlayCanvas 工具链

### SplatTransform 3.10.1：托管稳定性修复

[v3.10.1](https://github.com/playcanvas/splat-transform/releases/tag/v3.10.1) 把昨天仍是 commit/PR 的 display-space stats、ZIP64，以及今天新合入的 [#353](https://github.com/playcanvas/splat-transform/pull/353) 一起变成可锁版本。#353 改的是 worker pool：worker 在 ready 前失败时不再无界补位；若仍有存活 worker，就让它们完成队列；若一个都没有，任务转当前线程。新增回归测试直接覆盖构建后的 library。

转换算法及 SOG/SPZ/PLY 结果不变；直接收益是 CSP、错误 MIME、worker 文件网络失败、自定义部署路径不再造成 CPU 风暴和永久挂起。内联回退可能阻塞 UI，故“能完成”不等于性能无损。**建议马上升级**转换服务，并分别以正常 worker、禁止 worker 的 CSP、错误 worker URL 回归。

### SuperSplat Editor / Viewer 与 Engine

[SuperSplat Editor](https://github.com/playcanvas/supersplat) 与 [Viewer](https://github.com/playcanvas/supersplat-viewer) 本窗口无新 commit、merged PR 或 release；没有新的 Editor/WebGPU、selection/picking、histogram、viewer export、camera animation、shared settings、LOD、streaming 或 stochastic rendering 变化。

[Engine #9710](https://github.com/playcanvas/engine/pull/9710) 将内部 ComputePass 放到 camera render 之后，使其可处理当前帧 color/depth；[#9722](https://github.com/playcanvas/engine/pull/9722) 加 XR view 选择与 before/after 回调，避免左右眼重复 dispatch。它们不是 splat 专项，也未修改 sorting/projection/shader，但为未来 GPU sort、投影或 XR 单次计算提供正确的帧阶段。当前属于 beta 架构信号，不要求 SuperSplat 用户立刻升级。官方博客、文档、论坛未发现同窗口新增 GS 公告；需登录的 Discord 未读取。

## 4. 4D / Dynamic Gaussian

[OuroWorld 项目页](https://ouroworld.userwei.com/)、[论文](https://arxiv.org/abs/2610.12461) 与 [GitHub](https://github.com/youzhe0305/OuroWorld) 已公开。方法先建立静态 3DGS，再以 Fourier deformation 表示周期运动，并用 grounded drift 控制不同区域。README 给出 Linux、Python 3.11、PyTorch 2.4.1/cu121、24GB NVIDIA GPU、约 35GB RAM 与约 55GB 模型；多视图约 70 分钟、周期 4DGS 训练约 1.5 小时、渲染约 20 秒/30fps，39 场景数据在 Hugging Face。

**可运行性：研究原型，代码+数据+权重路径。** 已发布场景不需生成 API；自定义 reference video 可用 GPT-5.5/Seedance 或 Wan2.2，VGGT-Omega 需门控访问。主仓 MIT 不自动覆盖 vendored 4DGS、VGGT 与模型权重条款。

固定监控的 [hustvl/4DGaussians](https://github.com/hustvl/4DGaussians)、[fudan-zvg/4d-gaussian-splatting](https://github.com/fudan-zvg/4d-gaussian-splatting) 与 [Dynamic3DGaussians](https://github.com/JonathonLuiten/Dynamic3DGaussians) 本窗口无新 commit/release。

## 5. Viewer / Editor / Web / Mobile / XR

[splatkit e3e5720f](https://github.com/Xget7/splatkit/commit/e3e5720feca4c85e617bcbd7a4126840c5bd64e9) 是移动端最值得关注的变化：Android 目标 API 29+、Vulkan 1.1、arm64；iOS 是 SwiftPM beta Metal renderer；React Native 提供统一 SDK。显式 SPZ v2/v3/v4 与 RDF/RUB 归一化可减少“能解码但朝向/手性错误”。

边界也很清楚：作者记录 iPhone 17 Pro 加载 12M SH2 SPZ 会 OOM；改用 LOD+SH1 后约 3 秒进入，但 .lodsplat 约 1.25GB，对比 SPZ 214MB，且当前整棵层级仍驻留内存。它证明移动链条可跑，不代表已解决随机访问与真正流式内存。

LichtFeld [#3162](https://github.com/MrNeRF/LichtFeld-Studio/pull/3162) 修复 12 个 sequencer 问题：清空后重置 playhead、PLY scrub 正确报错、逐帧视频更新时间戳、停止空闲重绘、修正 Ping-Pong 反转；作者 9M garden filmstrip 约 32→58fps。它改善 camera/path 与序列发布稳定性，不改项目格式。

## 6. Compression / Format / LOD / Streaming

[LichtFeld #3182](https://github.com/MrNeRF/LichtFeld-Studio/pull/3182) 将 gallery SSOG chunk/unit 从 256K 降到 64K，仍保持最粗层 ≤500K、最多 8 级。更小页可减少低带宽/移动端的过取、峰值解压和驻留浪费；代价是 range request、索引与调度开销增加。应以同一场景比较首屏、请求数、总传输、峰值内存和快速移动时的模糊/抖动。

[luce-spz 0.1.0](https://github.com/dymokomi/luce-spz) 可读 SPZ v1–v4、写 v4，处理 16 种坐标系和 Adobe extension；SH0–3 保留，SH4 明确告警丢弃，pack/unpack/zstd 可并行。Apache-2.0、含参考兼容测试，但无标准包管理分发且当天创建，定级 P1-。

本窗口未发现新的 Khronos glTF、OpenUSD、3D Tiles、MPEG GSC、W3C/WebGPU 正式标准更新；既有 KHR_gaussian_splatting release candidate、SOG/SPZ/PLY 能力不重复报道。

## 7. Training / Reconstruction / SLAM / Robotics / Mapping

[Spirula 5c9a9a37](https://github.com/harry7557558/spirula-studio/commit/5c9a9a378c225ba61e8320f453d2ded702e51b1f) 为 coarse tile trials 加 guard，并以 vkCmdDispatchBase 分拆 dispatch。触发案例是 M2 Max、5M splats、432px 在 3000 steps 后第一次 128px trial 丢 device。作者在 Intel UHD、4946×3286、753K splats bicycle 上给出最长 submit 从 5.4s/1.6s 降到最大 478ms，总时 4:59→4:47；RTX 3070 的 600 steps 仍约 19.5s。修复不覆盖 CUDA 与 per-splat kernels。

[97d994f5](https://github.com/harry7557558/spirula-studio/commit/97d994f5a0219be136584dd8d7592c6446182ff1) 允许 Vulkan subgroup 到 64；AMD GCN wave64-only 可运行，RDNA 可按 kernel 选 wave32/64，并可用 SS_VK_SUBGROUP 覆盖。Ryzen 7000 iGPU/RADV wave64 dump-compare 通过，仅有原子顺序微小噪声。稳定 release v2026.10.6 尚不含两项。

LichtFeld [#2138](https://github.com/MrNeRF/LichtFeld-Studio/pull/2138) 把 depth、normal、consistency 与 flattening channel/gradient 接进 GUT；pinhole 用 camera-Z，fisheye/equirectangular 用 radial depth，缺失先验可由 MoGe-2 生成。作者跑了 60 组受控 200-step、48 个 geometry tests、CUDA memcheck 与 30K MRNF；GUT 约比 FastGS 低 0.1dB但法线更好，仍需自有 360/鱼眼数据复现。

[nerfstudio-project/gsplat](https://github.com/nerfstudio-project/gsplat)、[WebODM/OpenSplat](https://github.com/WebODM/OpenSplat) 与 [graphdeco-inria/gaussian-splatting](https://github.com/graphdeco-inria/gaussian-splatting) 本窗口无新 commit/release。

### 3) Spirula Vulkan watchdog + AMD wave64
