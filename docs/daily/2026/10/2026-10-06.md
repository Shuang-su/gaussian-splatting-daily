## 2. SuperSplat / PlayCanvas 工具链

今天是 PlayCanvas 专项的实质更新日。

### SuperSplat Editor 3.5.2

[#1066](https://github.com/playcanvas/supersplat/pull/1066) 在打开 Publish 对话框时并行请求 `GET /splats/limits`：日发布额度耗尽或正在处理的 scene 达上限时，会在真正上传前禁用 Publish 并给出恢复时间。只更新 animation、不重新上传 model 的既有 scene 不受影响；旧服务器或 limits 请求失败时仍回退到旧行为。

上传协议同时修复三个真实问题：

- `filename` 过去误写成 `fileName`，服务器忽略后会落成默认文件名；现在同时提交 source format，可在传输前拒绝不支持格式。
- 每个 10 MB part 单独请求 signed URL 改为每批 20 个；15 分钟后刷新批次，避开 20 分钟过期。
- 单 part 失败以 1 s、2 s backoff 最多重试三次，每次换新签名 URL；无 ETag 会给出明确错误。

这不是带宽加速算法，但对 10–20 GB 的 SOG/SPZ/PLY 发布是明显稳定性升级。限制是维护者只跑了 lint/typecheck/build，没有登录实际服务完成端到端上传。

### SplatTransform 3.9.1 / 3.9.2

[#347](https://github.com/playcanvas/splat-transform/pull/347) 将 SPZ metadata 查询拆出独立的 `readSpzHeader` / `statSpzSource`：

- v4 直接读 16-byte plaintext header。
- gzip 包裹的 v1–v3 通常只拉前 64 KB；若 FEXTRA/FNAME/FCOMMENT 很长，则 16× 扩张 range，直到拿到 header 或最终退化为全文件。
- LCC2 的 chunk header 复用同一解析器，避免固定 64 KB prefix 对合法大 gzip header 的误判。

[#348](https://github.com/playcanvas/splat-transform/pull/348) 让单输入、只执行 `--info ... null` 的 CLI 真正走 `readFileInfo`，而不是打开完整 source。代价是语义变化：header 正确但 payload 截断的 SPZ 仍会显示数量，只有 full read 才报错。因此资产验收需把“快速盘点”和“完整校验”分开。

### PlayCanvas Engine

[#9673](https://github.com/playcanvas/engine/pull/9673) 将 GS LOD、AABB、node AABB 调试统一到 15 色 palette，避免 LOD 8+ 看起来像 LOD0。billions 示例对所有 tile 设置 `lodMultiplier=1.5`，将有限 splat budget 拉回近景，并显示颜色图例。

同窗口还有 [0×0 canvas resize 防护](https://github.com/playcanvas/engine/commit/b30cb3dd358a8fda0db6e68880baf7a0f2b5ed54)：隐藏/折叠 canvas 或 Chrome device mode 切换时保留现有分辨率，避免 WebGPU zero-size swapchain validation error 与 WebGL2 incomplete framebuffer。它不是 GS 专属，但直接提升嵌入式 viewer 的稳定性。

SuperSplat Viewer 本窗口没有新的 GS commit/version，1.37.0 仍是 XR/LOD 回归基线。公开 Discord 如需登录或加入服务器，本轮没有直接读取，也没有采用未核实转述。

## 3. 可实际运行的开源项目

### Spirula：E57 扫描仪数据直接变成训练输入

[E57 PR #101](https://github.com/harry7557558/spirula-studio/pull/101) 新增 `spirula e57` CLI 与 GUI/drop-file 入口。内置 reader 直接解析 XML、paged binary、`bitPackCodec` points 与 image blobs，不新增 libE57Format/Xerces 依赖。

输出包含：

- pinhole 或 full-sphere panorama cameras；pose/intrinsics 以 double 写入。
- 默认 voxel-thin 到 500k、或 `--points all` 的 double-precision PLY seed。
- 每相机 16-bit mm depth 与朝向相机的 normal map。
- `gauge.txt` 标记 oriented/metric frame；Nerfstudio parser 也开始读取该文件。
- 对 24 种 axis turns 做图像与 coloured points 相关性检查，证据足够时自动修正相机方向。

合入前的真实验证覆盖 BLK360、Lixel 与 Matterport Pro3，另有 synthetic E57、相机 round-trip 0.002 px、plane/sphere depth tests。未覆盖 Linux/CUDA，也没有把 SAM 3 mask 全数据集跑完；因此属于“可实际测试”，不是跨扫描仪生产认证。

### GSPAR：Gaussian map 进入规划栈

[GSPAR](https://github.com/JiahaoChen14/GSPAR) 是 TU Braunschweig 硕士项目的首次公开代码，基于 NeRFICG：

- Direct：直接对 3DGS 计算碰撞，接 RRT 与 trajectory optimization。
- Global：从 checkpoint 构建 sparse voxel map，以 JPS 做 global、EGO 做 local planning；地图可以复用于多次查询。
- 安装参考环境是 Python 3.11、CUDA 12.8、Linux/NVIDIA，并需要 CMake、Eigen、glog 与 NeRFICG submodules。

仓库有完整训练、建图、GUI 和 batch/evaluation 路径；许可证文件是 MIT，但它继承的 NeRFICG/子模块仍需逐项核对。首次公开 commit 是 2026-10-05 20:13 北京时间，属于今日窗口内的新项目，不是旧代码传播。

### LichtFeld / Spirula 的发布边界

LichtFeld 今日变化都在 `master`，正式 release 仍需单独核对；Spirula E57 与 EXR alpha 也只证明合入 `master`。日报不把“master 可编译”表述成“稳定二进制已经包含”。

## 6. Compression / Format / LOD / Streaming

今天最直接的格式变化是 **SPZ metadata path**，不是编码 schema：3.9.1/3.9.2 仍读现有 v1–v4，只将 header peek 与 full payload decode 分离。资产服务可以低内存扫描多 GB 文件，但必须另设完整读取/校验任务，不能把 `--info` 成功当成文件健康证明。

[Budgeted-GS](https://arxiv.org/abs/2610.03162) 提出把任意训练后 3DGS 转为 moment-matched factoring tree，按设备预算选 cut；同时提出 budget-centered training。作者声称对 13 个场景按预注册协议验证，并在单张消费 GPU 以 1080p/full SH 实时跑官方 city capture，但无代码、硬件/表格需从论文逐项审计，当前只列 P2。

PlayCanvas Engine #9673 只调整 LOD debug palette 与 billions 示例的 `lodMultiplier`，不应写成新 compression/streaming 格式。SOG、SPZ、compressed PLY、glTF Gaussian extension、OpenUSD、3D Tiles 与 MPEG GSC 本窗口没有新的正式 schema 或标准里程碑。

## 7. Training / Reconstruction / SLAM / Robotics / Mapping

### LichtFeld 高分辨率评估链

[PR #2848](https://github.com/MrNeRF/LichtFeld-Studio/pull/2848) 将 CUDA image 直接量化为 interleaved bytes 后下载，移除 device float intermediates；CPU 的 float→8/16-bit 与 resize 并行化并避开逐样本 `std::lround`。作者 40 个 5120×2700 视角从 2.74 s/image 降到 1.35–1.48 s，保存图像与 metrics 不变。

[PR #2856](https://github.com/MrNeRF/LichtFeld-Studio/pull/2856) 再用 `PipelinedImageLoader::decode_ahead` 将下一张 8/16-bit/float reference 的 CPU decode 与当前 GPU scoring 重叠；不预先上传、不提前占设备内存，只多保留一张 host image。相同 workload 进一步到 1.06 s/image，peak VRAM 7999→7989 MiB。

这两项数字来自 resume-only evaluation，并非训练总时长；JPEG 与已缓存图不会走 decode-ahead，因此实际收益取决于输入格式。

### Spirula 与机器人规划

E57 直入路径让激光点、已配准相机、depth/normal supervision 和 metric gauge 组成同一个训练 dataset，避免为扫描仪已经解算的数据重复跑 SfM。GSPAR 则把训练后的 Gaussian map 接到 collision/planning；两者组合是今天最接近“采集→重建→可行动地图”的开源链条，但尚未证明彼此直接兼容。

Spirula #145 的 EXR alpha 对影视/合成 plate 很关键：SfM keypoints 和训练 mask 终于共用透明区域语义。要显式区分 cut-out subject 与 undistortion border，否则 auto mask 可能损坏背景几何。

## 8. Avatar / Human / Generative 3D

## 13. 今天最值得实际测试 / 部署

### 1. SuperSplat 3.5.2 + SplatTransform 3.9.2 大资产发布回归

**为什么：** 这是今天对 WebGS 发布链最直接的变化：编辑器在上传前暴露额度/并发限制，CLI 对 SPZ 盘点不再占用数 GB 内存。

**门槛：** 准备 1 GB、10 GB、20 GB 的 SPZ/SOG/PLY；有可登录 PlayCanvas 发布环境；同时保留 3.5.1/3.9.0 对照。

**记录：** `--info` wall time/peak RSS、signed-URL 请求数、part retry、ETag、上传完成率、服务端 filename/source format、额度耗尽提示。另做一次截断 SPZ，确认 fast info 成功而 full read 正确失败。

### 2. Spirula E57 → 3DGS 训练小闭环

**为什么：** E57 已经包含注册、图像和激光点时，跳过 SfM 能显著减少重复计算，并保留 metric scale。

**门槛：** `master` 源码；优先使用 BLK360/Lixel/Pro3 之一的副本；固定 `--points 500000` 与 `all` 两档，保留原始 E57 hash。

**记录：** 相机数/被跳过图像类型、axis correction、point count、depth/normal coverage、gauge、首步与最终 PSNR/geometry、坐标量级。若图像是 EXR，再 A/B cut-out 与 Ignore distractors。

### 3. LichtFeld 5K evaluation + 导出 WebXR

**为什么：** #2848/#2856/#2863 组合可同时验证离线评估吞吐、viewport overlays 成本和头显交付体验。

**门槛：** `master` 源码；40-view 5120×2700 数据、约 5M splats、Chrome WebXR 头显；固定同一 build/scene/camera。

**记录：** s/image、CPU/GPU overlap、host RAM/VRAM、saved image byte identity、frustum off/on GPU ms、depth/mesh occlusion、XR label/measurement alignment、stick/grip locomotion。正式 release 前不要覆盖唯一生产环境。
