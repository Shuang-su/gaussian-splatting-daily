## 2. SuperSplat / PlayCanvas 工具链

### Engine 2.23.2：全视野粗 LOD 优先进入稳定版

[v2.23.2](https://github.com/playcanvas/engine/releases/tag/v2.23.2) 正式包含 [#9694](https://github.com/playcanvas/engine/pull/9694)。该 PR 的算法已经在 10 月 8 日日报解释过：请求优先级由距离优先改为 tier → 更粗 LOD → 距离，先让整个视野达到同一粗层，再继续细化。它主要改善首屏均匀性、快速转向和受限带宽体验，不保证最终 FPS 上升。此前只建议测 master；现在可以锁稳定版做部署回归。

### WebGL 资源正确释放

[#9726](https://github.com/playcanvas/engine/pull/9726) 修复 WebGL2 VertexBuffer 销毁后 VAO 仍等待 GC 的问题。Chrome 可能继续保留已删除 vertex/index buffer，并因缓存错误跳过新 index buffer bind，最终出现 “Insufficient buffer size” 和几何缺失。对频繁重建 mesh、碰撞代理、测量辅助物或场景切换的 GS 应用有直接稳定性价值；纯静态 splat 不一定触发。

### WebGPU debug 构建不再每 draw 建 error scope

[#9725](https://github.com/playcanvas/engine/pull/9725) 将验证 scope 从每 draw 移到每次 command submission。作者的 debug-only 场景在约 2,500 draws 时由 63.6ms 降至 3.6ms；release build 原本就会移除这些 scope，因此这不是生产 FPS 提升，而是让 WebGPU 调试大型 GS+mesh/XR 场景不再被验证开销淹没。

SuperSplat Editor、Viewer 与 SplatTransform 本窗口没有新的 commit/release；selection、histogram、camera/path、viewer export、SOG/SPZ 编码和 stochastic renderer 均无新增。Discord 未直接读取。

## 3. 可实际运行的开源项目

### 3DGS-LOD：面向现有 PlayCanvas runtime 的训练感知 LOD

仓库创建于 10 月 10 日，当前 2 stars、MIT，最新 commit [966ebc1f](https://github.com/Azusa309/3DGS-LOD/commit/966ebc1f7f09cab7f6969e3eab5de1f769b4eed3)。lodkit 输入 trained PLY 与原 COLMAP views，按 ΣT·α 计算贡献度，做 geometry-gated merge，只优化 SH+opacity 恢复外观，然后调用官方 SplatTransform 输出 lod-meta.json。runtime 无需改 PlayCanvas。

作者在 DTU scan1/scan6、1.45–1.48M Gaussians 上报告：25% level 与 teacher 的 PSNR/LPIPS 很接近；M1/Chromium 720p 上 50% level 文件 22.9→13.1MB、117→150fps，首帧 362→213ms。三层构建在 RTX 4090 约 173 秒。限制是仅两件 DTU 物体、无户外/大场景/手机测试、要求训练相机、只支持 undistorted pinhole；强主张应视为作者基准而非普遍结论。

### Gaussian Splat Renderer：Vulkan 与 WebGPU 共用可验证路线

[首次 commit 5abe77c8](https://github.com/netolcc06/gaussian-splat-renderer/commit/5abe77c81668e91391e4f351992a66d4a1820fb2) 提供 C++20/Vulkan 1.3 native 和 Emscripten/WebGPU。四条路径包括 CPU sort+quad、GPU radix sort、compute tile rasterizer 和 point debug；另有 CPU reference、image diff、Vulkan validation 与 headless browser tests。

门槛：Windows 10/11、VS2022、CMake ≥3.24、Vulkan SDK 1.4；Web 需 Emscripten 6.0、Ninja 与 WebGPU 浏览器。RTX 4060 Laptop、1080p 作者数据中，tight bounds+adaptive list 对 train/bonsai 分别约 4.26/4.03ms，声称与 CPU reference 约 58.77dB。MIT、0 stars、单一首次提交，成熟度为可测试原型而非生产库。

### Gaussian-Splat-Lite

[15475268](https://github.com/WilliamLiu-1997/Gaussian-Splat-Lite/commit/154752681ccd58696c6a70efc9872ec9c15889eb) 将 WebGPU projection kernel 独立并简化 TSL 类型；[da1e0f6d](https://github.com/WilliamLiu-1997/Gaussian-Splat-Lite/commit/da1e0f6d507b3874af83d3bf89abdd230b7e04c8) 重用输入快照，减少每帧数组、slice 和 matrix spread。代码结构更清晰，但无性能数字、未发版；只建议在固定 Three.js r186 与 XR/mono 场景做 allocation/GC profile。

## 5. Viewer / Editor / Web / Mobile / XR

Spirula [#173](https://github.com/harry7557558/spirula-studio/pull/173) 在 trainer 和 viewer 中共享五个 dataset-frame camera bookmarks；position、rotation、pivot、camera model、FOV 和 orthographic 均被保存，切换 leveling 或 model placement 不会移动书签。

[#174](https://github.com/harry7557558/spirula-studio/pull/174) 通过引擎以固定尺寸渲染，而不是抓屏；默认 1920×1080，训练不停止，JPG/PNG 可嵌入 run、step、splat、VRAM、尺寸与 dataset-frame pose。对视觉回归、训练设置 A/B 和展示交付非常实用。Windows CUDA/Vulkan 已测；Linux/macOS 未由作者验证。

新 Vulkan/WebGPU renderer 的浏览器端是独立 C++→WASM 路线，支持 PLY SH0–3、GPU scan/radix/tile 和 live demo；没有 LOD/streaming，所以它适合研究 renderer 与硬件 profiling，不替代 SuperSplat/PlayCanvas 的大场景发布链。

## 6. Compression / Format / LOD / Streaming

3DGS-LOD 的关键价值不是新 runtime 格式，而是改进标准 Streamed SOG 各层内容。它最终仍由 SplatTransform 3.10.0 编码，因此现有 PlayCanvas viewer 可直接加载；主要代价是需要训练相机和 CUDA recovery，不能像单纯 -d 那样只给 PLY 即运行。

新出现的 .py3s 仓库提供 MIT 的 Python/C++/TypeScript pack/unpack，把 splat payload、碰撞、metadata 和 thumbnail 装进 128-byte header 容器。但其所谓“标准”和 Unreal 一键插件能力目前仅由单一项目自述，未见 Khronos、MPEG、OpenUSD 或主流引擎采纳；定级 P2 社区格式，不与 SPZ/SOG/glTF 标准化混淆。

本窗口没有新的 SPZ、SOG、glTF Gaussian、OpenUSD、3D Tiles、MPEG GSC 或 W3C/WebGPU 正式标准变更。

## 7. Training / Reconstruction / SLAM / Robotics / Mapping

### Spirula dense filters

[#161](https://github.com/harry7557558/spirula-studio/pull/161) 把过滤器从 fusion 逻辑分离：two-image points 会用三图点误差中位数和 free-space test 判断；depth precision 限制不可精确恢复的深度；far-isolated 删除稀疏点包围盒外的孤点；metric 模型按 baseline 拒绝过远配对；reprojection check 重读输出 PLY 并写 p50/p95。

默认仅 far-isolated 和 metric max-baseline 生效，reconstruction revision 4→5，会重建 dense cache。全开可补困难区域，但作者 basement 样例耗时约 197→1027 秒，不能默认启用 two-image 路径。

### Metashape PSX 直读与 A1 遥测

[2f8650e6](https://github.com/harry7557558/spirula-studio/commit/2f8650e66672ed9d721a9ceddcca19da6e1b0dd7) 让 .psx 不再只用于 XML 文件名消歧，而可直接读 active chunk 的 sensors、components、camera poses、frame photo paths 和 point_cloud.zip tie points；项目需在 Align Photos 后保存。

[604e195b](https://github.com/harry7557558/spirula-studio/commit/604e195ba8f85d19b100dc042807e4942f2b9102) 支持 Antigravity A1：VID.insv 两路 3840²，IMU 原始 int16、GPS 约 0.6Hz；PRX proxy 无传感器时按 serial 和 first-frame timestamp 找对应 VID 读取。对全景无人机 mapping/GPS BA 有直接输入价值，但目前证据是一段 119 秒 flight。

LichtFeld 的 #3194/#3193/#3197 则属于测量链正确性：旧的非整除 downsample 会让 fx/cx 出现约 0.06% 偏差；旧 eval split 会随 COLMAP 写入顺序变化；第二批 cameras-only 导入会复用 UID，导致 frustum/picking 指向第一批相机。

## 13. 今天最值得实际测试 / 部署

### 1) 3DGS-LOD 对真实 WebGS 场景的 A/B

**门槛：**MIT；CUDA GPU、Python ≥3.10、gsplat 1.5.3、Node ≥22；必须有训练 PLY、COLMAP images/sparse。  
**测试：**同一 teacher 构建 50/25/10% levels，对照 SplatTransform -d 与 “-d+同 recovery”；经过 SOG encode/decode 后测 PSNR/SSIM/LPIPS、文件大小、首帧、转向恢复、移动端内存。  
**预期收益：**若在户外/建筑场景复现，可在不改 PlayCanvas runtime 的前提下显著提高粗 LOD 画质；最大风险是 DTU 结果不能外推。

### 2) Spirula dense filters + Metashape PSX

**门槛：**GPL-3.0、晚于 [38f8b956](https://github.com/harry7557558/spirula-studio/commit/38f8b9564ac8b2dc354ad65b1a365a302db258d7) 的源码；准备一份已 Align Photos 的 PSX 和薄结构/楼梯数据。  
**测试：**先默认，再单独开启 two-image/free-space、reprojection-check；记录点数、重投影 p50/p95、free-space violation、运行时间和 cache 重建。  
**预期收益：**减少 PSX→XML/PLY 的人工中转，并用可量化过滤补足困难区域；不要把 5.4× 慢的全开配置当默认。

### 3) PlayCanvas 2.23.2 + Engine #9726 生命周期回归

**门槛：**MIT；稳定版 2.23.2 测 streamed SOG，若验证 #9726 则需更新到含 41dd4a52 的后续构建/master。  
**测试：**限速网络下测全视野首屏 LOD；同时循环创建/销毁大型 indexed mesh 或碰撞代理，观察 Chrome GPU memory、缺失几何和 Insufficient buffer size。  
**预期收益：**前者把 coarse-first 策略带入稳定部署；后者可消除长会话中资源滞留和偶发绘制失败。
