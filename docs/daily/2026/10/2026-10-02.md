## 2. SuperSplat / PlayCanvas 工具链

### Viewer #322：独立头显不再误用 desktop 4M budget

[PR #322](https://github.com/playcanvas/supersplat-viewer/pull/322)，merge commit [`3d87dc8a`](https://github.com/playcanvas/supersplat-viewer/commit/3d87dc8aa104b892921f1b10c9b04bf5ff51bc0f) 修复了一个很实际的分类错误：Quest/Pico 浏览器 UA 报告 Linux desktop，Viewer 因而给它们 **4M desktop splat budget**；XR 又要每眼各画一次，Quest 3 最终只有 9.7 fps。

现在独立头显 session 默认：

```text
streamed budget      1M（显式 budget 仍优先）
fixed foveation      1
target refresh       72 Hz（设备支持时）
performance mode     0.8× render resolution
exit XR              恢复原 2D budget
```

作者在 Quest 3、Quest Browser 152、WebGL、Engine 2.22.6 的结果：

| 模式 | Budget | 分辨率 | FPS |
|---|---:|---:|---:|
| 修复前 | 4M | 3360×1760 | 9.7 |
| Quality | 1M | 3360×1760 | 30.7 |
| Performance | 1M | 2688×1408 | 40.3 |

主线程只用 1.1–1.8 ms，瓶颈明确在 GPU；每 1M splats 约增加 18 ms。这个结果不能外推到 Pico，因为 Pico UA 检测未在真机验证；单文件非 streamed scene 也没有 splat budget，只会得到 foveation/分辨率收益。

### Viewer #323：双手把环境缩成桌面模型

[PR #323](https://github.com/playcanvas/supersplat-viewer/pull/323)，merge commit [`4a173177`](https://github.com/playcanvas/supersplat-viewer/commit/4a17317780072b5920286896c69404d1a022fd9a) 把 Engine 的 `XrManipulation` 接到 camera rig：双手 grip 或 tracked-hand fist 可移动、yaw 旋转、缩放 splat；VR 绕脚底 pivot，AR 绕双手 pivot，退出 session 恢复 authored placement，避免破坏 viewer 的 camera framing、collision 与 annotation 假设。

Quest 3 上 1M streamed scene 在拖动时由 28.2 降到 21.9 fps，因为世界变换变化会每帧重拷 work buffer 并重排；松手后无持续性能损失。这是功能性进步，但还不是“零成本 XR manipulation”。

### Viewer #324：XR LOD 按距离选，不再因头部朝向降级

[PR #324](https://github.com/playcanvas/supersplat-viewer/pull/324)，merge commit [`e83a447e`](https://github.com/playcanvas/supersplat-viewer/commit/e83a447eac29d6bb45cd63c2aafd6742f5a3d453) 在 XR 内把：

```text
lodBehindPenalty: 5 → 1
lodUpdateAngle: 90° → 0
```

也就是完全按距离选择 streamed detail，不再把身后区域视为最远 5 倍，也不因头部转动触发重新平衡/重流式。作者固定 1M budget 的脚本测试中，转 80° 后原本位于身后的画面区域由 97K splats 提升到 150K；代价是正对最初方向时总体 splats 约少 8%。

## 3. 可实际运行的开源项目

### SplatTransform：SOG 生成从串行等待改为重叠流水

[PR #340](https://github.com/playcanvas/splat-transform/pull/340)，merge commit [`b9809137`](https://github.com/playcanvas/splat-transform/commit/b98091373f647f895d78469a657e67cae7f60d35) 包含两层优化：

1. 对没有 `shader-f16` 的 WebGPU 设备（例如 NVIDIA/Dawn/Vulkan），f32 k-means assignment 改用 zero-padded `vec4`、`|c|²−2x·c` 距离形式和 128-thread workgroup；
2. LOD writer 把 `writeSogSource` 拆成 start/finish，两份 unit 最多同时驻留，让下一 unit 的 GPU k-means 与当前 unit 的 CPU encode/write 重叠。

A10G `castle.ply`、5M Gaussians、SH3、生产参数的作者数据：

| 工作负载 | Before | After |
|---|---:|---:|
| 3M×45、K=65536、10 iter k-means | 23.7 s | 12.5 s |
| PLY→SOG | 51.0 s | 31.8 s |
| 4 LOD、9.4M streamed combine | 144.5 s | 69.9 s |

M4 Max 走 f16 kernel，普通 SOG 基本不变（44.4→43.9 s），但 streamed SOG 仍因流水重叠从 56.4 降到 44.4 s。839 tests 通过；输出除随机 k-means 的 `shN` codebook 外与旧版一致。

同一提交还加入 `--lod-file-count <n,n,...>`，允许每个结构 LOD 指定 file-unit 的 Gaussian 数，最后一个值对更粗层重复；它只改变 leaf 打包进文件的方式，不改变 `--lod-chunk-count` 的 leaf split。这对网络请求数、单请求大小与解码峰值的 A/B 很有价值。

[PR #341](https://github.com/playcanvas/splat-transform/pull/341)，merge commit [`efb2fa3d`](https://github.com/playcanvas/splat-transform/commit/efb2fa3dab128d20870cf522e67b9f6c19a669b3) 则让 `readPly` 真的遵守 `binary_big_endian`，并对 ASCII 给出清晰拒绝；过去两者都可能被按 little-endian binary 静默读坏。

正式版本仍为 [3.8.0](https://github.com/playcanvas/splat-transform/releases/tag/v3.8.0)，因此这两项均按 `main` 可测，不写成 npm 已发布。

### LuluSplat v1.1.2：Windows/Vulkan 的一体化本机流程

官方产品页当前同时提供 [Mac 与 Windows v1.1.2](https://liquiduslabs.com/lulusplat/)：

- 输入：stills、普通视频、equirectangular 360、Insta360 `.insv`、COLMAP；
- SfM：提帧、模糊过滤、相机解算、稀疏重建检查；
- 训练：Mac Metal；Windows Vulkan；Vanilla 与 MCMC；
- 输出：`.ply`、`.splat`、`output-log.txt`；
- 自动化：batch、headless CLI、JSON 输出、内置 MCP server；
- Windows 门槛：Windows 10/11 x64、2016 年后 Vulkan-capable GPU，安装包约 83 MB。

直接下载免费且可离线运行，但官网没有公开自身源码或软件许可证，所以应标记为**可下载闭源工具**，不能把它使用的 gsplat/metal-gauss 开源组件自动等同于整个产品开源。Reddit 作者帖声称 RX570 可运行，证据只作为 C 级单机演示，不把它升级为通用性能保证。

### LichtFeld：多大模型同时加载的合并成本下降

[PR #2620](https://github.com/MrNeRF/LichtFeld-Studio/pull/2620)，merge commit [`1fdfa3e7`](https://github.com/MrNeRF/LichtFeld-Studio/commit/1fdfa3e70898f792d77d746399d8f9931be56b41) 不再为所有模型的 SH 建整份 float 临时副本，而是按 bounded bands 编码 q16 payload，并让量化输入在 GPU 上解码。

三个 5M SH3 模型：

| 输入 | 峰值 GPU | Build time |
|---|---:|---:|
| quantized | 5.4→3.7 GB | 2.2→0.13 s |
| float | 5.2→3.8 GB | 约多 16 ms |

输出与旧 builder byte-identical。紧接的 [#2621](https://github.com/MrNeRF/LichtFeld-Studio/pull/2621) 修复 allocator 为 means 预留额外 rows 后，SH degree 检查按 capacity 而不是 row count 失败的问题。它们适合“多个分区/多个 splat 组合成一个 viewport model”的场景，不是单模型训练显存优化；当前正式 Release 仍是 v0.5.3，main 与用户下载版边界很大。

## 5. Viewer / Editor / Web / Mobile / XR

今天 Viewer/XR 的真实进步可以概括为：

```text
以前：桌面 UA → 4M budget → Quest 3 约 10 fps
现在：头显识别 → 1M + foveation + 可选 0.8× → 31–40 fps
再加：双手抓取、退出复位、按距离 LOD
```

这对大型 WebGS 导览的价值高于单纯“支持 WebXR”标签，因为它处理了实际帧率、LOD 可见正确性与交互闭环。但还要注意：

- Quest 测试为 WebGL；WebGPU XR 路径仍取决于浏览器支持；
- Pico 仅 UA 识别，未真机验证；
- streamed scene 才有 1M budget，单文件 scene 仍需手工控 splat 数；
- manipulation 期间会每帧重排，Quest 3 约损失 22% fps。

移动训练方面，昨日 ARKit Scanner 已覆盖 iOS/Metal；今天新增的 LuluSplat Windows 让低端 Vulkan 桌面卡也进入同类“一体化 GUI”比较组。SuperSplat Editor 本身没有新更新。

## 6. Compression / Format / LOD / Streaming

今天没有新的 SPZ/SOG schema、glTF/KHR Gaussian 扩展、OpenUSD、3D Tiles 或 MPEG GSC 标准版本。工程层的三项变化值得记录：

1. **SOG 生成速度**：SplatTransform #340 在 A10G 上把 streamed combine 降低 52%，以双 unit 驻留换吞吐；
2. **LOD 文件粒度**：`--lod-file-count` 让各 LOD 层的 file unit 大小可独立配置，可直接测 HTTP 请求数与首屏/近景切换；
3. **输入正确性**：#341 正确处理 big-endian binary PLY，拒绝 ASCII，避免“转换成功但所有数值都坏了”的静默失败。

LichtFeld 的 q16 banded builder 属于运行时模型合并/显存路径，不是新的交换格式。Gausser 可导出 Gaussian PLY、Point PLY、SPLAT、SPZ，但产品页没有说明其 SPZ/SOG 编解码实现或 LOD/streaming 语义，不能推断与 PlayCanvas streamed SOG 等价。

## 7. Training / Reconstruction / SLAM / Robotics / Mapping

### Spirula #130：GPS 从 gauge 升级为 mapping prior

[PR #130](https://github.com/harry7557558/spirula-studio/pull/130)，merge commit [`37d8dc44`](https://github.com/harry7557558/spirula-studio/commit/37d8dc445940d6091864a6235f4e0025b9e83978) 是今天重建侧最大改动：

- 图片文件夹的 EXIF GPS 与视频遥测一样，生成 GPS-near match pairs，并在全局/联合 BA 给每帧 centre factor；
- `--metric-gps auto` 成为默认：有高度的 drone/EXIF→`full`，无可靠高度→`horizontal`，少于 3 个 fix→`none`；
- `full` 使用 COLMAP `pose_prior_mapper` 同口径：1 m sigma、Cauchy scale 7.815；
- 新注册帧会对 GPS 轨迹做检查：连续漂移触发提前 global BA，前一帧正常而本帧偏离 4× radius 时拒绝错误 PnP；
- levelled ERP 的 -Y up 共识可形成 up prior 与 tilt gate，票数不足/分散过大时 fail closed；
- 修复 exact-zero angle-axis 导数、prior-only 小步无法降低 LM damping、GPS final pass 迭代不足。

作者的一条 1,800 帧林下 equirect 航拍：

| 指标 | COLMAP GPS | master | #130 + follow-up |
|---|---:|---:|---:|
| 单模型注册帧 | 1800 | 1784 + 10-frame 小模型 | 1800 |
| 林下 GPS p90 / max | 4.95 / 7.39 m | 约 8–13 m 偏离 | 1.63 / 2.56 m |
| 开阔区 GPS median | 1.80 m | 1.71 m | 1.72 m |

这里必须保留三个限制：表中包含后续 seam-weld PR 的联合结果；同一困难区运行间仍可能相差约 2 m；Windows/CUDA 未由作者验证。对无人机/360 大场景很值得测，但不能据此宣布普遍优于 COLMAP。

固定库 gsplat、OpenSplat、Graphdeco 原版在本窗口没有新主分支提交。Spirula 新 GPS/level prior 仍在 master，最新正式二进制仍是 [v2026.9.30](https://github.com/harry7557558/spirula-studio/releases/tag/v2026.9.30)。

## 8. Avatar / Human / Generative 3D

本窗口没有新的可运行 Avatar/Human Gaussian release。

生成式方向有两个早期信号：

- [sun-conditioned-3dgs](https://github.com/hsiang0117/sun-conditioned-3dgs) 不是生成式 3D，而是条件外观模型：共享 geometry/opacity，每 Gaussian 16D feature 与共享小 MLP 根据太阳方向的 degree-2 SH 生成 view-SH residual；可把某一太阳方向烘焙成常规 PLY。9 个单测与 1,000-step/256² 验证通过，但尚无 30k/full-res 质量结果，列 P2。
- [giro](https://github.com/kevinraymond/giro) 在本轮出现公开社区发布：单图→MiniMax H3 轨道视频→自动环轨 gate/gap fill→SAM 3.1 mask→COLMAP→Brush 透明训练→visual-hull crop→SPZ/SOG/PLY/WebXR。代码 MIT，但模型各有独立许可；需要 Linux、两张 24 GB NVIDIA GPU、Python 3.12、Node、Rust、FFmpeg、CUDA COLMAP，作者明确称为个人研究原型，现有结论来自少量 subject/seed，因此列 P2 而非“一键产品”。

新建 [NovaSplat](https://github.com/POSE-Lab/novasplat) 的描述是“通过 3DGS onboarding/refinement 做 model-free 6D object pose”，但仓库目前只有一行 README、size 0、无代码/权重/许可证。保留为 P2 watch，不写成已开源实现。
