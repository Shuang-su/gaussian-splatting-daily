### PlayCanvas Engine：WebGPU sort 正确性优先于新功能

- [#9756](https://github.com/playcanvas/engine/pull/9756) 的根因是 portable multipass radix sort 在 `is_valid` 分支内执行 workgroup `atomicAdd/atomicOr`；Adreno 编译器/驱动在 divergent control flow 的尾部 partial workgroup 丢 invocation。修复后每个 invocation 都执行 atomic，无效 lane 加 0，并通过 clamp 读取 key。作者在 Galaxy S24 Ultra、Adreno 750、Chromium WebGPU 上从 v2.23.2 的 histogram/sort 7/60、5/60 错误降为 0/60、0/60；desktop NVIDIA 强制 portable path 为 80/80 正确，约 1.3 ms 未见回归。**建议马上在 Android Chrome 与 Quest 类设备测试**，并记录错误率而非只看平均 GPU time。
- [#9759](https://github.com/playcanvas/engine/pull/9759) / [`6289969`](https://github.com/playcanvas/engine/commit/62899692e933be1b93a41004189715be3206ec14) 修复 sorter 在固定 high-water `capacity` 下由 1M 增长到 4M 时 prefix-sum block buffer 未扩容，以及动态切换 `destructiveKeys` 造成调用者 key buffer 被销毁/内部 buffer 泄漏。Engine 自身 GS sort 始终 destructive 且不设固定 capacity，官方明确说当前 GS 路径不受此 bug 影响；第三方复用 `ComputeRadixSort` 才是直接受益者。
- [#9758](https://github.com/playcanvas/engine/pull/9758) / [`62aafbb`](https://github.com/playcanvas/engine/commit/62aafbb4cefae6d6432686ad745fe092c29d6875) 修复 `GSplatBoxShaderEffect` sweep 后 `edgeTint` 永久残留、tint-only 硬边以及方向符号依赖；过渡面现从 box 前一个 band 开始并在后一个 band 结束。API 语义变化：完整 effect 时长变成 `duration + 2*interval`，camera path 或 preset 若按旧 duration 切换，需要调整。
- [#9757](https://github.com/playcanvas/engine/pull/9757) / [`9dbd6b9`](https://github.com/playcanvas/engine/commit/9dbd6b96c838f77f4f24e882a5e629f0385935e6) 新增 tree-shakeable `AutoExposureEffect`：GPU 统计 64-bin histogram，每帧只回读 256 bytes，WebGL2/WebGPU 同接口；三次小 pass，把半分辨率场景归并到 128×64 后计数。它对室内/室外 GS tour 的曝光适配有用，但必须启用 tone mapping。
- [#9761](https://github.com/playcanvas/engine/pull/9761) 让 CameraFrame effect 使用 application `dt`，自动曝光随 `timeScale` 暂停/慢放，并受 `maxDeltaTime` 约束；[#9760](https://github.com/playcanvas/engine/pull/9760) 新增 `Sky#enabled` 与 per-camera 隐藏，并修复 frustum culling 关闭时 custom visibility 被忽略——后者会错误渲染仅供其他 camera 的 mesh instance，包括 GS renderer 的内部实例。
- 最新稳定版仍为 [v2.23.2](https://github.com/playcanvas/engine/releases/tag/v2.23.2)，窗口内 tag 线到 [`v2.24.0-beta.11`](https://github.com/playcanvas/engine/releases/tag/v2.24.0-beta.11)。移动 WebGPU 若依赖 portable radix sort，建议先 pin beta/commit 做 correctness 灰度；一般生产项目暂不只为自动曝光升级整个 engine。

- [#3520](https://github.com/MrNeRF/LichtFeld-Studio/pull/3520) 修复 exFAT/FAT 等不支持 hard link 的文件系统上项目替换失败：`link()` 失败后改用 rename backup→publish→sync parent；崩溃落在两次 rename 之间时保留旧项目 backup，恢复时 quarantine 而非删除。对外接盘/跨平台便携项目是稳定性修复。
- 评估与输入侧还有 [#3504](https://github.com/MrNeRF/LichtFeld-Studio/pull/3504) 一次渲染同时输出 mask/unmasked/inverted 指标、[#3510](https://github.com/MrNeRF/LichtFeld-Studio/pull/3510) 配对 COLMAP camera subfolders、[#3511](https://github.com/MrNeRF/LichtFeld-Studio/pull/3511) 避免 `--max-width` render 被错误上采样、[#3512](https://github.com/MrNeRF/LichtFeld-Studio/pull/3512) 让 tiled/strip TIFF 都按 stored layout 读取并支持 16-bit/float tiled TIFF。

## 5. Viewer / Editor / Web / Mobile / XR

- PlayCanvas #9756 是今天 Web/mobile 最重要的 GS 相关变化：任何 portable radix sort 错误都可能表现成偶发 splat 丢失、索引重复或画面抖动，而且平均帧时看不出来。测试需加入 sorted-key 单调性、index permutation 完整性和长时间重复运行。
- #9758 直接影响 Room Reveal 等 GS shader effect 的最终状态与 camera animation 定时；升级后 effect 总时长改变，自动切镜/导出视频应同步调整等待时间。
- AutoExposureEffect 可改善室内外/隧道类 splat tour，但 histogram 对象是屏幕亮度，不解决捕获时跨帧曝光不一致；应在 tone mapper、TAA/SMAA、透明背景和 camera cut `reset()` 组合下验证。
- LichtFeld 8.9M selection 修复对大型编辑器和通过 MCP/Python 自动筛选同样关键；Spirula source preview 使 360 orientation、mask、scan/camera、传感器时间线在训练前即可检查。
- 本窗口未发现新的 WebXR、Unity、Unreal、Godot、Babylon.js 或 Three.js 官方 GS release；不要把新建的 SDL3/D3D12 教学 viewer 解读为跨平台引擎支持。

## 6. Compression / Format / LOD / Streaming

<!-- arxiv:2610.17605 -->
- **PLEDGE**（[arXiv:2610.17605](https://arxiv.org/abs/2610.17605)）的核心新意不是“更小”，而是把 screen-space position、rotation/scale footprint、view-dependent color、opacity 四类容差变成在指定 camera domain 内成立的 primitive-level bound；progressive bitstream 每个 prefix 都有明确误差界。它很适合受控 LOD/streaming 和验收型工作流，但**无代码、无现成 SOG/SPZ/glTF 映射、无 GPU decoder**，当前为论文信号。
- TETRIS-4DGS 复用传统 image/video codec 的方向有部署吸引力，但“40×”只在作者论文口径下成立；尚不能回答 splat 数、序列长度、codec profile、decode latency、随机 seek、PSNR/SSIM/LPIPS 与 motion consistency 的完整对照。
- 今天没有 SOG、SPZ、compressed PLY、glTF Gaussian extension、OpenUSD、3D Tiles、MPEG GSC、Khronos/W3C WebGPU 的新正式修订。PlayCanvas 变化是 sorting runtime 正确性，不是文件格式升级。

## 7. Training / Reconstruction / SLAM / Robotics / Mapping

<!-- arxiv:2610.14963 -->
- **AD-GS**（[arXiv:2610.14963](https://arxiv.org/abs/2610.14963)，[仓库](https://github.com/yulinjiaxue/AD-GS-BMVC2026)）：attenuation-aware MCMC birth/death densification 把 primitives 集中到 enamel/cortical bone 等高衰减结构，20k iterations 后启用 352-d MedSAM2 feature cosine regularization。仓库含环境、训练/评估、R²-Gaussian Beer–Lambert rasterizer 和 MedSAM2/SAM2.1 下载脚本；需 ToothFairy3/R²-Gaussian layout、两套 CUDA extension、约 190MB segmentation weights。作者在 RTX 4090 报告每 case 约 27 分钟，对照 SAX-NeRF >7 小时；这是特定 medical dataset 的作者结果。

<!-- arxiv:2610.16292 -->
- **SG-GS**（[arXiv:2610.16292](https://arxiv.org/abs/2610.16292)）：用 SAM region type 动态调整 densification threshold、在边界额外增密，并把 feature-gradient/edge/high-frequency loss 分阶段引入。作者报告相对原始 3DGS 的 PSNR 提升约 2.7–5.2%，但**未找到代码/权重**，不能核验训练成本或跨数据集泛化。

<!-- arxiv:2610.15522 -->
- **GNFormer**（[arXiv:2610.15522](https://arxiv.org/abs/2610.15522)，[代码占位仓库](https://github.com/GCChen97/gnformer_occ)）：以 256（室内）/1024（室外）Gaussians 定义 neural-field spatial support，再由网络解码 occupancy；作者称在 Occ-ScanNet、SSCBench-KITTI-360、nuScenes-SurroundOcc 的单帧方法中兼顾最好 IoU/mIoU 与最快推理。仓库当前为空，评级**论文/代码未发布**。

## 13. 今天最值得实际测试/部署的项目

1. **PlayCanvas Engine portable radix sort（#9756）**：用 Galaxy S24 Ultra/同代 Adreno 或 Quest 的 Chromium WebGPU，固定 180k、200k、非 workgroup 整倍数与更大 splat index buffers，重复至少 1,000 次；检查 key 单调性、index 唯一性/范围和最终画面，再比较 v2.23.2 与 `f4be5ce` GPU time。门槛是可替换 Engine beta/build；预期收益是消除“偶发花屏/丢 splat”而非平均 FPS 提升。
2. **LichtFeld master correctness suite**：准备 3M/9M splat 场景、斜平面、nested groups、多视频、exFAT 外接盘；覆盖 Align 三点、brush/lasso、group export、batch extraction、Save As/crash recovery。门槛是源码构建、Windows NVIDIA Vulkan/CUDA；预期收益是把大场景编辑与便携盘保存从静默错误改成可验证结果。
3. **Spirula source preview + clip**：用双轨 360 HEVC + GPS/IMU 与一组 E57/LAS/PLY，先在 GUI 预览 orientation、传感器时间线和 scan cameras，再裁剪同一段分别走内置 decoder/ffmpeg/CLI，核对 frame names、time_offset、COLMAP/训练输入。预期收益是训练前发现时间/姿态/源素材问题，减少重跑。
