### SplatTransform 3.10.0

[v3.10.0](https://github.com/playcanvas/splat-transform/releases/tag/v3.10.0) 的唯一条目是 [PR #349](https://github.com/playcanvas/splat-transform/pull/349)：`webgpu` npm package 从 0.4.0 升到 0.6.2，`@webgpu/types` 从 `^0.1.69` 到 `^0.1.72`，并取消 Renovate 对 `webgpu` 的精确 pin。代码 diff 没有新增 SOG/SPZ/PLY、LOD、streaming、chunking、GPU sorting、viewer export 或 stochastic rendering 算法。**升级建议：**依赖 WebGPU Node/tooling 的构建可做兼容性回归；仅做格式转换、且 3.9.2 已稳定时无需因为版本号立即升级。

### PlayCanvas Engine：未合并的 GPU-sort 修正

[#9677](https://github.com/playcanvas/engine/pull/9677) 指出 GPU-sort compute projector 用 `sqrt(2a)` / `sqrt(2c)` 近似屏幕足迹，默认 `minPixelSize=2` 时可能比 quad renderer 至少早一倍裁掉 splat，细长且中心在屏外的 splat也会在边缘 pop。修订先用 covariance 最大特征值统一 footprint，再以 `(t-a)(t-c)>b²` 做无平方根阈值测试；作者用 200 万随机 covariance 验证 predicate 与显式 eigenvalue 判定一致。该 PR 尚未合并，Editor/Viewer/SplatTransform 当前发布物都不能假定已经受益。

SuperSplat Editor 最新仍为 10 月 5 日的 3.5.2，SuperSplat Viewer 最新仍为 1.37.0；本窗口没有新的 commit、merged PR 或 release。没有新的 SOG/SPZ/GLB/glTF、selection/picking、camera/path、shared viewer settings、WebXR 或发布 API 变化。官方博客/文档/论坛也没有检索到新公告；需要登录/加入服务器的 Discord 本轮未直接读取，也未采用转述。

## 3. 可实际运行的开源项目

### SplatCraft：端到端但仍是首发状态

[SplatCraft](https://github.com/AshishIsaac/SplatCraft) 用 pycolmap 取 pose，自定义 PyTorch autograd + Triton kernel 训练，压缩层组合 pruning、SH k-means VQ、标量量化、Morton/delta 与 interleaved rANS，前端则手写 WebGPU radix sort、tile alpha renderer，并由 FastAPI 提供资产。作者给出的 lego 是 44.1 MB/33.95 dB → 2.94 MB/33.34 dB，bonsai 是 88.3 MB/29.76 dB → 5.57 MB/29.00 dB；这些数字没有独立复现，也未完整列出同类 codec 对照。仓库为 MIT，并明确称未复制 Inria 原实现，但仍需检查 pycolmap/COLMAP、Triton 等依赖许可与显卡路径。

### MaRO-GS：目标物体优先重建，已有 Docker

[MaRO-GS](https://github.com/kgh1234/MaRO-GS) 随 [arXiv:2610.06472](https://arxiv.org/abs/2610.06472) 提供训练代码和 `mobuk/marogs` Docker：直接优化 target object，用多视角可靠性过滤、剪枝/增密与 silhouette loss 抑制背景资源浪费。可跑级别为“研究原型”；LERF mask 尚标注 coming soon，仓库未见 LICENSE，数据与权利边界不完整。适合小物体重建指标复现，不适合直接并入商业流水线。

固定仓库方面，`nerfstudio-project/gsplat`、`WebODM/OpenSplat`、`graphdeco-inria/gaussian-splatting` 本窗口没有新的 release 或关键 commit；不要把 repo 的旧活跃度当作今日新增。

## 4. 4D / Dynamic Gaussian

## 7. Training / Reconstruction / SLAM / Robotics / Mapping

[LichtFeld #2961](https://github.com/MrNeRF/LichtFeld-Studio/pull/2961) 除评估位深外，还修正 GUT thin-prism fisheye 到 COLMAP 模型的投影、resume 后 mask reload 初始点、以及 eval-space resume 行为；masked evaluation 会输出 reference/render 的正反 mask 三行网格。对 benchmark 的价值高于“多一个指标”：它减少 JPEG cache、位深和 mask 处理造成的不可见口径漂移。

[LichtFeld Tensor::cat PR #2964](https://github.com/MrNeRF/LichtFeld-Studio/pull/2964) 仍开放：CUDA 实现此前对所有 dtype 都按 4-byte word 复制，Float16/UInt8/Bool/Int64 会被破坏甚至越界；PR 按 1/2/4/8 byte dispatch，86 个 cat tests 通过。问题由 DINOv2 class token 触发，对 semantic/feature pipeline 很重要，但在合并前避免把非 float32 cat 放入正式流程。

[FOCUS](https://arxiv.org/abs/2610.05639) <!-- arxiv:2610.05639 --> 用 3D Gaussian map 的概率几何与渲染外观证据做 persisted/replaced/removed 三态开放词表变化检测。**编辑摘要：**作者报告 replacement F1 从 0.20 提到 0.84，方向适合长期机器人地图维护；当前没有可核代码，且跨时间光照/遮挡下的 calibration replay 成本仍需实测。

[Differentiable Lagrangian-Coupled 3D Gaussian Splatting and SPH](https://arxiv.org/abs/2610.04336) <!-- arxiv:2610.04336 --> 将 3DGS 视觉表示与 SPH 固体力学耦合并保持可微。**编辑摘要：**它把 Gaussian 从被动地图推进到可优化的物理载体，适合 inverse mechanics/robotics 仿真跟踪；目前只有论文证据，没有可运行 solver 或 benchmark harness。

## 13. 今天最值得实际测试/部署的项目

1. **Spirula v2026.10.6 + 多 NVIDIA workaround（优先级最高）。** 门槛最低：Windows/Linux/macOS 有 binary；多卡 crash 修复需拉 `master` 源码构建，因为 commit 晚于 tag。Windows 多 NVIDIA 用户可记录驱动、WDDM/TCC、显示卡/计算卡组合，并用 `GUI_VK_PRIME=0` 做 A/B。预期收益是消除 OpenGL 后首个 `vkCreateDevice` 触发的 `nvoglv64.dll` crash；不是通用训练提速。
2. **LichtFeld 新评估路径。** 用已有 checkpoint 分别跑 `--eval-bit-depth auto/8/16/float` 与 `--eval-flip`，固定图片、mask、resolution，再比较 PSNR/SSIM/LPIPS/FLIP；MCMC/IGS+ 同时记录 1M splats 的 ms/iter 与 peak VRAM。门槛是 CUDA/Vulkan 源码构建，预期收益是得到可解释、可复核的评估口径，并回收误开曝光校正的约一成训练开销。
3. **Mobile-4DGS 沙箱部署。** 推荐 Python 3.11/CUDA 12.6 环境，准备 TMC13/GPCC 与 RAPIDS cuML；先用作者小样跑压缩与 WebGL viewer，再测固定相机下动态子集更新。预期收益是验证移动 4D 的存储/排序预算；停止条件是 LICENSE 未澄清、README clone/arXiv 元数据不一致，暂不接入商业资产流水线。

SplatCraft 排在第四：它覆盖面大但新到只有首个公开 commit。若测试，应先复现 lego/bonsai 的尺寸、PSNR、训练时间与 RTX 3050/Iris Xe fps，再讨论替换现有训练器或格式。
