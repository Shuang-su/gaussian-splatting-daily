## 2. SuperSplat / PlayCanvas 工具链

### SuperSplat Viewer：移动随机渲染、直接 source 与 XR 一次合并

[PR #330](https://github.com/playcanvas/supersplat-viewer/pull/330) 在 2026-10-19 18:26（北京时间）合并。它不是小补丁，而是 Viewer 渲染数据通路和 XR 交互的成组改造：

- `?stochastic=mobile` 增加 mobile tiler 路径；作者 Pixel 7 Pro、1M splat 测试中，启动/高 overdraw 分别为 8.4/11.7 ms，对比 per-pixel stochastic 17.0/22.6 ms、sorted 17.7/40.7 ms。
- 直接 source 成为默认：resident 文件直接供渲染器读取，SOG v2 重排为一个 geometry texel + 一个 color texel；SH palette 用 11/11/10 位解码。Engine 临时 workbuffer 可缩到 1×1，source texture 用后释放。作者 Mac、1M house 数据口径为 219 → 128 MB。
- WebGPU XR 为每眼创建独立 SplatView；Vision Pro 的 foveated rate-map 有专门修正，作者称相同成本下中心水平/垂直分别清晰约 2.3×/1.9×。
- 双眼默认共享 projection；Vision Pro 1M 场景作者测得 63 → 69–72 fps，XR TAA 7.4 → 3.2 ms。frames-in-flight gate 将作者测得的 pose latency 从 Vision Pro 134 → 34 ms、Pixel WebGPU 119 → 47 ms。
- 加入 VR teleport/collision、双手抓取、head menu、world-in-miniature 与 `?vr` 入口。
- 依赖 PlayCanvas `^2.23.0`；传统 sorted 路径仍为默认，未带 flag 的现有应用不被切换。

限制必须保留：功能仅 WebGPU；Quest 3 作者测试约 34 fps/1M，未达 72 Hz；质量/预算尚不自适应；Quest 在约 4.19M splat 以上遇到 storage-binding 边界，stochastic 在约 4.47M 后下降；Quest 上画面仍比 sorted 软。Viewer 最新正式 release 仍是 [v1.37.0](https://github.com/playcanvas/supersplat-viewer/releases/tag/v1.37.0)，因此建议 pin SHA 做副线测试，不直接推生产。证据 B。

### OOOSplat 0.7.0

[release 0.7.0](https://github.com/ooolabdev/ooosplat/releases/tag/0.7.0) 与 [合并 commit f516f036](https://github.com/ooolabdev/ooosplat/commit/f516f0368d683b7f8199172ba9090a98447aa5b9) 把全景视频、全景图片和既有多格式导出合入 main；维护者报告 453 个前端测试、6 个 diagnostics、398 个 Rust 测试通过。

- 输入：普通/2:1 ERP 全景 MP4、MOV、JPG/JPEG/PNG；图片超过 100 张可选择顺序匹配。
- 重建/训练：Tauri + Rust，内置 FFmpeg/FFprobe、COLMAP、Brush；素材和模型默认完全本地。
- 导入：标准/压缩 PLY、SOG、SPZ、SPLAT、KSPLAT。
- 导出：标准 PLY、compressed PLY、SPZ v4、单文件 SOG、离线 HTML 与 MP4。
- 平台：Windows 11 最成熟；Apple Silicon macOS 15+ 与 Ubuntu 24.04 x86_64 为 Alpha。Windows 的 COLMAP CUDA 需要驱动 580+、Compute Capability 7.5+；否则回退 CPU。Brush 使用可用图形后端。
- 风险：全景暂不支持补拍；compressed PLY/SPZ/SOG 编码仍可能出现整模型内存峰值；macOS 包未签名/未公证；Ubuntu CPU-only 未端到端验证。

它是今天最接近“下载后直接跑”的完整开源工作流，Apache-2.0；值得用副本数据立即验证，但 Alpha 平台暂不建议当无人值守生产节点。证据 A/B。

## 5. Viewer / Editor / Web / Mobile / XR

Viewer 侧的主更新就是 SuperSplat Viewer #330；它对 WebGS 的含义分三层：

1. **移动端**：tiler stochastic 显著降低作者测试中的 overdraw 成本，但仍需按芯片、热降频、splat 数和分辨率做实机矩阵；不能把 Pixel 7 Pro 数字外推到 Adreno/Mali 全部设备。
2. **XR**：双眼 view、foveated rate-map 与帧门控同时降低画质和延迟风险；但 Quest 3 尚未达到目标刷新率，适合技术预览而非默认开启。
3. **内存**：直接 SOG source 减少中间 texture/workbuffer，对浏览器显存敏感场景价值很高；要回归 SOG v2、SH palette、多个场景切换后的资源释放。

[Gausify Orbit #17](https://github.com/obraia/gausify-orbit/pull/17) 则补上浏览器端第二套相机估计器：默认仍是 AKAZE incremental SfM；可选 COLMAP 使用 COLMAP 4.2.1 SIFT、几何验证、view-graph calibration、global mapper WASM 和 `colmap-wasm 0.1.0` 的 WebGPU exact matching。两套设置分别保存在 localStorage，headless 可用 `--estimator`；维护者称耗时相近但 COLMAP 更占内存、在 AI-generated orbit 上更稳定。MIT，无 CUDA、无需安装；门槛是桌面 Chrome/Edge WebGPU。证据 B。

## 7. Training / Reconstruction / SLAM / Robotics / Mapping

### LichtFeld POPSpa

[PR #2043](https://github.com/MrNeRF/LichtFeld-Studio/pull/2043) 是今天训练侧最值得测的改动：

- POPSpa 为 opt-in，旧 Opacity ADMM 默认保持不变；贡献评分、intermediate exact pruning、sparse optimization、final exact pruning、photometric recovery 都在原生 C++/CUDA 内完成，不新增 Python gsplat 依赖。
- GUI、CLI、JSON、Python 均可设置；示例为 `--enable-sparsity --sparsity-method popspa --popspa-target-count 256000`。
- checkpoint 升到 v4；v1–v3 可读，但新写 v4 需要新版应用。旧 ADMM 状态会丢弃；处于 ADMM tail 的旧 checkpoint 可恢复但不继续稀疏化。
- 冻结 Gaussian 被保留，目标预算在拓扑变化前校验；独立 FastGS Adam batch table 增加 fence，修复异步 upload/kernel race。
- 作者 Windows RTX 5090 短测把 Garden 2.56M 压到 512k，并通过 focused tests；这只是响应性/契约验证，不是画质或压缩率 benchmark。

适合先做 2M→512k、1M→256k 两档，与原模型比较 PSNR/SSIM/LPIPS、PLY/SPZ 大小、Viewer memory 和移动端帧时间。证据 B。

### KFS⁴LAM

[论文](https://arxiv.org/abs/2610.22505)、[代码](https://github.com/XinweiJu/KFSLAM) 与 [reconstructions-v1](https://github.com/XinweiJu/KFSLAM/releases/tag/reconstructions-v1) 同时可用。仓库提供 SplaTAM、EndoGSLAM 两条 backbone、adaptive keyframe、fold-boundary supervision、restricted temporal deformation、`run.py` 与 `render_checkpoint.py`；release 含 25 个 C3VD/C3VD-v2 序列的 Gaussian 参数、形变系数、姿态、内参、keyframe 和配置。

作者报告相对 SplaTAM 在 C3VD-v2 上 rotational RPE -20.3%、depth RMSE -38.4%、PSNR +0.78 dB。新运行需要 RGB-D 与 fold response，属于医疗内窥镜研究原型，不是通用 SLAM drop-in。仓库未见顶层 LICENSE，第三方许可有单独声明；在许可证明确前只用于评估。证据 A/B。

## 10. 研究论文

### Direct Conditional Parameterization for N-Dimensional Splatting

[arXiv:2610.22778](https://arxiv.org/abs/2610.22778)，NeurIPS 2026。方法用直接条件参数化替代 N-DGS/UBS 渲染切片时逐 primitive 的逆矩阵与回归；作者在四个训练场景报告 production slicing 6.9–7.7×、整体渲染 1.25–1.91×，主 MCMC 评估最高 +1.26 dB。项目有演示但未发现代码。P2+，论文无代码；任何加速结论都要在同 GPU、分辨率、Gaussian 数与质量指标下复测。

<!-- arxiv:2610.22778 -->

### X-Splat: Unified Gaussian Splatting for Joint RGB and X-ray 3D Reconstruction

[arXiv:2610.23237](https://arxiv.org/abs/2610.23237)，SIGGRAPH Asia 2026；[代码](https://github.com/zezeaaa/X-Splat) 已开放。单一 Gaussian 集合共享几何，只有表面附近承载 RGB 外观，同时承载 X-ray density。流程是 3,000 iter X-ray 预训练、PCA+ICP 对齐、12,000 iter 联合训练；输出 `gaussians_rgb.ply` 与 X-ray pickle。

门槛较高：Linux、NVIDIA RTX 6000 Ada/A6000 48 GB 为作者环境，训练/评估约 20 GB VRAM，MVS 预处理最高约 40 GB；CUDA 11.8、gcc≤11、Python 3.10、Torch 2.1.2、COLMAP 3.8–3.12、TIGRE 2.3，部分数据还需 Blender 3.6.5/MVSFormer。约两小时/scene/单 GPU。许可为 Gaussian-Splatting License，仅研究评估、非商业。P1 研究原型，代码+部分场景/权重可跑。证据 A/B。

<!-- arxiv:2610.23237 -->

### Frame-Consistent Feed-Forward 3DGS from Sparse Unposed Images

[arXiv:2610.23039](https://arxiv.org/abs/2610.23039) 分析冻结 VGGT+TokenGS 的退化主要来自坐标 frame 与 translation scale 不一致，并用确定性修正把四 context 输入做到 22.47 dB，与 COLMAP reference 相差 0.51 dB；作者称四 context 已接近 all-view quality。未发现代码/权重。P2，论文无代码。

## 13. 今天最值得实际测试/部署的项目

### 1) SuperSplat Viewer #330 + PlayCanvas Engine beta.16

- **为什么**：同一周内解决高阶 SH 正确性、SOG resident memory、移动 overdraw、XR 双眼/注视点与交互，可能直接改变 Web/XR viewer 的性能上限。
- **门槛**：Viewer pin `5976646d`、Engine `2.24.0-beta.16`；Chrome/Edge WebGPU；移动与头显真机。现有 production 保留 sorted 路径作 A/B。
- **测试矩阵**：1M/4M SOG v2 与 PLY SH3/SH4；首次加载、峰值/稳定显存、相机移动、TAA、中心/边缘清晰度、pose latency、热降频；Quest 重点验证 4.19M/4.47M 附近边界。
- **预期收益**：移动端高 overdraw 与 XR latency 明显下降、resident memory 更低；风险是画面更软、尚未正式发版、不同 GPU 限制明显。

### 2) LichtFeld POPSpa

- **为什么**：它把训练后的 splat 数预算控制直接放进成熟 GUI/CLI，而不是额外 Python 脚本；可把“模型太大”转成可重复的后处理阶段。
- **门槛**：master/untagged build、CUDA/Vulkan；旧 checkpoint 可读，新 v4 不能回到旧版；先用资产副本。
- **测试矩阵**：2.56M→512k、1M→256k；MCMC/MRNF 各测；质量、训练/后处理时长、显存、导出大小和 SuperSplat/Spirula viewer frame time。
- **预期收益**：更小交付资产与更低 viewer 成本；风险是薄结构/高光被裁、作者短测不是质量 benchmark。

### 3) OOOSplat 0.7.0

- **为什么**：今天唯一正式 release 的端到端开源桌面入口；全景输入、COLMAP、Brush、编辑和四格式交付在一个 GUI 内闭环。
- **门槛**：Windows 11 最低；macOS/Ubuntu 属 Alpha。准备普通视频、2:1 ERP 视频/图片和一个外部 SPZ/SOG。
- **测试矩阵**：普通/全景重建注册率；PLY→compressed PLY/SPZ/SOG 往返的 splat 数、SH、坐标和颜色；大资产编码峰值；离线 HTML 与 SuperSplat/GSL 互操作。
- **预期收益**：显著降低非研究用户从素材到 Web 交付的装配成本；风险是全景补拍缺失、Alpha 平台与整模型压缩峰值。
