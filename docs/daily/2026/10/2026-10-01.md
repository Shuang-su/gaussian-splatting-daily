## 2. SuperSplat / PlayCanvas 工具链

### #9610：动态 GS 换帧的正确性修复

[PR #9610](https://github.com/playcanvas/engine/pull/9610)（merge commit [`8e3e990c356b`](https://github.com/playcanvas/engine/commit/8e3e990c356b6b44f16513d7b852957e14476e07)）修的是 streaming 与 render reconcile 的时序：

```text
GSplatComponent.asset 被替换
→ 旧 placement 销毁、新 placement 建立
→ framerender 的 streaming tick 先于 render path
→ world state 仍按上一帧 placement 构建
→ 本帧没有 splat / 旧 2.22.x 甚至抛错后永久停渲染
```

新实现让 `GSplatDirector#updateStreaming` 在 manager streaming 前检查 `gsplatPlacementsDirty` 并 reconcile 当前 placement。公开 API 不变；只有 placement 改动帧会多一次轻量 reconcile，render path 的第二次遍历发现无变化。

作者的固定间隔 Chrome 152 测试：

| 场景 | 修复前空白/失败帧 | 修复后 |
|---|---:|---:|
| 30 fps Flipbook / 60 Hz / WebGPU | 16 / 40 | 0 / 40 |
| 30 fps Flipbook / 60 Hz / WebGL2 | 19 / 40 | 0 / 40 |
| 每帧换 asset / WebGPU | 29 / 30 | 0 / 30 |
| 每帧换 asset / WebGL2 | 29 / 30 | 1–2 / 30（首次 CPU sort） |

这对 4DGS 不是完整动态形变支持，但对“多份静态/时间片 splat 轮换”的实现非常关键。当前只在 Engine main；Viewer/SuperSplat/SplatTransform 本窗口没有新 commit 或新 Release，升级前仍应核对应用实际锁定的 Engine 版本。

### XR 修复组

- [#9623](https://github.com/playcanvas/engine/pull/9623)：销毁 `XrManager`/`XrView` 与结束 session 时移除监听器，避免多次进入 XR 后对象和回调累积。
- [#9624](https://github.com/playcanvas/engine/pull/9624)：运行中的 `nearClip/farClip` 会传给 session；Quest 3 测试从仍为 0.1–10000 修到设置的 0.5–5。
- [#9625](https://github.com/playcanvas/engine/pull/9625)：输入源 origin/direction 不再覆盖 position/rotation 返回向量，射线使用完整 rig transform，linear velocity 回到文档声明的 world space。
- [#9626](https://github.com/playcanvas/engine/pull/9626)：进入 XR 时按 camera forward 计算完整 360° heading；180° 相机不再被折回 0°。
- [#9627](https://github.com/playcanvas/engine/pull/9627)：被移除的 plane/mesh 仍保留最后数据供 remove handler 读取；hit test 跳过无 pose 结果并按浏览器给出的沿射线顺序取最近有效命中。

这些是 GS XR 应用的宿主引擎修复，不应写成 Gaussian rasterizer 获得了新能力。

## 3. 可实际运行的开源项目

### ARKit 3DGS Scanner：从采集到 SOG 都在设备内

项目：[KuoFengYuan/arkit-3dgs-scanner](https://github.com/KuoFengYuan/arkit-3dgs-scanner)

- **用途**：ARKit 照片/pose/可选 LiDAR capture → refinement → Swift/Metal 3DGS training → `gaussians.sog`；也可导出 COLMAP ZIP 给桌面 trainer。
- **门槛**：Xcode 26+；iOS/iPadOS 17+；本机训练需 A14+；LiDAR 可选。
- **档位**：4k/300k、10k/600k、20k/1M iterations/Gaussian cap；默认 960 px，可选 1440/1920。
- **互操作**：README 声明 SOG 可由 SuperSplat、PlayCanvas、LichtFeld Studio 打开。
- **许可**：2026-09-30 从此前状态改为 **PolyForm Noncommercial 1.0.0**，不适合直接纳入商业闭源产品。

[#58](https://github.com/KuoFengYuan/arkit-3dgs-scanner/pull/58) 没改 loss、PPISP、pose refinement、densification schedule、精度或 cap，主要改 GPU/CPU 执行：

- backward blend 每线程重放 4 个垂直像素，M1 Pro 18.1→10.9 ms；
- projection backward 只写被 view 触达的行，每步省约 100 MB zero gradients，3.17→0.78 ms；
- 六组 Adam 合并一次 dispatch，5.72→5.02 ms；
- 每步等待 6→3 次；
- CPU refine 去掉逐行分配并并行算 Gumbel keys。

作者 F21171（715 train / 143 held-out）报告：

| 设备 | 10k iteration 总时长 | GPU step | 质量变化 |
|---|---:|---:|---|
| M1 Pro | 374.2/386.7→261.7/277.6 s | 36.6→26.4 ms | aligned PSNR 均值约 23.861→23.859 dB |
| iPhone 17 Pro，serious thermal | 769.4→553.1 s | 80.7→58.9 ms | 23.946→23.907 dB |

手机每版只有一组同热状态运行，不能泛化到其他 iPhone、20k/full-res 或正常 UI preview；但这已比只报理论 kernel speed 更有工程参考价值。

### Spirula main：采集输入更友好

[外部 PLY seed cloud #126](https://github.com/harry7557558/spirula-studio/pull/126) 增加 `--seed-pointcloud` 与 GUI picker。它读取普通 XYZ+RGB ASCII/binary PLY，在 centering 和坐标变换之前替换 dataset seed points；支持 COLMAP 与 Nerfstudio，并对空点云、NaN/Inf、缺 RGB、相对/绝对路径做回归测试。它与 `init_ply` 的“从既有 Gaussian warm start”不同：这里是**初始几何点**，不带训练好的 Gaussian 参数。

[HEIC 支持 commit](https://github.com/harry7557558/spirula-studio/commit/c8aaa2e38215383a55ac49aea47ce07f985b1e1f) 对 iPhone 静态照片集尤其有用；本轮未见包含这些晚间提交的新 tag，因此均按 main 可测，不写成 v2026.9.30 已带。

## 7. Training / Reconstruction / SLAM / Robotics / Mapping

今天最值得映射/重建用户关注的是 **Spirula 的 LiDAR/PLY seed 注入**。推荐的实际链路是：

```text
COLMAP / Nerfstudio 相机与图像
+ 已配准 LiDAR XYZ+RGB PLY
→ --seed-pointcloud
→ 共用 centering / coordinate transform
→ Gaussian training
```

这避免把 LiDAR 数据伪装成 COLMAP `points3D.bin`，也允许 poses-only COLMAP reconstruction 使用外部 cloud。限制是必须先完成同一坐标系配准；此功能不会自动做 LiDAR-camera registration。

ARKit Scanner 则把 ARKit pose、可选 LiDAR depth seed/loss、per-image exposure/color correction 放进设备端链路。它适合比较“Apple 设备快速现场闭环”与“导出 COLMAP 后在 5090/专业训练器重训”的质量/耗时差异，而不是替代所有桌面 SfM。

固定库 gsplat、OpenSplat、Graphdeco 原版在窗口内没有新主分支提交；LichtFeld 新提交均已进入昨日 9 月 30 日正文，不重复计数。

## 13. 今天最值得实际测试 / 部署的 3 项

### ① iPhone 端训练：做真实热稳态 A/B

在同一段现场扫描上固定 10k、960 px、PPISP、600k cap，比较旧/新 commit：

- total time、GPU step；
- thermal state、峰值内存、电量；
- held-out PSNR/SSIM、empty pixel share；
- `gaussians.sog` 在 SuperSplat/PlayCanvas/LichtFeld 的打开与方向/颜色一致性。

预期收益是训练时长约 20–39%，但需在你的目标 iPhone、正常 UI preview 和自采数据上验证。商业项目先解决非商业许可证。

### ② PlayCanvas：Flipbook + XR 生命周期联合回归

用 2–4 个时间片 asset 以 30 fps 轮换，同时在 Quest/移动浏览器重复进入退出 XR：

- 每帧 drawable splat count、黑帧数；
- WebGPU/WebGL2 首次 sort；
- near/far 动态改变；
- 180° 初始 camera heading；
- plane/mesh remove handler 与 hit-test 多结果；
- 退出后的 listener/object 数。

预期收益是消除序列换帧闪烁和多次 XR session 累积故障；门槛是需要 Engine main，自行确认 npm/tag 含提交。

### ③ Spirula：COLMAP poses + LiDAR seed 对照

同一数据做三组：

```text
A. 原 COLMAP points3D
B. 已配准 LiDAR XYZ+RGB PLY
C. random / warm-start（作为不同机制参照）
```

记录初始 scale/center、收敛速度、floaters、几何边界、最终 Gaussian 数与 VRAM。再把 iPhone HEIC 原图直接输入，检查 EXIF orientation、色彩与特征数。预期是更稳的初始几何和更少数据预处理；前提是 LiDAR 与相机坐标已经可靠配准。

### 今日结论

今天的变化不在“又一个 viewer”，而在**把移动采集、训练初始化、动态播放和 XR 运行时的断点补齐**：

```text
iPhone capture / Metal training
        ↓
COLMAP / Nerfstudio poses + 外部 LiDAR seed
        ↓
SOG / USD 等交付格式
        ↓
Web flipbook / XR navigation 的稳定运行
```

短期最值得立即验证的是 PlayCanvas #9610 和 Spirula #126；前者影响动态 GS 展示的可见正确性，后者能把专业采集/测量点云更干净地接入跨厂商 trainer。ARKit Scanner 的速度数据很亮眼，但许可证与设备/数据集外推边界必须同时写在评估结论里。
