### LichtFeld Studio：新增能力与生产修复同时落地

- [mesh init #3596](https://github.com/MrNeRF/LichtFeld-Studio/pull/3596)：`--init` 直接吃常见 mesh 格式，`--init-mesh-resolution` 默认 1024、范围 16–2048，并自动受 `--max-cap` 约束；mesh 需先对齐 dataset coordinate。作者 outdoor mesh 8.2M triangles 在 2.9 秒生成 269k splats；2k init 的 LPIPS/SSIM 优于 sparse、PSNR 略低，30k 后接近持平。单场景数据仅用于定向测试。
- [GPU undistort #3610](https://github.com/MrNeRF/LichtFeld-Studio/pull/3610)：旧 CPU crop 会接受 folded 或未收敛 inverse root，极端 action-camera fisheye 可把 5388×3360 裁成 1595×887。新实现共享 branch-aware inverse、遵循 turning point/horizon 和 COLMAP scale rules；作者报告 camera prep 222→35 ms、3840×2880 fisheye inverse 149→88 ms。硬件未在 PR 摘要中统一列出，倍率不可外推。
- [export #3588](https://github.com/MrNeRF/LichtFeld-Studio/pull/3588)：撤销 Linux/vcpkg libarchive 不接受 `hdrcharset=UTF-8` 的回归，POSIX 使用原生 UTF-8 bytes，Windows 保留 UTF-8 处理；恢复 SOG、SSOG、NuRec USDZ 导出，作者 192 项归档/导出/gallery/provenance 测试通过。
- [Linux Vulkan interop #3571](https://github.com/MrNeRF/LichtFeld-Studio/pull/3571) 为单 full chunk 绕过 sparse bind，并补 buffer device address；[#3577](https://github.com/MrNeRF/LichtFeld-Studio/pull/3577) 删除会在 scratch 增长后造成大量 failed live frames 的环境 fallback。作者在 RTX 4060 Laptop、driver 570.133.20、CUDA 12.8、Vulkan 1.4.303 和 1M PLY 上验证。
- [Windows long paths #3572](https://github.com/MrNeRF/LichtFeld-Studio/pull/3572) 覆盖图片、PLY/SOG/SPZ/SSOG、COLMAP、mask、checkpoint、metrics 的本地/网络长路径；video import/export、log file、Python script loading 仍不在覆盖范围。
- [histogram #3543](https://github.com/MrNeRF/LichtFeld-Studio/pull/3543) 将 641k GS、48×48 grid 的 selection handler 中位时间从 27.70 降至 1.64 ms（作者单机 cProfile，约 16.9×）；修复 partial cell selection count。稳定 release 仍是 [v0.5.4](https://github.com/MrNeRF/LichtFeld-Studio/releases/tag/v0.5.4)，以上均是 master，生产升级前需自建包回归。

## 5. Viewer / Editor / Web / Mobile / XR

- Gaussian-Splat-Lite 的 RAD streaming 现在把 cache budget 与 splat display budget 分开：默认 `maxResidentCpuBytes=2 GiB`、`maxResidentGpuBytes=1 GiB`；统计新增 `residentCpuBytes`、`residentGpuBytes`、`loadProgress`。预算不含 pending copies、WASM memory、renderer buffers，所以不能把数值当浏览器总显存。到顶时会提前释放 unused detail、必要时先显示较低细节。
- 后续 [`e71bfb4a`](https://github.com/WilliamLiu-1997/Gaussian-Splat-Lite/commit/e71bfb4aa251) 删除 RAD LoD hysteresis，使 refine/coarsen 使用同一阈值并简化 bitsets；可降低状态和选择工作，但相机在阈值附近可能更频繁切换，需用固定路径检查 pop/churn。最新 release 仍是 [v1.3.0](https://github.com/WilliamLiu-1997/Gaussian-Splat-Lite/releases/tag/v1.3.0)，这两项尚未正式发布。
- Spark 的 [#487](https://github.com/sparkjsdev/spark/pull/487) 以 actual viewport 而非整张 render target 给 splat 定尺寸，修复 ArrayCamera/WebXR 每眼 side-by-side 下 AA blur 与 largest splats 半宽；[#488](https://github.com/sparkjsdev/spark/pull/488) 从 XR projection matrix 推 LoD pixel limit，并忽略 <1e-5 的微小变化以免逐帧重算。
- VLAM #116 的 picking 修复应同时覆盖 WebGPU/WebGL2、单源/多 pooled source、`pick`/`pickMany`，尤其是画布顶部/底部对称坐标。
- PlayCanvas Vision Pro #9748 与上一日报 #9750 可组合回归：首帧、late frame、head-locked UI、teleport/turn、transient pointer、GPU memory 与每眼视觉一致性。

## 6. Compression / Format / LOD / Streaming

- LichtFeld #3588 是今天最直接的格式修复：SOG/SSOG/NuRec USDZ 在 Linux 再次可导出。它修的是 archive header charset/平台编码，不改变格式本身压缩率或解码语义。
- Spark [#463](https://github.com/sparkjsdev/spark/pull/463) 抽象 `FetchSource`：PagedSplat 可从 URL、内存或自定义源取页，`UrlFetchSource` 可在请求前后处理，示例用途包括解密。它为私有/签名/加密 streaming 打开扩展点，但不等于提供端到端 DRM。
- Spark [#485](https://github.com/sparkjsdev/spark/pull/485) 将 SPZ gzip encoder/decoder 从 miniz_oxide/自定义 parsing 切到 flate2 + zlib-rs；这是实现依赖调整，未见新的 SPZ version 或压缩率声明。
- Gaussian-Splat-Lite RAD cache budget 提升大场景可控性，但达到内存上限会牺牲当前可见 detail；测试需同时记录视觉 LoD、网络重取、CPU/GPU cache、浏览器进程内存，而不是只看 splat count。
- 本窗口未发现 SOG/SPZ/glTF Gaussian extension、OpenUSD、3D Tiles、MPEG GSC 或 Khronos/W3C WebGPU 的新正式 revision。Khronos 已公开的 [Gaussian Splats / glTF 讨论材料](https://www.khronos.org/events/gaussian-splats-use-cases-next-steps-for-gltf-standardization) 是 2026-04-07 既有事件，不重复计为今日标准进展。

## 7. Training / Reconstruction / SLAM / Robotics / Mapping

- LichtFeld mesh init 让 mesh/CAD/photogrammetry surface 成为 train-time Gaussian prior；价值在已有几何、稀疏图像或需要对齐的工程场景。必须先核对 coordinate/scale/center，分别记录初始 splat 数、`--max-cap`、2k/30k 指标和是否出现 surface bias。
- unified GPU undistort 对 action cam、fisheye、wide/FOV 和 COLMAP 多 lens model 的价值高于普通 pinhole；建议保存 crop ROI、sample map hash、blank-border 检测、训练实际输入分辨率与相机准备耗时。
- OpenFTGS 目前最适合做 CLI/数据转换/训练可启动性测试，而非 SOTA 宣传。推荐先跑 CPU tests 与 license scan，再用公开小数据集做 `convert→init roma→train→export→render→eval` 全链；RoMa weights、CUDA wheel 许可和 fused extension 必须单列。
- Target-aware language map 面向 robotics language-goal localization，但仓库 README 明示 “Code will be released soon”；今天只能审算法与评测设计，不能部署。
- 固定 SLAM/robotics/mapping 项目未发现本窗口新的 code+weights release。

## 8. Avatar / Human / Generative 3D

- **Training-Free Target-Aware Refinement of 3D Gaussian Language Map**（[arXiv:2610.21619](https://arxiv.org/abs/2610.21619)）：text-promptable segmenter 指导区域内 embedding 与 target text embedding 融合，注入强度 closed-form 求解；centered readout 消除 query-agnostic bias。项目页与 MIT 仓库已公开，但 README 明示代码待发布，评级**论文 + 仓库骨架，无可运行代码，P2+**。

<!-- arxiv:2610.20917 -->
- **Decision-FLIP: Budget-Free Pruning for Gaussian Occupancy Banks**（[arXiv:2610.20917](https://arxiv.org/abs/2610.20917)）：无需目标预算，从 decision stability 判定可删 rows。作者报告 eligible rows -12–79%、dependent latency -7–45%、whole-model latency 最多 -8.0%、peak memory 最多 -16.6%，semantic mIoU 变化 ≤0.18 point。未找到代码；评级**论文无代码，P2**。

<!-- arxiv:2610.22108 -->
- **CF-Splat: Closed-Form Triangle Splatting with Mesh Priors**（[arXiv:2610.22108](https://arxiv.org/abs/2610.22108)）：已知 mesh 上以 closed-form least squares 求 per-vertex SH，作者称相对 3DGS compute 少 27.5–378×、peak GPU memory 低 1.8×。它是 triangle splatting，不是 Gaussian representation；无公开代码/统一硬件与质量复现，评级**论文无代码，P2+**。

以上倍率均为论文作者口径；没有代码的条目不得进入部署清单，也不能与已发布工具的实测混写。

## 13. 今天最值得实际测试/部署的项目

1. **Spirula Studio v2026.10.16**：直接下载对应平台二进制，用一组高分辨率普通相机、一组 log/action-cam、一组 360 数据和一个 partitioned 大场景与旧版对照。门槛：Vulkan-capable GPU、足够磁盘；GPL 分发边界需审查。记录 SfM RAM、训练 VRAM、wall time、PSNR/LPIPS、mask/crop、seam、watchdog。预期收益是 capture-to-train 可靠性和输入覆盖，而非保证提速。
2. **LichtFeld master：mesh init + GPU undistort + Linux export/Vulkan**：选已有对齐 mesh 的数据集和一组 fisheye；Linux/NVIDIA 再测 SOG/SSOG/NuRec USDZ、q16/f16 SH 与 live frames。门槛：自行构建 master、CUDA/Vulkan 工具链。预期收益是 geometry prior、正确高 FOV 输入和格式交付稳定性。
3. **Gaussian-Splat-Lite RAD cache + Spark WebXR fixes**：用同一大 RAD/PagedSplat 场景，设 2–3 组 CPU/GPU cache budgets，录固定 camera path 和 XR 双眼；记录 cache、网络重取、LoD churn、每眼 splat 尺寸、first-renderable 和总进程内存。门槛：Three.js/WebGPU/WebGL2，XR 项另需 headset。预期收益是更可控的浏览器大场景内存和正确 WebXR 画面。
