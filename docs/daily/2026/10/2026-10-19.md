## 2. SuperSplat / PlayCanvas 工具链

### SuperSplat 三件套

[playcanvas/supersplat](https://github.com/playcanvas/supersplat)、[supersplat-viewer](https://github.com/playcanvas/supersplat-viewer) 与 [splat-transform](https://github.com/playcanvas/splat-transform) 本窗口没有新 commit、merged PR 或 release。Editor、Viewer、SOG/SPZ/PLY 导入导出、selection/picking、histogram、camera path、发布 API、共享 viewer settings 与 streaming 均没有可核实的新变化。

### PlayCanvas Engine SH4

[PR #9796](https://github.com/playcanvas/engine/pull/9796) / [commit 40854828](https://github.com/playcanvas/engine/commit/40854828f51deaf53221093403114e9490e8da04) 是今天最重要的 PlayCanvas 更新：

- PLY 有 72 个 f_rest 属性时识别为四阶 SH，即每个颜色通道 24 个 view-dependent 系数。
- 第四阶新增 9 个系数；在 GLSL/WGSL、unified/non-unified renderer 中采用 Graphdeco 的 real SH basis。
- SH4 数据从 SH3 的每 splat 64 bytes、4 张纹理增加到约 100 bytes、7 张纹理；低阶文件不受影响。
- Viewer example 新增 SH Update Angle，并默认 0，即相机移动时每帧重新计算 SH；Engine 默认仍为 10。
- 旧代码不会拒绝 SH4，而是按 SH3 stride 错读，造成绿色/洋红色偏色，因此这是正确性修复，不只是画质升级。

状态边界：2.24.0-beta.15 的版本提交早于 SH4 merge，SH4 当前在 main；SuperSplat/SplatTransform 也没有同步发版。需要 SH4 的项目应 pin commit 做副线测试，暂不建议无条件替换生产 Engine。证据 B。

## 3. 可实际运行的开源项目

### Gaussian-Splat-Lite v1.3.2

[正式 release](https://github.com/WilliamLiu-1997/Gaussian-Splat-Lite/releases/tag/v1.3.2) 同时支持：

- PLY 和 SPZ SH4 解码；
- WebGL、WebGPU 与 WebGL2 fallback 的 SH4 渲染；
- Splats.getSplat 与 postDecode 暴露全部 24 个 view-dependent RGB coefficients；
- Viewer Max SH 从 SH0 到 SH4，可运行时切换，并对普通/流式模型立即生效。

迁移注意：

- SplatExtra 的 sh1、sh2、sh3a、sh3b、sh4a、sh4b 改名为 shBlock0–shBlock5；直接访问内部字段的应用会破坏。
- SplatMesh.maxSh 默认从旧上限变为 4。设置为 3 只限制渲染细节，不会减少 SH4 SPZ 已保留的数据与内存。
- 许可 Apache-2.0，适合立即做 PLY/SPZ → WebGL/WebGPU 对照；重点检查显存、颜色一致性与 SH 切换时的 frame spike。证据 A。

### LichtFeld Studio：跨应用拖拽

[PR #3661](https://github.com/MrNeRF/LichtFeld-Studio/pull/3661) 让 Scene Graph 行成为原生文件拖拽源：

- 单 splat、多选、分组和嵌套组均可拖出；组会展开成逐 splat 文件，不保留接收端层级。
- 快速导出为 PLY 或 SPZ；SOG 仍通过普通导出面板。
- Windows、Linux X11、Wayland 有独立后端；macOS 未实现。
- 单次 batch snapshot 有保守 2 GiB 预算，这不是进程总内存上限；大模型仍应使用普通导出。
- PLY/SPZ 先写 partial，再同文件系统 rename；失败或取消会回滚未交付的兄弟文件。
- Blender 5.3 可用原生 importer，不需要插件。Windows 由 [#3688](https://github.com/MrNeRF/LichtFeld-Studio/pull/3688) 自动识别 blender.exe 并用 +Z；文件夹导出遵守 -Y/+Y/-Z/+Z 偏好。

已知兼容边界：Blender 5.3 beta 的 SPZ v4 SH0 importer 对五 attribute streams 有独立 bug；上游 [Blender #165139](https://projects.blender.org/blender/blender/pulls/165139) 尚未合并。现阶段拖入 Blender 优先使用 PLY。证据 B。

### OOOSplat 四格式导出

[commit 410859b9](https://github.com/ooolabdev/ooosplat/commit/410859b91850a7b3591878809f3bf11febe3fb64) 支持标准 PLY、compressed PLY、SPZ v4 和 bundled SOG：

- Rust 提供可随机访问的 edited model view，无需先生成完整中间 PLY。
- 仅删除时生成位图索引；有裁切才扫描位置；按需应用一次 transform 与 SH rotation。
- 浏览器 CPU worker 固定使用 splat-transform 3.10.1；单次 binary IPC 最大 1,024,000 bytes。
- compressed PLY/SPZ/SOG 仍需要整模型编码内存，不是完全流式编码。
- SPZ 检查当前编码器约 ±2048 坐标范围，避免溢出后静默发布。
- 压缩输出会完整解码，验证点数、SH 阶数、渲染模型和属性有效性，再进行原子发布。

Apache-2.0、约 2k stars；Windows 11 最成熟，macOS/Ubuntu 仍偏 alpha。此项在 main、没有新 release tag，建议以副本资产测试格式往返。证据 B。

## 5. Viewer / Editor / Web / Mobile / XR

### LichtFeld RAD/3DGUT

[PR #3675](https://github.com/MrNeRF/LichtFeld-Studio/pull/3675) 修复 RAD splat 在 3DGUT Vulkan viewer 中显示为扁平、不透明 tile 的问题。根因包括把 quantized half 属性当 fp32、把 projected slot 当几何索引、重复 sigmoid Spark opacity、遗漏 LOD fade、parent 使用错误 alpha kernel。

修复复用现有 GPU buffer，不新增 per-splat allocation、scene copy 或 CPU readback。作者 Windows 本地测试：

- 5M PLY、500 frames：master 8.23 ms，修复前 8.55 ms，拆出 RAD 专用 variant 后 7.86 ms；
- 1M RAD：2.15 ms → 1.75 ms；
- 普通 3DGUT 图像与 master bit-identical。

这些是作者单机、特定场景数据；Linux GPU runtime 尚未验证。对使用 RAD+3DGUT 的项目是应立即回归的正确性修复。证据 B。

### Gausify Orbit 改为 Web-only

[PR #16](https://github.com/obraia/gausify-orbit/pull/16) 删除 Tauri 桌面端、Rust 版 ffmpeg/COLMAP/Brush sidecar 和 installer workflow。维护者理由是 Web pipeline 已更完整，而 native Brush 在其测量中仅快 1.0–1.45×；macOS WKWebView 又缺 WebGPU subgroups 且会暂停隐藏页，不能简单复用浏览器实现。

当前要求桌面 Chrome/Edge + WebGPU；SfM、RMBG/SAM/chroma masking、Brush WASM、SOG/PLY/GLB export 均在浏览器本地运行。旧桌面设置会迁移到 RMBG，旧 gorbit/session 和项目目录仍可导入；COLMAP 专用字段被丢弃。仓库 releases 当前为空，不应再引用旧 v0.5.0 installer。证据 B。

## 6. Compression / Format / LOD / Streaming

### SH4 格式边界

PlayCanvas Engine 当前只明确支持 PLY SH4，SOG 后续另做；Gaussian-Splat-Lite 1.3.2 同时支持 PLY/SPZ SH4。两条栈还不能据此宣布 SOG、compressed PLY、glTF Gaussian 已实现统一 SH4 互操作。

SH4 成本：

- PlayCanvas：SH texture 约 64 → 100 bytes/splat，4 → 7 textures；
- GSL：SPZ 解码后保留完整 SH4；将 maxSh 降到 3 不回收这部分内存；
- 更高阶 SH 对 stale view direction 更敏感，应评估 colorUpdateAngle、每帧重算成本和相机移动时的偏色。

### OOOSplat export

SOG 使用单文件容器、10 次 SH palette iteration；SPZ 为 v4。三种压缩格式共享内存预检并执行解码回读。该实现提高交付完整性，但不是 streaming encoder，也没有宣称压缩率或 GPU 解码性能突破。

本窗口未发现 SPZ/SOG 规范、glTF Gaussian extension、OpenUSD、3D Tiles、MPEG GSC 或 Khronos/W3C WebGPU 的新正式标准。

## 7. Training / Reconstruction / SLAM / Robotics / Mapping

### Spirula 模糊/近重复帧过滤

[commit a21c00a1](https://github.com/harry7557558/spirula-studio/commit/a21c00a129900db4c06eda5037554524bc95abff) 将坏帧清洗放进 Create Dataset：

- 用强边缘跨越宽度衡量 blur，并相对同次采集的锐利帧建立像素阈值；
- 64-bit dHash 对比上一个保留帧，去除近重复；
- 最多连续跳过两帧，坏片段会被稀疏而非整段切断；
- Off、10/8/5 px 预设或手动 Sharpness 视图；被跳过帧默认保存在 images_skipped；
- 已完成数据集可在不重跑 reconstruction/mask/depth 的情况下收紧阈值，放宽则需要重新提帧；
- 多镜头/360 的同时间帧按最差镜头共同移动。

作者测试中，选定 5K 帧的测量约 50–110 ms/帧，启用规则后提取约慢 1.5×；手持测试用 8 px 阈值跳过 22%、严重涂抹保留比例由 20% 降至 10%。这些是作者数据，不是通用质量保证。建议对自有 DJI/360/手机素材保存 CSV，并比较 COLMAP 注册率、最终 splat 清晰度与覆盖缺口。证据 B。

## 13. 今天最值得实际测试/部署的项目

### 1) Gaussian-Splat-Lite v1.3.2 + PlayCanvas Engine SH4

- **为什么**：SH4 从“文件能打开但颜色可能错”推进到两条 WebGS 栈的显式支持。
- **门槛**：准备同一份 SH3 与 SH4 PLY/SPZ；GSL 可直接锁 v1.3.2，PlayCanvas 需 pin main commit。
- **测试**：固定相机路径记录颜色差异、GPU allocation、纹理数、frame time；逐档 SH0–SH4，并对比 colorUpdateAngle=0/默认。
- **预期收益**：正确呈现高阶 view-dependent appearance；代价是每 splat SH 数据约 64→100 bytes（PlayCanvas 口径）和更多计算。

### 2) LichtFeld Scene Graph → Blender 拖拽 + RAD/3DGUT

- **为什么**：一个提升 DCC 交付效率，一个修复 RAD 查看正确性，均已进入 master/untagged build。
- **门槛**：Windows 或 Linux；Blender 5.3；RAD 测试需 Vulkan/3DGUT。正式 v0.5.4.1 tag 在核查时尚不可见，生产应等待 tag 或锁定 SHA。
- **测试**：单 splat/多选/嵌套组，PLY/SPZ、四种 up-axis、长名称、取消/失败；RAD 对比 PLY、3DGS/3DGUT、coarse LOD 和 selection overlay。
- **预期收益**：减少导出/导入步骤并消除 RAD tile artifact；SPZ SH0 暂避开未修复的 Blender importer。

### 3) Spirula blur filtering + OOOSplat 多格式导出

- **为什么**：前者改善 capture→dataset 输入质量，后者改善 edit→delivery 格式闭环。
- **门槛**：Spirula main 自行构建；OOOSplat main 使用副本资产，Windows 路径最成熟。
- **测试**：同一视频用 Off/10/8/5 px，比较保留帧、SfM 注册率、训练清晰度与覆盖；再把编辑结果导出四格式，核对 splat 数、SH、坐标、大小与渲染。
- **预期收益**：减少坏帧软化和手工格式转换；风险是过严清洗造成覆盖缺口、压缩格式编码时整模型内存峰值。
