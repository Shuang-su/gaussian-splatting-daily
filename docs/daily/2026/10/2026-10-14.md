### PlayCanvas Engine：画质路径与可观测性进入 beta 线

- [#9739 / commit `4519a2c`](https://github.com/playcanvas/engine/commit/4519a2c49691f11696e2cfb565e3655e844a3a0f) 为 TAA 增加 `taa.upscale`（默认关闭）：场景按低分辨率渲染，再在全分辨率历史缓冲中累积 jitter sample；jitter cycle 从 16 扩到 128。维护者只说明半分辨率效果“大致接近”3/4 分辨率 bilinear，不应解释为确定性能倍数；运动物体仍可能更模糊/ghosting。
- [#9741 / commit `f855bf6`](https://github.com/playcanvas/engine/commit/f855bf699a0c24eb5e762f0478f99a652021a263) 把 TAA 改为新的 CameraFrameEffect resolve stage，使 bloom/DoF 等后续效果吃到 resolve 结果，并修复重建 frame pass 或切换效果时每次遗失一张全分辨率 history texture。兼容性注意：`cameraFrame.taa = {...}` 整体赋值不再支持，应改属性设置；内部未文档化 pass 不再导出。
- [#9744 / commit `14d611e`](https://github.com/playcanvas/engine/commit/14d611e0949cd0e7d937970d7fcb82135d1af34a) 以可逆 Karis tone map 抑制高亮边缘闪烁，并让运动量大时当前帧权重最高提升到 0.5；只增加 ALU，不增加 pass/texture。
- [#9747 / commit `7b806b1`](https://github.com/playcanvas/engine/commit/7b806b16d1f7c72418930d4c7a823e376d241d01) 新增 tree-shakeable SMAA 1x：3 个 fullscreen pass、无 jitter/history/ghosting。作者在 Apple silicon Mac、1080p WebGPU 测得约 1.4 ms；导入增加约 36KB minified/12KB gzip 与 8KB lookup data。Safari 16.4 以前缺 `deflate-raw`，效果会告警后 no-op。
- [#9740 / commit `affb254`](https://github.com/playcanvas/engine/commit/affb2545d922f35f6f5c25f6813c7b731d45a1d8) 在 AppStats/MiniStats 增加 compute dispatch/pass 计数，GS 示例也显示指标；这对 WebGPU projector/sort/cull 的回归定位很实用，但不改变算法。
- [#9746 / commit `bbd6a18`](https://github.com/playcanvas/engine/commit/bbd6a18e7655b3cd45e0552b6349e2a45fcd0d84) 为 StorageBuffer 读写/复制、indirect dispatch 与 bind group storage 增加 debug-only usage 检查；release 构建移除，不增加生产开销。
- tag 线已到 [`v2.24.0-beta.10`](https://github.com/playcanvas/engine/releases/tag/v2.24.0-beta.10)，最新正式版仍是 [v2.23.2](https://github.com/playcanvas/engine/releases/tag/v2.23.2)。对 WebGS 的实际建议：在相同 splat 数、相机轨迹、renderTargetScale 下比较 native、TAA upscale 与 SMAA，记录 GPU time、history 显存、ghosting 和高亮 flicker；暂不直接替换生产 stable。

## 3. 可实际运行的开源项目

### Gausify Orbit v0.5.0：本地端到端 orbit-video → splat

- [仓库](https://github.com/obraia/gausify-orbit)创建于 2026-10-13，核查时 11 stars、2 forks；[v0.5.0](https://github.com/obraia/gausify-orbit/releases/tag/v0.5.0) 同日发布 Windows x64 installer 与 Apple Silicon DMG，另有[在线 WebGPU 版](https://orbit.gausify.com)。代码 MIT，作者 Bryan Diniz；项目年轻、样本量小，评级为**可实际测试**，还不是生产可用。
- 桌面端为 Tauri 2 + React/Rust：Windows 首启可下载并 SHA-256 校验 COLMAP 4.2.1/ffmpeg，NVIDIA 可用 CUDA COLMAP；macOS 14+ Apple Silicon 需 Homebrew 安装 COLMAP/ffmpeg。安装包未签名/未 notarize，是当前部署阻力。
- 浏览器端要求桌面 Chrome/Edge、WebGPU `subgroups`，项目存 OPFS。自研 SfM 使用 AKAZE、WebGPU 暴力匹配、RANSAC、PnP/triangulation 与局部/全局 BA；Brush 编译成 WASM+WebGPU 训练，无需 CUDA。开发需 Node 20+、pnpm、rustup、wasm-pack 与 side-by-side Rust 1.99。
- 导出 `.ply` 或 PlayCanvas SOG v2，支持 opacity/SH trimming 与 decimation；作者称 SOG 通常比 raw PLY 小 5–15×，但未给同一数据集全套质量/体积表，应视为作者经验值。分享走 Cloudflare R2 临时链接和 PlayCanvas WebXR viewer。
- 作者可复现实验在 M4、120 帧 960×720 合成 orbit 上：浏览器 SfM 37s、120/120 cameras、位置中位误差为半径 0.27%、训练约 40 steps/s（约 native Brush 的 1/3）。文档明确说浏览器 SfM **尚未在真实 AI 视频上验证**，因此第一轮应用测试应优先检查低纹理、动态背景、运动模糊和闭环漂移。
- 许可证注意：主程序 MIT，但可选 RMBG-1.4 模型是非商业许可；SAM 2.1 tiny 为 Apache-2.0。商业试用不要把“主仓库 MIT”误当作所有按需模型均可商用。

### Spirula Studio：Spherical Beta 与 checkpoint 容量恢复

- [Spherical Beta 合并 commit `71d8a916`](https://github.com/harry7557558/spirula-studio/commit/71d8a91666173f6f46b7e0274e9b1d78e1944c11) 增加 `--sb-lobes 1..8`；若未显式指定 SH，启用时默认退到 SH0，允许 SH+lobes 混合。每个 lobe 是 `(r,g,b,theta,phi,beta)` 六个 raw 值，写在 `features_sh` 后部并以 `sb_params_*` 导出；普通 viewer 可忽略它们显示 base color，gsplat 与 PlayCanvas 可读。
- 功能覆盖前向/反向、量化训练、densification、checkpoint/resume、merge、模型旋转和 web viewer。限制是**仅 Vulkan 后端**，CUDA 遇到带 lobes 模型会拒绝；因此应作为研究 beta 使用。

## 6. Compression / Format / LOD / Streaming

- LichtFeld #3417 的 SOG 变化本质是**用约 1.5% 体积换取作者场景约 44% 的非流式导出时间下降**；解码像素一致，但没有新的随机访问、GPU 解码、LOD chunk 或网络传输协议。
- Spherical Beta 的 `sb_params_*` PLY 布局与 gsplat/PlayCanvas 对齐，普通 3DGS PLY reader 会忽略额外属性而退化到 base color；这提高实验互操作性，但并不是新标准。SOG/SPZ/glTF 对 Spherical Beta 的通用编码仍需单独验证。
- Gausify Orbit 的 SOG v2 导出复用 lossless WebP texture 与 SH k-means palette，适合直接送入 PlayCanvas；`.gorbit` 是其项目包格式，不是通用场景标准。
- Khronos `KHR_gaussian_splatting`、SPZ、OpenUSD、3D Tiles、MPEG GSC 与 WebGPU 标准源在窗口内未核验到新修订/发布；不要把 2 月的 glTF release candidate 重复计为今日更新。

## 7. Training / Reconstruction / SLAM / Robotics / Mapping

- Gausify Orbit 是今天最直接的新 reconstruction pipeline：桌面依赖 COLMAP 4，Web 版改用自研 SfM；对真实拍摄 orbit 的首要门槛不是 GPU，而是闭环特征、主体遮罩与动态内容稳定性。M4 合成 benchmark 不能替代手机实拍验证。
- Spirula 的 Spherical Beta 重点在高光/视角依赖外观：作者在 RTX 5070、30k steps、1M splats、Mip-NeRF 360 单次实验中，2 lobes 相比 SH3 在 bonsai/counter/garden/room 的 PSNR 均不低，splat buffer 222 vs 351 MiB；建议复测 glass/metal、低视角覆盖和 held-out view，而非只看训练视图。
- LichtFeld [#3375](https://github.com/MrNeRF/LichtFeld-Studio/pull/3375) 与 [#3376](https://github.com/MrNeRF/LichtFeld-Studio/pull/3376) 让 mask 外像素不再影响 thin-structure 与 Canny densification guidance，避免隐藏内容改变保留权重；unmasked path 保持一致。
- 没有新的 SLAM、robotics、autonomous-driving 或地图融合代码发布达到 P1；固定项目的静默不解释为“方向无进展”。

## 13. 今天最值得实际测试/部署的项目

1. **Gausify Orbit v0.5.0**：先用一个 60–120 帧、纹理清晰、主体静止的真实 orbit 视频，同时跑浏览器和桌面路径。门槛：Chrome/Edge WebGPU `subgroups`，或 Windows/macOS + COLMAP/ffmpeg；若做 SAM 首次需下载 84/165MB 模型。记录注册相机率、闭环漂移、mask temporal consistency、训练速度、PLY/SOG 体积与 PlayCanvas/WebXR 显示。预期收益是用单一 UI 验证完整 WebGS 产品链。
2. **Spirula Studio Spherical Beta（`71d8a916`，Vulkan）**：在高光明显的真实场景上对比 SH3、2 lobes、SH3+2 lobes，固定 1M splats/steps 与 held-out views，记录 PSNR/SSIM、FPBO 时间、峰值 VRAM、PLY 体积及 PlayCanvas/gsplat 可读性。门槛是源码构建 Vulkan master；预期收益是更低的 view-color 成本和更强 specular 表达，但不能走 CUDA。
3. **LichtFeld master 大场景回归**：准备约 9M splats 的 `.licht` 项目，覆盖 merge、Save As、budget 调整、编辑/undo、SOG 导出与插件安装。记录进程 VRAM/RSS、首个正确帧、导出时间/体积，并验证 digest mismatch 会阻止解压。门槛是源码构建；预期收益是减少 OOM 与等待时间，同时补上插件供应链校验。
