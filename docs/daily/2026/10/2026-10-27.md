## 2. SuperSplat / PlayCanvas 工具链

### SuperSplat v3.7.0：径向排序是窗口内真正新增的渲染变化

[v3.7.0](https://github.com/playcanvas/supersplat/releases/tag/v3.7.0) 于 2026-10-26 09:31 UTC 发布。相对 v3.6.0，release 汇总了 [复制/粘贴 #1077](https://github.com/playcanvas/supersplat/commit/ebce8e6e3f3f41f3a816f35a0f4fe27beacaae53)、[typed Editor API #1078](https://github.com/playcanvas/supersplat/commit/659809448a4be1c0a3532fc1856a60ac2c5f0977)、[WebMCP #1081](https://github.com/playcanvas/supersplat/commit/e5e78473cec52cdd60d5d28118cc8c81bd4b8eb7)、[命令校验 #1082](https://github.com/playcanvas/supersplat/commit/f272ec238b032a8ac5568f1cbec303edc5eb4bd0) 和窗口内新增的 [radial sorting #1083](https://github.com/playcanvas/supersplat/commit/efb6a8abceee997c9896c6b15d58026115a9cc4a)。前四项代码早于本窗口，今天的“新事件”是正式 tag；去重时不把它们另算四条新闻。

- **架构变化**：投影 compute shader 新增 `radialSort` uniform；透视相机可用 `length(viewCenter.xyz)` 生成 20-bit sort key，`far` 改为由场景包围球推导的最远距离。正交视图仍使用视轴 depth。
- **为什么重要**：相机只旋转不平移时，径向距离不变，避免原视轴排序随朝向整体重排；这会减少排序抖动和无谓键变化，但不是“免排序”。需要用薄层、透明前景、相机内外穿越场景验证 alpha 混合误差。
- **Editor 自动化**：typed API 将 selection、property、region、transform、undo/redo、import/export 等串入同一 command queue；WebMCP 暴露带显式 scope、`viewToken`、取消与错误码的浏览器原生工具。它可用于可审计的编辑代理，但目前依赖 Chrome 的实验性 `WebMCP`/`WebMCPTesting`，不应当作所有浏览器的稳定 Web 标准。
- **导入导出与格式**：本版没有新增 SOG/SPZ/PLY/GLB/glTF 编码；WebMCP 复用现有 exporter，并要求明确 filename、format 与 selection/layer/visible scope。LOD import 可以显式指定 tier。
- **升级建议**：建议马上在 staging 升级；重点回归 perspective/ortho、radial/depth、stochastic on/off、selection picking、viewer export 和自动化取消。生产端先保留 v3.6 的可回滚包。

固定检查 [supersplat-viewer](https://github.com/playcanvas/supersplat-viewer) 与 [splat-transform](https://github.com/playcanvas/splat-transform)：本窗口无新 commit/release。PlayCanvas Engine 有三项相关但非 GS 功能发布的修复：[#9814](https://github.com/playcanvas/engine/commit/734d236d185cc6147799891f56d1965e6d138a8f) 按 canvas 所属 document 创建 WebGPU device，避免 WebKit 跨上下文配置导致页面终止并兼容 worker OffscreenCanvas；[#9823](https://github.com/playcanvas/engine/commit/a9f5510a5679cce019e5489ef0cfe9c1e0072e9d) 在 host-owned GPUDevice 销毁时释放 indirect draw/dispatch buffers；[#9829](https://github.com/playcanvas/engine/commit/fcc1368d710e13e3dbf80edd5a8079518fb99408) 统一 render-pass clear/store setter，并移除 GS processor、SOG 与 work-buffer 的冗余 clear 标志写入。对 iframe、worker 或复用 GPUDevice 的 WebGS 应用值得回归。

## 3. 可实际运行的开源项目

### OOOSplat：0.7.0 桌面流水线与 GPS 辅助

[OOOSplat](https://github.com/ooolabdev/ooosplat) 是 Apache-2.0 的本地桌面重建工具，Rust/Tauri 外壳编排 COLMAP 与 Brush，面向 Windows、Apple Silicon macOS 和 Ubuntu。大合并 [2cebd01d](https://github.com/ooolabdev/ooosplat/commit/2cebd01d38a16a5f713266045b34cb7674c13a92) 把版本标识推进 0.7.0，并统一：普通/ERP 图片与视频、外部标准/压缩 PLY、SOG、SPZ、SPLAT、KSPLAT 导入，标准 PLY/compressed PLY/SPZ v4/单文件 SOG 导出，以及普通、多相机和完整 ERP 补拍。

补拍不是 optimizer checkpoint resume：选择“沿用原模型”时从未经编辑的生成 PLY 初始化，旧图和新图仍跑正常完整配方；仅在确认相机条件相容时复用内参，裁切/删点编辑不会继承。真实跨设备、跨镜头与全景接缝仍在验收，不应把“能进入流程”理解为画质已经普遍验证。

[GPS commit 65193513](https://github.com/ooolabdev/ooosplat/commit/65193513fde9e5cb2bf5bd9b906c7221f834b077) 进一步读取 JPG/JPEG/PNG 的 EXIF/XMP：GPS 最多补充 50 个水平邻居匹配候选，不删除原有匹配；只有至少 5 张带高度、非近共线且跨度超过定位误差门槛的图片，才尝试 pose prior、Ceres 与 Sim3 对齐。失败会回到原视觉重建，不把取消、磁盘、OOM 或子进程崩溃伪装成“GPS 不足”。作者在固定的 Brighton Beach 18 张公开照片上报告 8000 steps、104,967 splats、约 110.6 秒、RTX 3060 Ti；相对输入 GPS 的残差中位数约 0.349 m，但这不是对地面真值的测绘精度，也未完成 macOS/Linux 原生验收。

### LichtFeld Studio：碰撞体从附属脚本变成一等场景节点

[e1531fb8](https://github.com/MrNeRF/LichtFeld-Studio/commit/e1531fb8b33b79620fd44e22cf47a1d8150ac5d8) 新增 `LichtFeld-Studio voxelize`、Python `generate_voxels/save_voxels` 与紧凑 GPU voxelization，输出 SuperSplat v1.1 `.voxel.json/.voxel.bin` pair；输入支持 PLY、SOG、SSOG，参数含体素尺寸、opacity、cleanup、最大 Gaussian 面积与自动分辨率。随后 [7d3c6783](https://github.com/MrNeRF/LichtFeld-Studio/commit/7d3c6783e86a539c1382f617d43e01a8101e2fde) 将不可变 collision volume 作为场景节点保存到项目，加入 MCP `scene.generate_collision` / `scene.export_collision`、可取消 job 与 Walk navigation；[83247a58](https://github.com/MrNeRF/LichtFeld-Studio/commit/83247a5857c1d276202a8ecf5f45cb9ae6526c0f) 补齐 GUI 对话框和可见 voxel preview。

[5bb7b895](https://github.com/MrNeRF/LichtFeld-Studio/commit/5bb7b89525727422bc0d060c5ff6c6ec9b518552) 又移除 collision octree 上传的临时副本：host-visible 内存直接写或通过 staging copy。维护者在 RTX 4080 上报告 4.6 MB 上传 2.3/4.2 ms → 0.5 ms、83 MB 94.7/111.3 → 10.6 ms、375 MB staging 418.9/497.1 → 171.9 ms；这是作者单机数据，场景和 PCIe/驱动口径不足以外推。

### splatkit：移动端坐标系终于显式化

[Xget7/splatkit](https://github.com/Xget7/splatkit)（MIT）把 `sourceFrame` 接入 iOS、Android 与 React Native load request，类型覆盖 48 种合法轴向组合并拒绝重复/冲突轴。缺省使用文件声明或格式默认：SPZ 为 `rub`（+X right、+Y up、+Z back，与 glTF/OpenGL 一致），COLMAP/OpenCV 常用 `rdf`。这是互操作正确性更新，不改变压缩率或渲染性能，但对于 PLY/SPZ 在训练、网页和原生移动端之间往返非常重要。

## 6. Compression / Format / LOD / Streaming

- **SPZ**：splatkit 的默认轴向文档修正避免把未标记的 `rdf` 文件误按 `rub` 读取；这属于语义兼容性，不改变 SPZ bitstream。
- **SOG/PLY**：OOOSplat 0.7.0 将标准/压缩 PLY、SPZ v4、单文件 SOG 纳入正式导出菜单；LichtFeld collision 读 PLY/SOG/SSOG 并输出独立 voxel pair，碰撞体不是 SOG 内嵌 extension。
- **SuperSplat**：v3.7.0 没有新的 SOG/SPZ/PLY 编码或 LOD/streaming 结构；WebMCP export 只是自动化现有 exporter。

## 7. Training / Reconstruction / SLAM / Robotics / Mapping

LichtFeld 除碰撞链外还有四项训练/生产正确性更新：

1. [#3833 / e8ed4816](https://github.com/MrNeRF/LichtFeld-Studio/commit/e8ed4816389d1b8e5b205e88802730e15db587ae) 让 combined-model worker 使用自己的 stream 并丢弃 stale 结果；导入两个大 splat 后立刻隐藏一个，不再让 render thread 等待重建。

3. [00625851](https://github.com/MrNeRF/LichtFeld-Studio/commit/00625851b9069285b1cad8f7f5990bf80a6668f2) 将 color variance loss 从“splat vs 训练照片”改为“splat vs 当前 rendered pixel 的期望颜色”，从而与 appearance correction/MRNF 默认 exposure correction 一致；这是 loss 语义修正，旧 run 与新 run 不应直接混用曲线。
4. [b4cc122f](https://github.com/MrNeRF/LichtFeld-Studio/commit/b4cc122f5e4189abfa7df5ba503395b5bb42e69c) 在训练运行或暂停时阻止修改需要重启的参数，结束后再解锁，避免 UI 显示已改而训练器仍使用旧值。

## 13. 今天最值得实际测试/部署的项目

### 1) SuperSplat v3.7.0

- **为什么**：正式 release，把可切换径向排序和可编程 Editor/WebMCP 放到同一版本。
- **门槛**：MIT；Chrome/Edge 等可用 WebGPU 浏览器。WebMCP 自动化测试需 Chrome experimental feature，普通编辑不依赖它。
- **测试**：同一透明/薄层模型下比较 radial/depth；相机原地旋转、穿入场景、ortho；再测 stochastic、selection、histogram、viewer export 与取消。
- **预期收益**：旋转镜头排序更稳定，自动化编辑更可审计；风险是新排序对特殊透明层的混合顺序需要画质回归。

### 2) LichtFeld collision + Walk

- **为什么**：这是从 Gaussian 场景直接生成可保存、可预览、可导出、可自动化调用的 collision volume，补齐 WebGS/游戏交互最常缺的一层。
- **门槛**：GPL-3.0、master、CUDA/Vulkan build；锁定 e1531fb8 + 7d3c6783 + 83247a58 + 5bb7b895。
- **测试**：PLY/SOG/SSOG；自动/手动 voxel size；thin wall、楼梯、门洞、地面；CLI/GUI/MCP 一致性；项目重开、撤销、取消、导出 pair；Walk 半径/步高与穿透率。
- **预期收益**：扫描场景可更快进入导航、XR 与简单游戏逻辑；风险是 voxel 近似会牺牲细节，作者 RTX 4080 上传数字不能替代目标硬件测试。

### 3) OOOSplat 0.7.0 + GPS

- **为什么**：把本地重建、补拍、多格式发布和可回退 GPS 地理参考放在单一桌面流程，且提供公开样例与边界说明。
- **门槛**：Apache-2.0；GPS 原生路径先限 Windows x64，需捆绑 COLMAP/Brush 和 NVIDIA GPU 才能复现作者训练环境。
- **测试**：先复现 Brighton 18 图；再构造无高度、弱跨度、冲突 GPS 和跨设备补拍；核对视觉 fallback、原图 hash、注册数、北向、尺度、PLY/SPZ/SOG 轴向与训练 checkpoint 失效策略。
- **预期收益**：为地图/数字孪生提供近似米制与北向，减少纯视觉尺度歧义；风险是非测绘精度、跨平台/跨设备未完成验收。

移动端集成团队可把 splatkit `sourceFrame` 作为低成本第四项测试；Unreal/Pico 团队应先向 MLS Labs 获取 Pro 2.1.0.0 的许可、构建和硬件矩阵，再决定投入。
