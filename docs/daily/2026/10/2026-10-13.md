## 2. SuperSplat / PlayCanvas 工具链

### PlayCanvas Engine：GS compute 从 workgroup 驱动转为线程驱动

- [#9733 / commit `94604f3`](https://github.com/playcanvas/engine/commit/94604f35db117f22d0c61dd81805c4abc4891d17) 新增 `Compute#setupDispatchThreads(x, y, z)`：由 shader 的 `@workgroup_size` 推导 dispatch，自动向上取整；`dispatchThreadsCS` 还提供线程数、越界判断和线性索引。大规模 1D 工作在超过 device per-dimension limit 时自动分摊到行。
- [#9735 / commit `c9ba403`](https://github.com/playcanvas/engine/commit/c9ba40399b0bcee497d05f0502a38dcb45dcbc56) 首批迁移 GS projector、GS shadow cull 和 GS interval cull；radix sort、prefix sum、interval scatter 仍保留 workgroup 语义。架构价值在于把“处理多少 splat/interval”与 shader 局部组大小解耦，减少 WebGPU 路径的手工 tiling 和漏改风险。
- 对 Editor/Viewer/SplatTransform/格式：这两项位于 Engine compute 基础层，不改变 SOG/SPZ/PLY/GLB/glTF 文件内容、发布 API、selection/picking 或 camera path；最直接影响是 WebGPU GS 投影/裁剪在超大工作量下更稳健。由于没有基准，不能宣称 GPU sorting 或投影本身提速。
- [#9737 / commit `d9792c1`](https://github.com/playcanvas/engine/commit/d9792c12a7d690d11cb276cda794379813dd26a7) 修正 TAA previous jitter 留存导致的半像素漂移、摇晃和软化，并把历史纹理由 `PIXELFORMAT_111110F` 改为 RGBA16F/32F。混合 GS、mesh 与后处理的 viewer 可获得更稳定画面，代价是两张 TAA history texture 从约 4 增至 8 bytes/pixel；它不是 GS rasterizer 变更。
- Engine 最新正式版仍是 [v2.23.2](https://github.com/playcanvas/engine/releases/tag/v2.23.2)；上述变更在 master/`v2.24.0-beta.9` 一线，**建议先在大 splat 场景与低 renderTargetScale 上做灰度回归，不建议仅为此直接升级生产稳定版**。

## 3. 可实际运行的开源项目

### Spirulae-splat：稠密初始化不再随视频帧数失控

- [commit `d76eba2`](https://github.com/spirulae-splat/Spirulae-splat/commit/d76eba240d93cd741c564d9ab9ddc391293946a0) 将自动图像配对从固定近邻+稀疏轨迹覆盖改成“表面驱动的投影可见性”。维护者给出的极端案例中，5,730 个 dual-fisheye 虚拟面原会产生 13,545 个 Balanced pairs；31,292 面、无 tracks 的 Nerfstudio 数据会让每个面都成为 reference。新预设 Fast/Balanced/High 使用 2/3/4 个邻居与 12/12/16 的 reference coverage，并保留旧项目预设迁移。
- 内存预算同时考虑物理 RAM、free RAM 和 Windows available commit，因为 device memory 也会占用 commit；decoded pixels、预测结果等缓存按不同权重计入。RoMa 权重加载最多并行 16 workers，维护者在 16-thread RTX 3070 Laptop 上报告约 0.8 秒，对照单线程 7–8 秒，device weights 相同。
- 成熟度：主分支可测，稳定 release 仍是 [v2026.10.6](https://github.com/spirulae-splat/Spirulae-splat/releases/tag/v2026.10.6)。安装与 GPU 依赖沿用项目现有 CUDA/Vulkan 路径；大型视频/全景数据受益最大，建议固定旧/新 pair 清单、总点数、峰值 RAM/VRAM、耗时和 PSNR/SSIM 一起对比。

### LichtFeld Studio：正确性修复密集落地

- mask/SSIM 三项合并消除了训练、评估和 cached visits 之间的六类语义分歧；masked SSIM 改为归一化的 mask-weighted moments，并使忽略区梯度为零。维护者报告 unmasked 路径 bit-identical，masked kernels 约快 4–6%，但仍应在自有遮罩边界、缩放 mask、16-bit TIFF 上复测。
- [#3297](https://github.com/MrNeRF/LichtFeld-Studio/pull/3297) 对 binary/ascii/big-endian PLY 都按 property name 映射，canonical header 仍走 fast path；[#3307](https://github.com/MrNeRF/LichtFeld-Studio/pull/3307) 修复 TIFF depth 被静默忽略。对从摄影测量/DCC/脚本工具输入非标准属性顺序或浮点深度的链路，这两项优先级高。
- 成熟度：主分支可测，稳定 release 仍为 [v0.5.4](https://github.com/MrNeRF/LichtFeld-Studio/releases/tag/v0.5.4)；许可证 GPL-3.0。今天没有新的独立仓库达到“代码+权重可跑”标准。

1. **Spirulae-splat dense init（主分支 `d76eba2`）**：用一个高帧数视频或 dual-fisheye 数据集做旧/新 A/B。门槛是现有 Spirula CUDA/Vulkan 训练环境与足够磁盘缓存；记录 pair 数、真正执行/缓存 pair 数、点数、峰值 RAM/VRAM、dense init 时间与最终 PSNR/SSIM。预期收益是避免配对数量随帧数失控，并让低内存/Windows 环境更可预测。
2. **LichtFeld mask + LOD + MCP export 组合回归（master）**：准备彩色/16-bit/resized mask、带 TIFF depth 的数据和 SH0/1/2 模型；验证冷/热缓存、训练/评估一致性、静止相机提高 LOD budget 后自动细化，以及多格式导出体积。门槛是源码构建；预期收益是消除静默数据错误，并减少不必要的 SH 负载。
3. **PlayCanvas Engine #9735 + #9737 灰度场景**：在 WebGPU 下压测超大 splat 数与 interval 数，再以低 `renderTargetScale` 检查 TAA；同时监控历史纹理显存增加。门槛是跟随 master/beta 而非正式 stable；预期收益是 dispatch 边界更稳、TAA 更清晰，但需确认自有设备矩阵无回归。
