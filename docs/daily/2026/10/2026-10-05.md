## 3. 可实际运行的开源项目

### godotGS：从“预算生效”进入“丢失可诊断 + HLOD 格式落地前夜”

昨天的 1,024-splat page atlas 已解决固定 65,536-splat slot 浪费；今天 [#1138](https://github.com/klausi3D/godotGS/pull/1138) 又暴露另一层瓶颈：16 px tile 在 high preset 只处理 12,288 records，超过部分按 near-to-far 排序后丢掉最远记录，会形成 tile-aligned 黑洞。

这次没有改变默认 cap，而是：

- 两条 raster path 都通过 bitmask 记录 `GS_OVERFLOW_DROP_RASTER_TILE_CAP`。
- always-on readback 从 4 B 扩为完整 88 B snapshot，`get_overflow_stats()` 新增 sampled dropped records/tiles、事件计数与实际 cap。
- `max_raster_splats_per_tile=0` 代表跟随 preset，正数才是真覆盖。
- fragment path 改为每 tile 计一次，避免按 fragment 夸大 256 倍。

它让“画面缺块”第一次可被 telemetry 直接诊断，但默认缺陷仍在。对现有项目最合理的做法是看到 warning 后按场景 A/B 12,288、32,768、65,536，而不是全局拉满。

[#1149](https://github.com/klausi3D/godotGS/pull/1149) 则实现 HLOD S1a：`.gsplatworld` v2 增加 80-byte header extension、128-byte node/instance records、world-aligned octree 和 interior payload。8M SH3 reimport 的作者实测 peak working set 8.089 GiB、80.2 s；当前仍没有 runtime consumer，属于 format/bake foundation。

### 3. Spirula HDR/SynthEyes plate 小规模验证

**为什么：** DWAA/DWAB、TIFF ICC、analysis exposure 与 fixed-pose sparse recompute 正好组成影视 plate→外部 solve→GS 的完整前处理链。

**门槛：** `master` 测已合入的 #141/ICC；#144/#145 只在数据副本或独立 branch 上评估。准备一组暗 TIFF、DWAA plate、COLMAP/SynthEyes camera model 与 alpha border。

**记录：** registered cameras、features、points、camera/pose byte identity、decode time、mask mode、训练边缘外漏。特别区分 cut-out alpha 与 undistort border，避免错误地把真实场景训练成空空间。
