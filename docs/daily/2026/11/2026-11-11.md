### P1｜SuperSplat WebMCP 从文本控制走向可视反馈与实例化场景编辑

- **时间 / 一手来源**：2026-11-10；[PR #1095](https://github.com/playcanvas/supersplat/pull/1095)，commit [`89fb456`](https://github.com/playcanvas/supersplat/commit/89fb456f76f24961c5d99affcc6baedf56be40ba)。
- **新增**：32 个 WebMCP 工具中增加 `render_view`、`instance_layer`、`create_from_generator`。`render_view` 可离屏输出最多四视图的 color / selection / property / layers / shaded JPEG/PNG；`instance_layer` 允许最多 128 个共享静态 Gaussian 数据的变换实例；generator 在无网络 CSP 沙箱内运行，限制 10 秒、200 万 Gaussian、64 列。
- **架构 / 影响**：代理现在可执行“修改→渲染→视觉核验”，而不是只读场景状态；实例层避免复制 splat payload，适合场景布置与重复资产。它不等同于新的 Publish API，也不改变 SOG/SPZ/PLY 编码。
- **可运行性**：可实际测试；MIT；WebGPU 浏览器；**可信度 B**。建议先用于非破坏式编辑与截图验收，再逐步开放写操作。

### P1｜SuperSplat 修复极端 far plane 的 GPU 排序碎裂，并把训练滤波信息贯通到 Editor

- **来源**：[PR #1097](https://github.com/playcanvas/supersplat/pull/1097)，commit [`1522a44`](https://github.com/playcanvas/supersplat/commit/1522a440c3c0bd0c39cb9c42db3382c191795687)。
- **新增**：透视排序键改为对数间距，避免少数离群 splat 把 far plane 拉大后中近景深度精度崩坏；Editor 新增抗锯齿 Auto/On/Off，使用 0.1 px² training filter 与 opacity compensation，并把 model tag 在 PLY/SOG/SPZ 间 round-trip。
- **性能 / 质量口径**：作者测试中错误红像素从约 18–24 万降为 0；这是确定性正确性样例，不是通用 FPS benchmark。
- **实际影响**：对大尺度扫描、飞散点与远距离背景最直接；AA tag 能避免已训练滤波场景重复补偿。**建议立即升级实验分支**，但 HTML 输出需同时使用 SplatTransform 3.11.1 才能完整保留 tag。
- **可信度 B**；另有 [PR #1096](https://github.com/playcanvas/supersplat/pull/1096) 把 `render_view` 的 frame wait 改为 5 秒可取消、播放时间线时拒绝渲染，并按请求相机重算分析范围，43/43 测试通过。

### P1｜SuperSplat Viewer 1.43.0 直接加载 LCC2 / SPZ，并修复 Firefox WebGPU 节流

- **版本 / 一手来源**：tag [`v1.43.0`](https://github.com/playcanvas/supersplat-viewer/tree/v1.43.0)，[package.json](https://github.com/playcanvas/supersplat-viewer/blob/v1.43.0/package.json)；MIT，Node.js ≥20，PlayCanvas Engine `^2.24.0`。
- **LCC2 / SPZ**：[PR #361](https://github.com/playcanvas/supersplat-viewer/pull/361) 允许直接打开 `.lcc2` 和 `.spz`，不再先经 SplatTransform 转成 `lod-meta.json`；LCC2 按需流式，SPZ parser 支持 v3/v4，只有 v4 才按需下载 zstd WASM。LCC2 使用 +Z up，SPZ 使用 +Y up。
- **限制**：LCC2 的 georeferencing offset / EPSG / shift / scale 尚未应用；XR 未测；严格 CSP 需允许 blob script。它是读取与流式入口升级，不代表完整地图坐标集成。
- **Firefox WebGPU**：[PR #359](https://github.com/playcanvas/supersplat-viewer/pull/359) 用空 `queue.submit([])` 轮询 FrameGate；作者在 Firefox 159 / macOS Apple Silicon / 120Hz 的重负载动画中，从约 19–20 fps 提升至 34 fps，仍比关闭 gate 慢约 20%。未提供手机/头显数据。
- **Stochastic AA**：[PR #362](https://github.com/playcanvas/supersplat-viewer/pull/362) 增加 AA compensation 与标准 0.3 px² filter；作者 church 场景 RMS 有改善，但未用真实 AA-trained 场景验证。**可信度 A/B**。

### P1｜SplatTransform 3.11.1：GLB Gaussian 输入、超大 compressed PLY 与 SOG v3 HTML 同时打通

- **版本 / 一手来源**：[`v3.11.1`](https://github.com/playcanvas/splat-transform/tree/v3.11.1)，[package.json](https://github.com/playcanvas/splat-transform/blob/v3.11.1/package.json)；MIT，Node.js ≥22，依赖 `@adobe/spz 0.3.1`、`webgpu 0.6.2`。
- **GLB reader**：[PR #360](https://github.com/playcanvas/splat-transform/pull/360) 支持一个 embedded-buffer、`KHR_gaussian_splatting` ellipse primitive、`srgb_rec709_display` 的 GLB，并支持 indexed primitive；明确拒绝多个 Gaussian primitive、instancing、sparse accessor 与非 identity node transform。
- **大文件**：[PR #374](https://github.com/playcanvas/splat-transform/pull/374) 把 FileWriter 分成最大 1 GiB chunk，修复 compressed PLY 超过 2 GiB 时 Node `ERR_OUT_OF_RANGE`；报告样例为 4.77 GB，约 4800 万 SH3 splats。
- **HTML / SOG v3**：[PR #376](https://github.com/playcanvas/splat-transform/pull/376) 在 HTML 输出保留 model tag 并嵌入 SOG v3，避免 AA scene 过亮，同时保留 >1 opacity 与 SH4。
- **实际影响**：这是当前最值得回归的“标准化 GLB → 转换 → 可分享 HTML”路径，但 GLB reader 的结构约束很窄；生产导入前必须做拒绝案例与坐标/颜色空间测试。**可信度 A/B**。

## 2. SuperSplat / PlayCanvas 工具链

本轮的关键关系是：Editor #1097 产生/保留 AA model tag，Viewer 1.43.0 让 engine 自行处理 AA，SplatTransform 3.11.1 才把该 tag 与 SOG v3 带进 HTML。只升级一端可能仍出现过亮或重复补偿。

- **Editor / selection / picking**：WebMCP `render_view` 能输出 selection/property/layers，但没有宣称替换交互式 picking；`instance_layer` 共享静态 Gaussian 数据，主要降低重复场景资产内存，而不是通用 LOD。
- **Viewer / WebGPU / WebGL / XR**：1.43.0 的 Firefox 修复只覆盖 WebGPU FrameGate；LCC2/SPZ 直读与 stochastic AA 应分别做 Chrome/Firefox、WebGPU/WebGL fallback、XR 三组回归。PR 未声称 XR 已验证。
- **格式**：SOG v3 / SPZ v3-v4 / PLY model tag 形成较完整闭环；GLB 输入开始可用，但只支持单 primitive 的有限子集；glTF 多节点、instancing 尚不能视为落地。
- **LOD / streaming**：LCC2 是按需 streaming；维护者同时把文档中“octree”更正为 N-ary tree。不要把 SPZ 直读误写成 progressive streaming。
- **发布建议**：Viewer 1.43.0 与 SplatTransform 3.11.1 值得立即进 staging；SuperSplat Editor main 的 WebMCP / 排序 / AA 变更应以 commit 锁定测试后再用于生产。

## 6. Compression / Format / LOD / Streaming

1. **SOG/SPZ/PLY**：AA model tag 现可在 Editor 与转换器间贯通；Viewer 把 AA 决策交给 Engine。建议建立 SOG v2/v3、SPZ v3/v4、PLY tag 有/无的交叉矩阵。
2. **GLB/glTF**：SplatTransform 首次提供 `KHR_gaussian_splatting` 输入，但只覆盖单 embedded buffer / 单 ellipse primitive / identity transform；这是可测试的狭窄入口，不是完整 glTF scene graph 支持。
3. **超大数据**：1 GiB chunk 修复的是 Node 写出边界；它不减少 4800 万 splat 的总内存、传输量或排序成本。
4. **LOD/streaming**：LCC2 直读是真正的按需流式新增；SPZ 仍以整体资产读取为主。本窗口无新的通用 chunk protocol 或 MPEG/Khronos 正式标准表决。

### P2｜Mitigating SM-Level Load Imbalance in 3D Gaussian Splatting on GPUs

<!-- arxiv:2611.12319 -->

- **arXiv**：[2611.12319](https://arxiv.org/abs/2611.12319)；**论文无代码**。
- **核心**：persistent kernel 先调度重 tile，并把极端 outlier tile 选择性拆给多个 CTA；无需重训练或专用硬件。
- **口径**：作者报告大城市场景平均最高 2.93×、最不平衡帧 5.6×；尚缺 GPU、场景规模与独立复测的完整工程核对，暂不升 P1。

### P2｜DPGS-SLAM: Diffusion-Prior and Provenance-Aware Monocular Gaussian Splatting SLAM for Dynamic Visual Sensing

<!-- arxiv:2611.12038 -->

- **arXiv**：[2611.12038](https://arxiv.org/abs/2611.12038)；[代码仓库](https://github.com/guibao233/DPGS-SLAM) 当前为空，按**论文无可运行代码**处理。
- **核心**：SAM2 mask + 异步 diffusion inpainting + Metric3D v2；用 provenance 标签把生成 Gaussian 排除在 tracking / real-map optimization 外，真实观测到来时删除生成 primitive。
- **口径**：作者报告 TUM ATE RMSE 1.2 cm、BONN 2.7 cm，StaDy4D 对 WildGS-SLAM +4.60 dB；需代码、配置与硬件披露后复核。

### P2｜RefineSplat

<!-- arxiv:2611.10379 -->

- **arXiv**：[2611.10379](https://arxiv.org/abs/2611.10379)；**论文无代码**。
- **核心**：开放词汇 object track 生成独立 object-centric Gaussians，再以 reconstruction feedback 与 view-clustered embeddings 细化，面向可编辑/可查询对象资产。
- **价值**：若代码开放，可能补上语义对象从 2D track 到独立 splat asset 的工作流；当前仅研究信号。

### P2｜SHIN

<!-- arxiv:2611.10652 -->

- **arXiv**：[2611.10652](https://arxiv.org/abs/2611.10652)；**论文无代码**。
- **核心**：共享 Gaussian 顺序的 base + additive enhancement layers，并在新增 splat 与保留 SH 间分配预算，配合轻量 opacity 更新。
- **价值**：接近可渐进传输/多档质量表示，但尚无下载、随机访问格式与 viewer 集成，不能视为现成 streaming 方案。

### P2｜PLS-GS: Probabilistic LiDAR Scaffolds for Compact, Surface-Aligned Gaussian Splatting

<!-- arxiv:2611.10699 -->

- **arXiv / 代码状态**：[2611.10699](https://arxiv.org/abs/2611.10699)，[QUT / Emesent 仓库](https://github.com/k-harikumar/PLS-GS)；README 明示 WACV 2027，代码“coming soon”，根目录未见 LICENSE，按**有项目页但无代码/权重**处理。
- **核心**：相机 + LiDAR，使用 position/color hierarchical GMM 作连续 scaffold，把 Gaussian 约束在局部 surface frame，以 Mahalanobis support 贴近实测表面。
- **价值**：紧凑、表面对齐的大尺度 mapping 路线值得跟踪，但当前不可运行。
