## 2. SuperSplat / PlayCanvas 工具链

### SuperSplat：WebMCP 从场景操作扩展到可逆的 camera timeline

[commit 40697123](https://github.com/playcanvas/supersplat/commit/4069712370df3425c386610f28a814403e835543) 新增 `editor-timeline.ts`，把 `editor.inspect.timeline` 和 `editor.timeline.*` 接入 WebMCP command queue。五个新工具分别为 `get_timeline`、`set_timeline`、`set_keyframes`、`move_keyframe`、`delete_keyframes`。关键帧批量写入是单个 `AnimTrackEditOp`，因此一次 undo/redo 即可回滚；timeline 的 frame rate、loop、playhead 等设置不进入 history，但随 document 保存。

实现细节直接影响自动化稳定性：seek PLY sequence 时等待 `sequence.idle`；即使目标 frame 与当前相同也重新评估相机；移动关键帧默认用 `key_exists` 防止覆盖；frame 可缺省为当前 playhead；改变相机的结果附带新 `viewToken`。PR 记录 npm 39/39、浏览器 WebMCP 83 项检查并实际执行全部 29 个工具，覆盖 9 个 locale。限制也明确：没有 image/video rendering 工具，保存文件仍受浏览器 user activation/file picker 约束。

**实际影响**：Editor 的 selection、histogram、SOG/SPZ/PLY 导入导出、SplatTransform 与 Viewer runtime 没有同时改变；新增价值集中在“外部 agent 可程序化建立和调整相机动画”。相机 path、帧率、loop 与 sequence frame 现在可以纳入自动化回归，但最终 viewer export、渲染输出和发布 API 仍需现有流程。当前版本号仍是 3.7.0，建议测试 main SHA，不要把它写成正式 3.7.1。

### Engine：beta.27 与 XR 恢复并非同一个交付边界

[2.24.0-beta.27 version commit](https://github.com/playcanvas/engine/commit/c012d4f7150fc0afd39d7712ad38e8241a25e1ab) 将 10 月 31 日已归档的 LCC2 runtime parser 与 hierarchy-cut LOD 纳入固定 beta；这让大型 XGRIDS/SOG 场景可从“跟 main SHA”转为“锁 beta 版本”测试。它不等于稳定版，也不改变 SOG/SPZ/PLY 格式。

[XR recovery commit](https://github.com/playcanvas/engine/commit/c4ead5541e9a95fdc3a8edd1ac006c9772f99057) 晚于 beta.27。Quest Browser 休眠后 projection layer texture 丢失时，Engine 清空同帧 partial subImages、重建 `XRWebGPUBinding` 与 projection layer、恢复 fixed foveation；第二次连续失败快速恢复，持续失败时每 60 帧重试，避免每帧反复建层。对 SuperSplat Viewer 的 WebGPU stochastic stereo、Quest resume、Vision Pro 等场景是稳定性修复；建议做 enter XR→sleep/wake→双眼画面/深度/抓取/退出重进的长测，生产等待下一个版本边界或锁此 SHA。

## 3. 可实际运行的开源项目

### LichtFeld：让预留容量不再等同于立刻占满物理显存

[f5e58a26](https://github.com/MrNeRF/LichtFeld-Studio/commit/f5e58a26c687ea026330f604c00cdd12de9e8090) 引入 `LazyDeviceStorage`：per-splat arrays 可保留稳定虚拟地址，物理 CUDA pages 随模型增长分段提交，最小预留 8 MiB，arena 以 64 MiB 片段扩展。VRAM governor 根据 refine/rasterizer 的实测需求限制增长；分配失败会先 trim caches、释放 ahead pages，再重试直接 CUDA allocation。cell grid 还增加边界，避免极端空网格如 1024³ 直接消耗约 8 GiB。

训练中 checkpoint 现在优先把 bands 复制到空闲 VRAM，设备复制完成即恢复训练，后台线程再搬往 host；final/emergency save 保留原 ring path。跟进 [625cc6e3](https://github.com/MrNeRF/LichtFeld-Studio/commit/625cc6e31a3fd81402173fd944346faea2eb7213) 修复回收 lazy CUDA storage 时活跃尾页被错误丢弃，说明首个 SHA 不应单独部署。建议同时测低余量 VRAM densification、连续 autosave、取消保存、OOM retry、模型增长/缩减和训练结果一致性。commit 没有统一 GPU、场景、splat 数与 pause 数据，不能宣称固定节省比例。

### LichtFeld Idol plugin：可运行，但许可证与显存门槛高

[lichtfeld-idol-plugin](https://github.com/lyehe/lichtfeld-idol-plugin) 把 Speridlabs Idol 嵌入 LichtFeld：图像先去背景/裁切，生成 Gaussian 后进入 scene graph，支持 placement gizmo、progress/cancel、重新 decode、PLY 保存，并在训练时卸载模型。README 给出约 66K–1M Gaussians detail 档；上游示例约 262K 需要 7.2 GB VRAM，约 7 GB 权重，NVIDIA compute capability ≥8.0，PyTorch 2.11/cu130。首次 `torch.compile` 更慢且有 eager fallback；embedded Python 下禁用 Xet 以避开 hang。

插件代码 MIT、vendored Idol Apache-2.0，但 DINOv3 与 FLUX.2-dev 是 gated weights，FLUX.2-dev 非商用。适合本地研究原型与视觉预览，不应直接标记为商业生产可用。

### Gaussian-Splat-Lite：优先回归重复加载和显存/堆释放

[ed22eae7](https://github.com/WilliamLiu-1997/Gaussian-Splat-Lite/commit/ed22eae77bc741bef7662918a472891d325c5238) 将 projected splat 编码统一为 32-byte record，打包 half RGB、kernel power 与 float alpha/radius，native WebGPU 顶点阶段少做重复准备；resize 时复用 `StorageBufferAttribute` 身份，避免旧 material/pass 继续抓住过期 CPU array。[808dbfb3](https://github.com/WilliamLiu-1997/Gaussian-Splat-Lite/commit/808dbfb3fc2bd8faa9df1ad9208df2933cd9c564) 让 source/index/SH/opacity texture 的 dispose 同时清空 backing data，并在 targetCount=0 时清除 projection cache binding。

画面语义宣称不变，但没有作者 benchmark。测试应循环加载/删除 PLY、SPZ、SOG、RAD，分别记录 JS heap、ArrayBuffer、GPU buffer/texture 数、首次 pipeline compile 与稳定帧时间，并比较 WebGPU/WebGL2。main 仍未形成新 tag，生产先锁 SHA。

## 5. Viewer / Editor / Web / Mobile / XR

- **Editor / agent workflow**：SuperSplat WebMCP 现在能构建、移动、删除 camera keyframes，并读取/设置 timeline。最有价值的回归是 agent 建 path→undo/redo→保存/重载→seek PLY sequence→比较 camera/view token。
- **Viewer / XR**：PlayCanvas WebGPU XR 的 projection layer 自恢复直接面向 Quest sleep/wake 黑屏；当前需 Engine main SHA，Viewer 1.42.0 本身未发新版本。测试必须覆盖双眼、foveation、深度清除和 session 重进。
- **WebGPU**：GSL 继续把 projection-ready 数据前移和压缩，并修补 disposal。没有 WebGL2 feature 新增；fallback 只需做兼容性/资源释放回归。
- **Mobile**：本窗口无新的原生 iOS/Android Gaussian SDK。Quest Browser 是移动 XR 运行时，不能把 XR 修复外推为手机浏览器性能提升。

## 6. Compression / Format / LOD / Streaming

本日没有新格式标准或压缩率突破；变化是实现与交付边界：

- **LCC2 / SOG LOD**：Engine beta.27 将昨日 LCC2 runtime 与 hierarchy-cut LOD 固化为 beta 版本；格式、预算语义和网络行为不因版本提交再改变。
- **SOG v3**：仍是 [issue #362](https://github.com/playcanvas/splat-transform/issues/362) 提案，未在本窗口 merge/release。opacity>1、24-bit rotation、SH4、blind data 与 extras 不得写成默认格式已切换。
- **PLY/SPZ/SOG/RAD**：GSL 更新 renderer cache/disposal，不改变格式版本或互转语义。
- **Streaming**：SuperSplat WebMCP 的 sequence seek 等待 frame idle 是自动化正确性变化，不是网络 chunking/LOD 算法。

窗口内未核实到 Khronos glTF Gaussian extension、OpenUSD、3D Tiles、MPEG GSC、W3C WebGPU、SPZ 或 SOG 的新批准版本。没有可核对 GPU、分辨率、场景与质量口径的“10×/100×”新声明。

## 7. Training / Reconstruction / SLAM / Robotics / Mapping

### visloc-rs：未知深度必须保持“未知”

[6fbabc85](https://github.com/rsasaki0109/visloc-rs/commit/6fbabc8558fc39873ce6b46d2ac7b75dd386f0de) 修复 GPU TSDF 在 depth-maps-only 模式把 0 深度当作 near-space measurement 的语义错误：override map 现在用 -1 表示 unknown，integration 跳过；depth map 模式的 `--min-component` 默认也调为 0。作者在六场 ETH3D 的 2 cm F1 数据给出整体改善，但 office/pipes 退化说明部分旧 carving 曾顺带清除错误深度。建议按场景保留门控，复测 holes、sky、reflective regions 与 mixed MVS+GS。

[642b6ccd](https://github.com/rsasaki0109/visloc-rs/commit/642b6ccdbd98ee0a6be6cdb3c356d5df7abe6c82) 为 Insta360 `.insv` 加两阶段标定：首次重建在两个 lens pixel space 内联合优化光心、焦距与后镜头 pose，使用 SIFT seam matches；第二次按保存的 `--insv-lenses` 切 faces。3 条路线中两条 median track error 改善、一条从 0.307 m 变差到 0.340 m，且尺度会变化，必须作为 opt-in 校准。

固定检查 gsplat、OpenSplat、graphdeco-inria/gaussian-splatting 与主要 Gaussian SLAM/robotics/mapping 仓库，窗口内没有新的正式 release、训练 kernel、权重首发或能改变工作流的 merge。

## 13. 今天最值得实际测试 / 部署

### 1) SuperSplat WebMCP camera timeline

- **为什么**：首次把相机关键帧编辑纳入浏览器原生 agent 工具，并保留一次 undo、document save、sequence-frame 等工程语义。
- **门槛**：SuperSplat main `40697123`、Node ≥20.19、支持 WebMCP 的 Chrome、WebGPU；准备静态 PLY 与 PLY sequence。
- **测试**：29 tools smoke；set/move/delete keyframe；overwrite guard；same-frame seek；sequence idle；undo/redo；保存/重载；locale；viewToken；最终 viewer export 仍走现有路径。
- **预期收益**：相机路径搭建、修订和回归可自动化；不承诺自动生成最终图片/视频。

### 2) LichtFeld lazy VRAM + checkpoint pipeline

- **为什么**：同时命中训练容量与 autosave 停顿两个真实瓶颈，并有紧随其后的尾页正确性修复。
- **门槛**：NVIDIA/CUDA，LichtFeld master 至少包含 `f5e58a26` 和 `625cc6e3`；准备 8/12/24 GB GPU 与会持续 densify 的大场景。
- **测试**：峰值/稳态显存、commit pages、grow/shrink、cache relief、OOM retry、autosave pause、连续保存、取消/退出、最终模型 hash/质量。
- **预期收益**：降低“大容量预留即物理占满”的风险并缩短训练中保存阻塞；具体幅度必须由目标场景实测。

### 3) PlayCanvas WebGPU XR suspend/resume

- **为什么**：直接修复 Quest Browser 睡眠后 projection texture 丢失导致黑屏的现场问题。
- **门槛**：Engine main `c4ead554`、Quest Browser/WebGPU WebXR，最好同时有 Vision Pro 与 WebGL2 对照。
- **测试**：连续 20 次 sleep/wake、单双眼 subImage、fixed foveation、framebuffer scale、depth clear、手势/控制器抓取、session exit/re-enter、renderer fallback。
- **预期收益**：减少 XR 长会话和设备唤醒后的黑屏；beta.27 不含此修复，正式部署需锁 SHA 或等待后续版本。
