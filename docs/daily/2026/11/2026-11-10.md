### P0｜SPZ v4 以 zstd skippable frame 增加任意逐点属性，并保持旧 v4 reader 可读

- **时间 / 一手来源**：2026-11-09；[Niantic SPZ PR #107](https://github.com/nianticlabs/spz/pull/107)，merge commit [`b56333f`](https://github.com/nianticlabs/spz/commit/b56333f5135c7ce4026a1237fcb227d35f8a6557)。
- **新增**：在核心 SPZ stream 后追加 zstd skippable extension frames，可存任意数量、命名的逐点属性；支持 C++、Python、JS/WASM API。属性可为 32-bit 或 1–8 bit 量化，适合 normals、materials、embeddings 等。

## 2. SuperSplat / PlayCanvas 工具链

### SplatTransform：SOG v3 的代码与架构变化

- **编码层**：opacity 从内部 logit 路径转成 linear，允许 decimation 产生 `>1` 的 mass-preserving opacity；v3 byte 映射为 `(b/204)^2`，上限 1.5625。PLY 用 `opacity_linear` 保留该语义；`--ply-logit-opacity` 会 clamp 并警告；compressed PLY、`.splat`、SPZ、GLB、voxel 等只能表达标准 opacity 的路径会 clamp 到 1。
- **渲染层**：过 1 opacity 生成 opaque core 和拉伸边缘以保持质量；`--no-compensation` 可关闭。抗锯齿场景缩放按 `sqrt(det Σ / det(Σ+filter))`，默认 0.1 px²；还能识别 Postshot 的 `postshot.anti_aliasing=1` comment。
- **数据层**：blind data 支持 u8–u32、f16/f32、unorm8/16 及范围，多字段可共存；SH4 已进入 PLY、SPZ、rotation、rendering，但 compressed PLY / GLB 会降到 SH3。
- **兼容建议**：Editor/Viewer 尚未全部证明兼容 v3 前，不要批量覆盖既有 v2 资产；持续发布 web viewer 的团队应先做 v2/v3 双工件与错误提示。文档修正 [PR #371](https://github.com/playcanvas/splat-transform/pull/371) 只是把 `--filter-harmonics` 参数范围补到 4，已并入同一事件。

### SuperSplat Editor：device loss 现在可恢复

Editor 的压缩 GPU device 与主渲染 device 分离；`devicelost` 后会销毁并丢弃 compression device cache，异常映射为 `GpuDeviceLostError`，用户看到本地化 retry 提示。它不改变 selection/picking、camera/path、shared viewer settings 或发布 API，但直接改善大场景 viewer export / SOG export 的稳定性。

## 6. Compression / Format / LOD / Streaming

今天的格式信号是两条互补路线：

1. **SOG v3** 把 WebGPU 友好的纹理容器做得更自描述：rotation、opacity、SH4、palette、extras 和 blind data 全部进入同一生态；但默认升级带来读者兼容性成本。
2. **SPZ v4 extension** 把额外逐点属性放进标准 zstd skippable frame，旧 reader 可忽略，部署风险更低；但使用方必须明确是否编译 extension support，否则读写链路会丢掉附加属性。

二者都在解决“GS 不再只是 position/scale/rotation/color/SH”这一现实。对 LOD/streaming 而言，本轮没有新的随机访问索引、chunk protocol 或正式标准落地；SOG palette 和 SPZ frame size 的优化仍主要是编码/内存改进，不应宣传成完整 progressive streaming。

## 7. Training / Reconstruction / SLAM / Robotics / Mapping

- **X-ray reconstruction**：X-Gaussian 是今天最完整的新增数据路径。建议先复现 held-out projection，再把 full-view FDK 当作“强基线伪参考”而非 ground truth 解读。
- **Training kernel**：visloc-rs #500 的 backward 改动质量差异落在 run-to-run spread；价值是缩短训练而非提高 PSNR。

## 13. 今天最值得实际测试 / 部署的项目

1. **SplatTransform SOG v3 + SuperSplat export recovery**
   - **为什么**：这是直接影响生产导出格式和 Mac 大场景稳定性的组合；兼容性风险也最高。
   - **门槛**：Node.js + WebGPU；准备一份含 SH、低 opacity、标签/自定义属性的大场景；同时输出 v2/v3。
   - **验证目标**：旧 viewer 是否拒绝/降级；SOG v3 体积、PSNR、过 1 opacity 边缘；device loss 后 retry；627K+ splat 是否仍触发 watchdog。

2. **SPZ custom attributes**
   - **为什么**：无需破坏旧 v4 reader 就能携带 normals/material/embedding，最适合做跨工具链原型。
   - **门槛**：CMake/C++ + zstd；或 Python/JS/WASM API；需要同时构建 extension on/off 两条 reader。
   - **验证目标**：有/无 extension 的核心 cloud byte-equivalence、未知字段忽略、属性 round-trip、16 MiB frame 的峰值内存和 Android/WASM 构建。

3. **X-Gaussian 真实扫描包**
   - **为什么**：数据、权重和 config 同时公开，能把 CT GS 的判断从合成论文图转为真实 held-out projection。
   - **门槛**：Linux、NVIDIA CUDA 11.8、PyTorch 2.1.2、GCC 11；环境较老，建议容器隔离；许可未明确，先限研究评估。
   - **验证目标**：复现 2D held-out 指标、量化 FDK 初始化与 culling 的时间/显存；将 3D FDK 参考明确标为 pseudo-reference。

---

**今日判断**：有 2 项可能改变格式工作流的重大新增（SOG v3 默认、SPZ v4 custom attributes），以及多项可立即测试的稳定性/性能更新。最优先不是追新论文，而是建立 SOG v2/v3 与 SPZ extension 的兼容性矩阵，并在真实 Mac / WebGPU / WASM / Android 路径上验证。
