## 重点正文

### SuperSplat 开始把 GSAF 动态高斯当作可编排时间线

[SuperSplat PR #1108](https://github.com/playcanvas/supersplat/pull/1108) 于 11 月 14 日北京时间合并，对应提交 [`b4f3b25`](https://github.com/playcanvas/supersplat/commit/b4f3b2557f8761170150f4766fa08c3ddcdfd5c5)。编辑器现在可从拖放、文件选择器、Recent Imports 和 `?load=` 导入 `.gsaf`，通过随仓库提供的 GSAF 2.8.5 WASM 解码器把各帧转为内存中的 binary PLY。用户可以选择把文件作为序列导入，也可以展开成独立场景。

这项更新解决的是“动态资产如何进入编辑器并与其他段落一起编排”。多段序列可以同时播放；较短序列在末帧停住；播放中加入的新序列从当前播放头开始；删除序列也会从时间线状态中移除。视频导出会暂停实时播放，对所有发生变化的 splat 重新排序，修正 360° 导出在帧切换和截屏间竞态导致的错帧。维护者在旧实现中观察到 78 个 cubemap 面里有 57 个取错帧。

边界同样明确：这是主干合并，不是新 tag；维护者测试了 251 帧 GSAF 和 PLY 序列，但没有直接测试真实操作系统拖放，也没有观看最终导出的视频文件；PWA manifest 尚未声明 `.gsaf`，安装后的应用不能靠系统“打开方式”接管文件；vendored decoder 也没有公开重建脚本。**判断：P1，可实际测试；MIT，Node.js ≥20.19、WebGPU/WebGL；可信度 B。**

### LichtFeld Studio 加入非破坏式裁剪，编辑结果可以延后烘焙

[LichtFeld Studio PR #3886](https://github.com/MrNeRF/LichtFeld-Studio/pull/3886) 合并为 [`ee6d3cb`](https://github.com/MrNeRF/LichtFeld-Studio/commit/ee6d3cb617b8c45054247c1dd87291da454f44f5)。用户可对单个 splat 场景添加盒体、椭球和多边形裁剪，多个裁剪相交生效，每个裁剪可独立启停，也可反转为排除区域。裁剪以虚拟的 `Crop (N)` 容器出现在场景树中，保存进项目，支持撤销、剪贴板和选择；只有执行可撤销的 Bake 后，点才真正被删除。

此前常见裁剪动作会直接改写资产，一旦想比较不同边界或找回误删区域，就需要重新导入。新方案把“看见什么”与“永久删除什么”拆开，更适合清理扫描边缘、生成多个交付范围和做客户复核。GPU 侧改为动态裁剪数据，不再受固定裁剪数量限制。

当前只支持单个 splat 对象，组或混合选择的裁剪被禁用。维护者在 Windows Release、MSVC、CUDA 12.8、RTX 5060 Ti 上完整测试；Linux 只验证 Debug 格式目标，不等同于全应用 GPU 测试。**判断：P1，可实际测试；GPL-3.0、原生 CUDA 构建；可信度 B。**

### LichtFeld 用文字选对象，但必须保留人工确认

[LichtFeld Studio PR #4057](https://github.com/MrNeRF/LichtFeld-Studio/pull/4057) 合并为 [`5af1d7a`](https://github.com/MrNeRF/LichtFeld-Studio/commit/5af1d7a56f6c0687c1b3cc48bad3c787c27d319c)。SAM 2.1 遮罩编辑器现在可输入英文对象描述或使用预设类别，由 LLMDet Tiny 给出候选框，再合并为遮罩供用户检查。检测不会自动应用；当前帧确认后，可以沿用现有跟踪流程向后传播。

工程上，它使用原生 CUDA 神经网络算子，不依赖 Torch 或 ONNX Runtime；模型压缩包从 LichtFeld 官方 release 下载，下载后校验 SHA-256，模型许可标为 Apache-2.0。对大型采集而言，这把“逐帧点选车辆、人物、天空等区域”变成“描述—候选—确认”，但不是可靠的自然语言分割服务。

限制包括：只在当前帧重新检测，跟踪不会在目标离开又返回时自动找回；高分不保证正确，不存在的类别仍可能误匹配；运行路径依赖 CUDA。**判断：P1，研究级可实际测试；GPL-3.0 主程序、Apache-2.0 模型；可信度 B。**

### Leica MANTIS 把现场相机跟踪与三维采集放到同一套设备

Hexagon 于 11 月 12 日发布 [Leica MANTIS](https://hexagon.com/about/news-media/press-releases/2026/hexagon-launches-mantis-to-capture-3d-scene-data-as-cameras-roll)，本期按事件日期补收。设备安装在拍摄相机上，在拍摄过程中同步记录场景几何与相机运动；配套 MANTIS Studio 输出经 LiDAR 修正的深度图、相机轨迹、位置数据和点云，文件包括 EXR、FBX 与 Alembic。

它针对的是虚拟制片和视觉特效中“拍完以后再重建现场、再估相机”的时间与误差。若输出能稳定对齐，团队可把实拍镜头、深度和相机轨迹更早送入合成、扫描重建或空间内容管线。官方在 11 月 12—15 日的 Infinity Festival 展示，计划 2027 年第一季度出货；价格、支持机型、精度、数据率和现场基准尚未公布，也没有理由把它写成已交付产品或高斯专用设备。**判断：重要行业产品，发布前预告；商业闭源；可信度 A。**

### MatrixSplat 把高维高斯特征渲染改写为 Tensor Core 矩阵运算

[MatrixSplat（arXiv:2611.15153）](https://arxiv.org/abs/2611.15153) 面向语义、语言或中间特征等高维属性，不再把每个 Gaussian 对每个像素的贡献逐项累加，而是组织成适合 Tensor Core 的矩阵乘法，并使用与顺序无关的加权聚合。论文列为 NeurIPS 2026，作者报告相对原始 3DGS 最多 3.8 倍、相对 TC-GS 最多 2 倍；高维特征 kernel 最多 36.7 倍；接入其他快速渲染器时又有 1.69—2.84 倍。

这些数字来自 Mip-NeRF 360、LERF 和 3D-OVS 等论文设置，不能外推为所有 3DGS viewer 的整体帧率。更关键的是，它改变了透明度合成方式，换取并行性；颜色与特征质量必须与原顺序相关渲染分别比较。当前未找到官方代码或权重。**判断：P2，论文无代码；可信度 A（原论文），性能待复现。**

## 简讯

### SuperSplat 多文件导入不再被一份无关文件拖垮

[PR #1107](https://github.com/playcanvas/supersplat/pull/1107) / [`c2ac898`](https://github.com/playcanvas/supersplat/commit/c2ac89897cfd697ad41376e5fc2da94e3b5e98d4) 重做多文件导入审阅：PLY 序列、SOG、LCC、项目文件和 companion files 会正确分组；夹杂一份不支持文件不再让整批失败；拖放遮罩可阻止浏览器把数百个文件分别打开。真实系统拖放以及 SOG/LCC 的最终加载仍未完整测试。

### PlayCanvas Engine 修复设备恢复后高斯阴影变白

[Engine PR #10021](https://github.com/playcanvas/engine/pull/10021) / [`ae62fc8`](https://github.com/playcanvas/engine/commit/ae62fc81c67d66397892fac3580cfd55036219b4) 修复 WebGL2 和 WebGPU 图形设备丢失后高斯阴影保持白色的问题。WebGPU GPU sort 会在工作缓冲重建后重传 interval 数据；CPU sort 保留最后一次顺序，在设备恢复的首帧重新应用，避免缓存阴影在 splat 数据恢复前被错误重绘。CPU 路径因此常驻一份 order-sized 缓冲。

### Viewer 把注释创作上限从 25 提高到 50

[SuperSplat Viewer PR #366](https://github.com/playcanvas/supersplat-viewer/pull/366) / [`964770e`](https://github.com/playcanvas/supersplat-viewer/commit/964770ec03021f92895e81f3a188b19e31819994) 将 authoring validation 的注释上限从 25 提高到 50。Viewer 本来就能渲染超过 25 条，变化只影响新导出的配置；标题和正文长度上限不变。它对导览、工地标注和作品解说有直接价值，但尚未发新 tag。

### LichtFeld 用 e-means 缩短部分 SOG 球谐导出

[LichtFeld PR #4061](https://github.com/MrNeRF/LichtFeld-Studio/pull/4061) / [`1c4d481`](https://github.com/MrNeRF/LichtFeld-Studio/commit/1c4d481a6cc53b984cb2b83c6dd7e5c437c0224b) 将 SOG 高阶球谐调色板的 k-means 换为 [e-means](https://arxiv.org/abs/2611.09501)，固定 10 轮并保证确定性。作者在 RTX 4090、4 个场景、每项 3 次测试中报告 SH1 总导出时间约降 46%、SH2 降 63%，SH3 基本不变或慢约 1%；瓶颈会转到图像编码，不能概括成所有 SOG 导出都提速。峰值 GPU 内存按 SH1/2/3 分别少 29/96/256 MiB。

### Niantic Spatial 展示不依赖专门扫描的城市级定位

Niantic 11 月 12 日的 [Putting Physical AI in its Place](https://www.nianticspatial.com/blog/physical-ai-in-its-place) 将地面相机画面与卫星图和数字地图匹配，返回带校准不确定度的位置与朝向候选，并可与 SLAM、IMU 或里程计融合。当前公开能力是定位，不是直接返回完整三维场景；更丰富的重建和语义整合仍属后续方向。本期按事件日期补收。

### Prevu3D 为 Gaussian splat 加入轮廓显示

Prevu3D 11 月 12 日的 [2026 Release Notes](https://doc.prevu3d.com/en/release-notes/2026/) 写明 Gaussian splat 现在可显示 outline，包括 RealityComposer 中的资产。这是商业软件更新，官方未给独立版本号、性能数据或价格变化；本期仅按发布说明记录，未进行软件实测。

## 论文与研究

### TopoEgo：让 4D 高斯表示物体分裂、融合与开合

<!-- arxiv:2611.16012 -->

[Topology-Aware 4D Gaussian Splatting for Egocentric Videos（arXiv:2611.16012）](https://arxiv.org/abs/2611.16012) 把场景拆为部件级刚体运动，并用随时间变化的 Gaussian 激活状态表示物体断开、合并、打开或关闭。它针对传统连续形变场难以表达的拓扑变化，项目页为 [TopoEgo](https://topoego.github.io/)。页面写明代码与数据“将公开”，截至本次核查仍按论文无代码处理。

### ReCan-GS：把稳定场景和视角相关干扰分开重建

<!-- arxiv:2611.16259 -->

[Reconstruct What You Can: Distractor-free 4D Gaussian Splatting（arXiv:2611.16259）](https://arxiv.org/abs/2611.16259) 以形变对参数的 Jacobian 敏感度，把跨视角一致的核心与每个视角的干扰 Gaussian 分开，目标是去除遮挡物、反射、烟雾和薄雾，无需外部分割器或人工 mask。作者页列为 WACV 2027；未找到官方代码或权重。

### Kosmo-GFM 把几何预测、位姿优化和重建数据组织成生产管线

<!-- arxiv:2611.16840 -->

[Kosmo-GFM: A Production-Ready Geometry Foundation Model（arXiv:2611.16840）](https://arxiv.org/abs/2611.16840) 由 GFM 预测相机、深度、对应关系与动态点，PoseEngine 再优化场景位姿和几何，KosmoWorld 提供重建监督。作者在 34 个场景上报告 PoseEngine 累计 14.07 小时，对比 GLUEMAP 69.67 小时；Flash 变体为 2.62 小时。这是作者的跨场景汇总，不是独立测评，也未找到公开代码。

### ThermalSplat：不依赖 RGB 与已知位姿的稀疏热成像重建

<!-- arxiv:2611.15435 -->

[ThermalSplat（arXiv:2611.15435）](https://arxiv.org/abs/2611.15435) 从稀疏热红外图像直接前馈生成 Gaussian，不要求 RGB、预先计算的相机位姿或逐场景优化，并加入 soft census 与边界损失来适应热成像的低纹理和强度差异。它可能减少消防、巡检和夜间采集的前处理，但当前未找到官方代码、权重或设备实测。

### MatrixSplat：高维特征渲染的矩阵并行路径

<!-- arxiv:2611.15153 -->

[MatrixSplat: Tensor-Core Matrix-Parallel Gaussian Splatting（arXiv:2611.15153）](https://arxiv.org/abs/2611.15153) 以矩阵乘法和顺序无关的加权聚合加速高维特征渲染。论文提供多组作者 benchmark，但未公开可运行实现；对语言高斯、开放词汇语义与大通道特征图最值得跟踪，普通 RGB viewer 不应直接套用其倍数。

## 相关深读与行动建议

1. **先测试 SuperSplat GSAF 时间线，而不是直接升级生产编辑器。** 用一段短 GSAF、一段长 GSAF 和 PLY 序列验证并行播放、暂停、跳帧、删除、360° 导出和普通视频导出；记录浏览器、GPU、帧数、首帧时间、内存和导出错帧。当前应锁 `b4f3b25`，等待正式 tag 再评估生产迁移。
2. **把 LichtFeld 裁剪与文本选区作为两个独立实验。** 裁剪实验重点验证项目保存、撤销、Bake 和多裁剪交集；文本选区重点测误检、漏检、目标离开再进入以及显存。两者都在主干，且都依赖原生 CUDA 路径。
3. **影视或现场扫描团队应跟踪 MANTIS 的交付参数。** 现阶段能做的是向供应商确认价格、支持机型、同步方式、LiDAR 范围/精度、数据率、EXR 深度定义和 FBX/Alembic 坐标约定；在这些参数公开前，不能把发布会演示当作已验证生产能力。
4. **高维语义渲染团队可优先复现 MatrixSplat。** 对比时必须固定 GPU、分辨率、Gaussian 数、通道数、质量指标和基线，并单独报告 kernel 时间与端到端帧时间；顺序无关加权带来的画质变化需要可视和数值两套检查。
