## 3. 可实际运行的开源项目

### GSPIM：论文数字可审计，但硬件收益仍是研究模型

[GSPIM 仓库](https://github.com/MAdrid1011/GSPIM) 提供 `python -m pip install -e '.[cuda]'`、`python -m gspim.demo --prepare` 与 `python -m gspim.demo` 的路径；prepare 会下载公共数据与 Ex4DGS 模型、预处理图像并检查提供的 1K/Anchored checkpoints，默认评估 12 个 workload/scene 组合并生成 Markdown 报告。源码含 CUDA、三类表示 adapter、PIM/HCF/RTL、reference model、tests 和 docs。

论文在三类 4DGS 表示与六个动态场景上报告几何平均 4.15× speedup、4.99× energy efficiency、最大 scene-level PSNR 差 0.011 dB，新增电路面积为 32 个 LPDDR5 die 合计 18.7172 mm²。工程上应先跑软件 reference 与 workload adapter，再把论文的模型结果与实际 Jetson/GPU profiler 分开记录。

### visloc-rs：浏览器端相机求解与显示形成完整前后段

[commit f8db6144](https://github.com/rsasaki0109/visloc-rs/commit/f8db6144b65f5476fff6b5c5b152f60aa90bb212) 新增 WASM/WebGPU viewer；[commit 0e0ff918](https://github.com/rsasaki0109/visloc-rs/commit/0e0ff9185e9372e8d3615b5ceef3070f55ceadc6) 增加无阻塞 async render 并做 bit-for-bit parity test；[commit fb408185](https://github.com/rsasaki0109/visloc-rs/commit/fb408185310335c64905b2fb37ed77509442d44c) 修复 GitHub Pages gzip 下 `Content-Length` 是压缩长度、错误预分配 splat buffer 的问题，作者以 headless Edge 验证 600k Gaussian 正常加载。

[commit ef9ae152](https://github.com/rsasaki0109/visloc-rs/commit/ef9ae1522dfa519b773f6c5f4544da0e40ed1dbe) 则把 photo SfM 编译到 WASM worker。两者合起来是“浏览器本地求相机 → 导出 PLY/JSON → 查看已训练 splat”的可测试链；训练仍在 `gsplat_train_cuda` 等离线工具完成。官方样例数据 ETH3D courtyard 为 CC BY-NC-SA 4.0，商用流程不要把样例许可误当代码许可。

## 4. 4D / Dynamic Gaussian

- **GSPIM**：支持显式 4D Gaussian + contribution mask、Ex4DGS keyframe 与 anchor+decoder 三类表示；真正新增价值是统一 workload adapter 和 temporal-locality/PIM 研究 artifact，不是新 4D 表示。
- **Phase-DGS**：[arXiv:2611.04666](https://arxiv.org/abs/2611.04666) 用冻结 DINOv2 与轻量 MLP 从图像内容估计 [0,1] phase，替换 4DGS backbone 的 timestamp。项目页给出 10% random drops、5–10 帧 freezes、20–30 帧 offsets 条件；代码尚未公开。<!-- arxiv:2611.04666 -->
- **egsc-4d-player**：[commit 6cf320ae](https://github.com/Hliii/egsc-4d-player/commit/6cf320ae3d237dc439c4508d83a92a8e7eea1d58) 把默认场景换成 bartender SH0 pruned：896,483 点、13.6MB、held-out 约 29.7dB；维护者同时说明它低于此前 scene-v9 的 10.25MB/38.3dB。这是明确质量回退/取舍，不应把新默认误写成改进。

## 6. Compression / Format / LOD / Streaming

[GSCV++](https://arxiv.org/abs/2611.05359) 将 GS sequence 映射到标准视频 codec：EA-SHDR 做跨帧 SH AC 降维，P-MiniPLAS 生成更平滑 2D feature maps，CA-GC 用非均匀 bit depth 与 coding-unit selection。论文称相对 SOTA 的 intra/inter rate-distortion gain 超过 20%/60%，且 mapping/encode/decode 更快；但摘要未给代码、codec profile、硬件或可直接下载 bitstream，暂为论文无代码。<!-- arxiv:2611.05359 -->

[3DGS-VBench+ / 3DGSV-Assessor](https://arxiv.org/abs/2611.04498) 提供未来压缩评测的重要基线：3,036 个重建、11 个真实 + 22 个合成场景、6 种压缩算法、9,108 个 overall/geometry/color MOS；模型支持 reduced-reference/no-reference。论文写明代码/数据 “will be released”，所给仓库截至窗口结束不可访问，不能按数据集已发布处理。<!-- arxiv:2611.04498 -->

SplatTransform 的 rasterizer 清理不改变 SOG/SPZ/PLY 编码；compressed PLY、glTF KHR_gaussian_splatting、OpenUSD、3D Tiles、MPEG GSC、WebGPU 标准本窗口未核实到新批准版本。11 月 2 日 Khronos 说明性内容在窗口外且不是新规范版本，不重复计入。
