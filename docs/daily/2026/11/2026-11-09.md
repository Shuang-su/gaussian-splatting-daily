### PlayCanvas Engine

- [PR #9977](https://github.com/playcanvas/engine/pull/9977) 把多个只参与数值计算的 StandardMaterial 常量改为始终使用 uniform。作者的 54 个 glTF 模型、358 个材质测试中，调节 refractionIndex 原先会新增 81 个 WebGL2 shader，修改后为 0；occludeSpecularIntensity 为 87→0。启动时 WebGL2 program 138→132、WebGPU 203→198。代价是相关材质每像素增加少量标量指令；这是作者测试，不应外推成 Gaussian 渲染 FPS 提升。
- [PR #9978](https://github.com/playcanvas/engine/pull/9978) 阻止仅 uniform 数值变化时清空 shader cache。对带 mesh UI、透明过渡或材质动画的 splat 场景，收益是减少主线程和 GPU 资源重建抖动。
- **架构影响**：两项变更位于 StandardMaterial、LitMaterial、shader option builder 与 material cache 层；没有触碰 GS projection、radix sort、SOG/SPZ 解码、LOD scheduler 或 splat draw path。
- **兼容性**：StandardMaterial#specularityFactorTint 被移除；旧资产在 debug build 记录 removal message，行为等价于始终为 true。若发布页自定义了该 API，应先回归。
- [2.24.0-beta.35](https://github.com/playcanvas/engine/commit/597f7e999acc8f1298d96e74d3e4a2e1294b58ba) 仅是本窗口内的 beta 打包节点；没有新增 GS 功能，不重复计数。

- **新价值**：把训练前视频数据清洗和跨进程训练观察直接放回 Gaussian Editor，减少外部 segmentation、文件轮询和 Blender/LichtFeld 间的人工切换。

## 7. Training / Reconstruction / SLAM / Robotics / Mapping

### SAM2.1 序列掩码

- [PR #4017](https://github.com/MrNeRF/LichtFeld-Studio/pull/4017) 复用现有 mask_video_sequence 与 SAM2.1 temporal inference，没有引入第二套 tracker。用户在抽帧序列中设定 seed 和范围，可前向、反向或双向传播。
- 手工 keyframe 与已批准帧在后续传播跨越时受保护；编辑会撤销 approval，但保留已保存 mask，直到用户显式覆盖。
- filmstrip 区分 proposal、低置信和已批准状态；范围批准是一个共享 undo step。只有批准帧被原子写入；取消或后续失败不回滚已经完成的 export。
- proposals 有内存上限且只存在于当前 session；关闭或替换序列后不恢复。运行前要确认 video-capable weights、抽帧采样间隔和 keep/exclude 语义。

### 外部训练观察

- [PR #4008](https://github.com/MrNeRF/LichtFeld-Studio/pull/4008) 显示的是已安装进 viewer 的 step、Gaussian 数与 SH degree，而不是 trainer 内部尚未发布的实时状态。相机 geometry 有独立 revision，可在训练暂停或 Gaussian generation 未变时更新。
- 不提供远程控制、训练所有权转移或 cross-process GPU allocation sharing；普通训练也不会默认发布 session，必须显式 opt-in。
- 对 Blender/headless pipeline 的价值是把“训练仍在另一进程进行”与“当前可视结果和标定相机”解耦，便于观察异常和进度，而不让 Editor 修改外部状态。

### CUDA 稳定性

- [PR #4024](https://github.com/MrNeRF/LichtFeld-Studio/pull/4024) 用 pinned staging + cudaMemcpyAsync 保障临时 host 数据在传输完成前存活；zero_、fill_ 与 strided mutation 使用 tensor home stream。
- 已退休 stream 走 legacy-copy fallback，CUDA graph capture 下 H2D 在 staging allocation 前返回 unsupported。该项应进入训练、外部 preview、undo/redo 和多 stream 压测；没有发布速度提升数字，不应包装成性能增益。
- 固定 SLAM、robotics、autonomous-driving、mapping 项目未出现更高优先级新增。
