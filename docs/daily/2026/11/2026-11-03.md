## 2. SuperSplat / PlayCanvas 工具链

### GS 排序：修的是“少数离群点拖垮近景精度”

[PR #9899](https://github.com/playcanvas/engine/pull/9899) 针对线性距离分桶的结构性问题：当 0.1% splat 被散布到 10 km，近处大量 splat 会挤在相同 key 中，WebGL/CPU 与 WebGPU/GPU 都可能出现错误混合和闪烁。新实现从正浮点距离的位模式构造近似 log2 key，让每次距离翻倍获得相近 key 数；透视 depth 与 radial sort 使用该路径，orthographic/fisheye depth 仍使用原来的 bins，因为它们可能绘制相机后方 splat。

GPU 小场景最低升至 16-bit key，约 23k splat 以下会多一次 radix pass；CPU 仍固定 16-bit 以避免 20-bit counting table 从 256 KB 增至 4 MB。维护者在 Pixel 7 Pro 上对 3M splat 给出混合结果：随机布局通常变快或相近，某些 coherent depth 变慢；真实场景 median frame time 仍为 16.4 ms，WebGPU GPU time从 radial 32.4→30.8 ms、depth 32.9→30.9 ms。应把它视为正确性修复；CPU 16-bit 在极细节上仍可能有轻微 flicker。

**升级建议**：当前 `2.24.0-beta.29` 的版本提交发生在此合并之前，不能假定 beta.29 包含它。受远端 floaters、超大坐标或近景透明混合闪烁影响的项目应锁 `41f34512` 之后的 main 做 A/B，或等待下一 beta/stable。

### VoxelOccupancy：从视觉场景走向可交互空间

[PR #9907](https://github.com/playcanvas/engine/pull/9907) 新增 Engine extras `VoxelOccupancy`。CPU 侧保留 splat-transform 体素格式的稀疏八叉树，提供 `isSolid`、block read、raycast、bounds/grid size；GPU 侧以每个 4×4×4 block 两个 32-bit word 的体纹理给 shader 使用，上传后释放展开的 typed array，并能在 device loss 后从八叉树重建纹理。

新的 `gaussian-splatting/particle-blast` 是 WebGPU 示例：从 GS 颜色/深度生成 compute particles，让它们受重力、风与湍流影响并与体素碰撞。示例只用公开 API，可复制到项目，但它不等于 Editor 的 selection/picking 或真正破坏 Gaussian 数据；本质上是“渲染 splat + 体素代理物理”。建议验证体素分辨率、边缘漏碰、raycast 吞吐、device loss、内存峰值与 WebGL fallback 行为。

## 6. Compression / Format / LOD / Streaming

今天的格式变化是“工具链落地”，不是新标准：

- **LCC2**：Gaussian Splat Lite 实现 LCC2 `0.0.x` scene index + SOG/SPZ/PLY payload 的相机驱动 LOD，并把多输入共享预算、environment、fade 与 viewer 文件夹加载做成公开 API。它没有改变 LCC2 的编码、压缩率或随机访问定义。
- **替换语义**：coarse coverage 先保持，完整 child cut 就绪后原子替换，能避免部分 child 到达时出现洞；已加载细节可在 coarse replacement 载入时继续显示。
- **预算语义**：splat budget 只约束 requested detail；加载、缓存、淡入淡出与环境层仍需独立内存指标。多源场景尤其要测试一个大 source 是否挤压其他 source 的细节。
- **PlayCanvas voxel sidecar**：`.voxel.json/.voxel.bin` 是碰撞代理，不是 Gaussian 压缩格式，也不替代 SOG/SPZ/PLY。

SPZ、SOG v3、compressed PLY、glTF Gaussian extensions、OpenUSD、3D Tiles、MPEG GSC、Khronos/W3C WebGPU 本窗口未核实到新批准版本。没有满足 GPU、分辨率、数据集、splat 数、质量指标与对照基线的全新“10×/100×”压缩或渲染声明。

## 7. Training / Reconstruction / SLAM / Robotics / Mapping

### visloc-rs：CUDA TSDF 终于与 lens-aware CPU 路径对齐

[PR #446](https://github.com/rsasaki0109/visloc-rs/pull/446) 在 `tsdf_integrate_kernel` 中用 lens projection 投影 voxel，在 allocation kernel 中沿 lens pixel ray 反投影 surface pixel，并按 pinhole camera-z 或 fisheye distance 比较深度；fisheye frustum 改为 max-theta cone。它移除 CUDA TSDF 的 pinhole 拒绝/剥离逻辑，ABI 不变，普通 pinhole 算术保持原路径。

测试中 distorted pinhole 的 device/CPU vertex 100% 在 1e-3 voxel 内，distorted fisheye 为 99.97%，剩余 worst 0.31 voxel。ETH3D delivery_area 的 948 views 中，lens median F1@2/5/10cm 都是 6.1/16.1/27.2%，GPU 8.8 s、CPU 115 s；lens planar GPU 7.1/18.4/29.9%、14.9 s，CPU 7.1/18.5/29.9%、191 s。这里的约 13× 仅属于这组 8 GB laptop GPU、场景、block 数与深度口径。

### visloc-rs：粗略鱼眼模型可作为 BA 初值，而非必须精确标定

[PR #448](https://github.com/rsasaki0109/visloc-rs/pull/448) 为 shared intrinsics 加入 lens 参数；一个 camera node 容纳前三个畸变参数，第二个 node 容纳剩余参数，从而支持 thin-prism/full OpenCV 的 8 参数。Jacobian 通过每步重建 probe lens、对参数做 1e-6 central difference 得到统一模型路径。local-window 仍像 focal 一样固定畸变，refined values 会写回 camera 并记录在 `BA_INTRINSICS`。

TUM-VI room1 的 195° fisheye 以 f=175（短约 8%）、中心 principal point、零畸变为初值：固定粗略模型注册 280/283，中心 RMSE 11.92 cm；`--refine-camera` 注册 283/283，0.48 cm，rotation median 0.30°；精确标定固定时为 0.44 cm/0.33°。这是强工程信号，但个别系数会相互补偿，真正约束的是观察视场内的组合 radial mapping。

固定检查 gsplat、LichtFeld Studio、OpenSplat、graphdeco-inria/gaussian-splatting 与主要 Gaussian SLAM/robotics/mapping 仓库，窗口内除 visloc-rs 外没有新的正式 release 或权重。

## 13. 今天最值得实际测试 / 部署

### 1) Gaussian Splat Lite 1.6.1 的 LCC2 流式

- **为什么**：tag、npm API、Viewer 与文档都已齐全；LCC2 可以直接进入 Three.js/WebGPU/WebGL2，而不必换专用客户端。
- **门槛**：`gaussian-splat-lite@1.6.1`、Three.js ≥0.187；真实 `.lcc2` index 与完整 companion files；开发构建需 Node.js ≥22.12，无 CUDA 要求。
- **测试**：URL/本地文件夹、SOG/SPZ/PLY payload、多 source 争用、环境层、相机 teleport、XR camera、断网重试；记录 firstRenderable、峰值 CPU/GPU/临时内存、cache 回收与 fade 期间超预算。
- **预期收益**：降低 LCC2 大场景接入 Web 产品的自研成本；不承诺固定压缩率或显存上限。

### 2) PlayCanvas `995faa17`：排序正确性 + VoxelOccupancy

- **为什么**：一个修复真实远端 floater 导致的全场闪烁，另一个给 splat 场景提供可复制的碰撞/粒子公共 API；二者都直接影响 WebGS 交互体验。
- **门槛**：锁 Engine main 至少 `995faa17`；排序可测 WebGL2/WebGPU，particle-blast 需 WebGPU；用 splat-transform 生成 voxel sidecar。
- **测试**：近景+10 km 离群点、快速平移/投影切换、CPU/GPU sort 一致性、Pixel/桌面；体素分辨率、raycast、边界、device loss、CPU/GPU 内存释放。
- **预期收益**：减少透明排序闪烁，并把碰撞/角色/粒子交互从自建空间索引降为 Engine extras；beta.29 不包含，生产升级需等待版本边界或自锁 SHA。

### 3) visloc-rs 鱼眼自标定 + GPU TSDF

- **为什么**：上一日报仍存在的“CUDA TSDF 仅 pinhole”缺口已经关闭，同时粗略鱼眼模型能在 native BA 中联合修正。
- **门槛**：Rust、CUDA GPU（作者测试含 8 GB laptop GPU）；准备已知标定/粗略初值的 fisheye、thin-prism 或 distorted pinhole 数据与 mesh ground truth。
- **测试**：固定标定、粗略固定、`--refine-camera` 三组；注册率、中心/旋转误差、held-out reprojection；CPU/GPU mesh F1@2/5/10cm、融合时间、worst vertex offset、显存。
- **预期收益**：减少去畸变预处理与错误固定标定造成的漂移，并把畸变镜头 TSDF 融合移到 GPU；约 13× 只作为 ETH3D delivery_area 的复验目标，不是通用承诺。
