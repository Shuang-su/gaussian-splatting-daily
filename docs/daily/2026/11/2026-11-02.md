## 2. SuperSplat / PlayCanvas 工具链

### Engine beta.28：XR 恢复终于有可锁定的版本边界

[2.24.0-beta.28](https://github.com/playcanvas/engine/commit/4b496a2a1c5892b6f8198a2ec7aef0009b4447cc) 是版本号提交，不能把它本身夸成新功能；真正重要的是它位于 [WebGPU XR projection-layer 恢复修复](https://github.com/playcanvas/engine/commit/c4ead5541e9a95fdc3a8edd1ac006c9772f99057) 之后。Quest Browser 睡眠/唤醒后 `getViewSubImage` 失败时，Engine 会重建 binding/layer、恢复 framebuffer scale 与 fixed foveation，并避免只有部分 eye texture 时继续渲染。beta.27 已包含 LCC2 runtime 与 hierarchy-cut LOD，beta.28 同样继承；这不是新的 LOD 算法，也不改变 SOG/SPZ/PLY。

**升级建议**：正在跟 main SHA 测 Quest/大型 LOD 场景的团队可切 beta.28 做固定版本回归；stable 项目仍应等待正式版。至少测试 20 次 enter XR→sleep/wake→双眼、深度、foveation、退出/重进，并保留 WebGL XR fallback。

### SuperSplat / Viewer / SplatTransform

因此，Editor 3、selection/picking、histogram、viewer export、发布 API、共享 viewer settings、SOG/SPZ/PLY/GLB/glTF 互转本日没有新变化；唯一值得立即升级测试的是 Engine beta.28 的版本边界。公开可索引的官方博客/论坛没有比 10 月 29 日公告更晚的新项；Discord 未直接读取，也没有使用 Discord 转述。

### DynamicSky：是混合场景能力，不是 splat shader 新特性

[953e8bec](https://github.com/playcanvas/engine/commit/953e8becb91e6f8cee7c0f897c3817d37dd16efa) 让 DynamicSky 每帧绑定 sky uniforms，GLSL/WGSL 共用大气函数，CPU 可按方向取 sky color；[4cae1780](https://github.com/playcanvas/engine/commit/4cae1780803ed99fe32de19394f40cb11db0dbfe) 增加按高度衰减的 haze 和 StandardMaterial opt-out。对 WebGS 产品的价值是让 splat 周围的 mesh/terrain/particle 与天空更一致；多个 sky effect 时最后更新者覆盖设备 uniforms，volumetric fog/XR flat cloud 仍有限制。

## 3. 可实际运行的开源项目

### LichtFeld：把 OOM 从“进程终止”降级为“释放、重试、跳过或回滚”

[477aca7a](https://github.com/MrNeRF/LichtFeld-Studio/commit/477aca7ac92a9654e7da253adb291ac3d7d0eaa7) 的核心不是单点省显存，而是失败语义。CUDA allocation exhaustion 被封装为可恢复异常并清理错误状态；scratch allocation 先调用 memory-pressure coordinator 释放可回收资源，再重试一次。position bounds 不再建 index list 和 gathered copy；tensor 新增 `truncate_rows`，densification append 后失败可恢复原 row count；Morton reorder 在移动数据前计算最大 scratch 并一次性申请，申请失败就保持原顺序继续训练。

这能降低显存临界点下的 crash 与半更新模型风险，但没有固定的 GB/% 节省。建议锁 SHA 测：剩余显存 0.5/1/2 GB、densification 峰值、checkpoint 同时发生、Morton skip、OOM 后继续 1,000 step、最终 Gaussian count/质量一致性。

### LichtFeld：数万相机不再每帧重建和复制全部 UI 数据

[23fb4b46](https://github.com/MrNeRF/LichtFeld-Studio/commit/23fb4b466868b875491af63f6e973eab3ebdfc6b) 对 frustum geometry 做弱身份缓存与输入失效；picking 用 TBB 并行扫描，projection/culling 分块并行且维持 camera 顺序；visible set 与 point cloud 改为引用。它主要改善大规模 capture 的 Editor 交互，不改变训练 kernel、PLY/SOG 导出或渲染质量。

### Spirula：从数据集任务直接进入训练队列

[b8cb6f02](https://github.com/harry7557558/spirula-studio/commit/b8cb6f02c2c3a57d080eee12e803275e3cac11e0) 让自动训练配置与 dataset job 同时快照，避免用户在处理中改 UI 导致后续训练参数漂移；只在成功结果上启动训练，取消/失败保持停止。批处理与 partition queue 也接入同一逻辑。建议测试取消、重启、无效 preset、输出路径、batch 顺序与 GPU 切换。

### Heatsplat：真实代码、真实数据路径，但仍是未许可的早期产品原型

[Heatsplat](https://github.com/jonathan10george/heatsplat) 可用 `uv sync`、FastAPI 与 Vite 启动；既能用合成场景，也能 ingest PLY + COLMAP/nerfstudio poses + thermal frames。维护者对 ThermoScenes Building A 加入 OpenCV distortion、完整 `fy`、oversized/floater 过滤与 M4/Metal OpenSplat patch，并用 Three.js/gaussian-splats-3d 展示 RGB/thermal/leaks。

依赖门槛不高（Python 3.11，Node，训练可选），但仓库没有 LICENSE；报告中的“热损失/成本”仍是模板与启发式，不是经认证能源审计。适合验证“热数据如何附着到 splat 并做 3D 可视化”，不适合直接商业复用。

### visloc-rs：镜头模型从输入参数变成贯穿式几何契约

[98537606](https://github.com/rsasaki0109/visloc-rs/commit/98537606e9180132d690539b2e7fe6449c668b5e) 让 native BA 携带 `Lens`、对非 pinhole 使用带 point Jacobian 的投影，并让 `gsplat_photos(_cuda)` 接受固定标定 `--camera "MODEL W H PARAMS..."`；legacy/GPU solver 仍 pinhole-only，非 pinhole 自动走 native。[0ec6b31f](https://github.com/rsasaki0109/visloc-rs/commit/0ec6b31f4b1d64fcf7f8c9d9847c7b6bb19191ac) 修复 Kannala-Brandt 超过 90° ray 的镜像问题，以 unit-ray path 支持 244° synthetic 与 195° TUM-VI。

## 13. 今天最值得实际测试 / 部署

### 1) LichtFeld 显存极限训练恢复

- **为什么**：它同时处理分配失败、scratch relief、append rollback 与 reorder skip，最接近“低余量 VRAM 仍能完成训练”的生产问题。
- **门槛**：NVIDIA/CUDA，LichtFeld master 至少包含 `477aca7a`；准备会持续 densify 的大场景。
- **测试**：人为压低可用显存；同时触发 densification/checkpoint/Morton reorder；记录是否 crash、是否跳过、row count 是否回滚、继续 1,000 step 后质量与 hash。
- **预期收益**：减少临界显存下的中断与模型部分写入；无固定百分比承诺。

### 2) visloc-rs 原生鱼眼/畸变链

- **为什么**：同一镜头模型贯穿 SfM、Gaussian projection、loss 与 CPU mesh，能减少去畸变重采样和坐标语义漂移。
- **门槛**：Rust；按路径选择 CUDA 或 WGPU；准备已知标定的 fisheye/KB/OpenCV 数据，注意 CUDA TSDF 仍 pinhole-only。
- **测试**：native lens 对 undistorted baseline；>180° ray；camera-center RMSE；held-out PSNR；mesh F1；运行时间；CPU/CUDA/WGPU 一致性。
- **预期收益**：广角、全景、机器人/车载数据可直接进入重建链；效果依赖标定与视场覆盖。

### 3) Spirula dataset→train 自动队列

- **为什么**：无需 CUDA、改动边界清晰，能立刻减少人工等待和参数抄录。
- **门槛**：Spirula master `b8cb6f02`，Vulkan GPU；准备照片、视频和 batch/partition 用例。
- **测试**：成功/失败/取消、preset 快照、override、输出路径、batch 顺序、应用重启和训练中断恢复。
- **预期收益**：捕获到训练成为一条稳定、可批量化的本地流水线。
