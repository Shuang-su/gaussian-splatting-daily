## 3. 可实际运行的开源项目

### Arcturus Vision / 3dgs-scripts

- 仓库首次公开，仅一个 commit [80c2c0a](https://github.com/arcturus-vision/3dgs-scripts/commit/80c2c0a633bfd4644f1e2df9dc804ae81e4317f9)；MIT。新仓库尚无有意义的 stars 增速。
- `av1_colmap.py`、`av1_to_3dgs.py`、`av1_train.py`、`av1_spirula_sfm.py` 的输入不是任意 MP4，而是带标定/位姿的 **Arcturus Vision Camera AV1 双目 MP4**。先生成度量对齐 COLMAP 数据，再复用同一数据选择训练器。
- Linux/NVIDIA 可走 LichtFeld；Apple Silicon/macOS 14+ 可试 M-Splat/Metal；Spirula 可走 MoltenVK/Vulkan 或 CUDA。LichtFeld/Spirula 默认 150 万 Gaussian 上限；M-Splat 未见上游硬上限。脚本保留 hash、`run.json` 和 resume 校验，不上传远端。
- 输出可保留 full-SH PLY，LichtFeld 可直接产 SOG，也可用 SplatTransform 转换。当前 Gaussian XR SOG loader 只读 DC color、跳过高阶 SH，XR 结果必须标注口径，并保留 full-SH PLY 母版。Linux CLI 最完整；macOS/M-Splat 为实验性，固定 Spirula Linux build 尚未重验。**可实际测试；A/B。**

### visloc-rs

- 仓库 MIT OR Apache-2.0；Rust + CUDA。SAM3 组件受 Meta 单独许可约束，部署前需分开核对。
- [PR #476](https://github.com/rust-cv/visloc-rs/pull/476) 将 SAM3 文本提示类别按每个 Gaussian 的体渲染贡献 `T_i·α_i` 投票，PLY 增加 `class`、`class_confidence`，Web viewer 可叠加类别。作者在 FIORD MeetingRoom_In（106 张 200° fisheye、10 prompts、8GB 笔记本 GPU）报告 held-out pixel agreement 82.6%、mIoU 71.3%；属单场景作者自测。
- [PR #477](https://github.com/rust-cv/visloc-rs/pull/477) 增加实例 membership、跨视图 overlap 0.5、至少 3 视图和 union-find，PLY 增加 `instance`。
- [PR #478](https://github.com/rust-cv/visloc-rs/pull/478) 把最多 16 类 semantic logits 设为可训练属性；默认 semantic weight 0.02，支持 `--semantic-logits-only`。作者报告 MeetingRoom held-out mIoU 81.5%、instance match 76.8%；Building_In mIoU 71.9%、instance match 45.4%，PSNR 约 32.69 dB；semantic passes 令训练时间约翻倍。
- 价值是从 2D segmentation 推进到可导出的 3D semantic/instance splat；但自定义 PLY 字段不是跨 viewer 标准，转换前需验证未知属性是否保留。**可实际测试；B。**

### LichtFeld Studio / Spirula

- LichtFeld 为 GPL-3.0-or-later，C++23/CUDA 12.8，文档要求 NVIDIA compute 7.5+、driver 570+。SAM2.1 掩码是逐图编辑，不是跨视频传播；须在训练初始化前应用。[PR #4015](https://github.com/MrNeRF/LichtFeld-Studio/pull/4015) 另修复从 camera list 点击时被旧 zoom/chrome 状态挡住的问题。
- Spirula 为 GPL-3.0、自包含 C++，可选 Vulkan/CUDA，无需 PyTorch。除缓存可复现性修复，[PR #308](https://github.com/spirulae/Spirulae-3D-Reconstruction/pull/308) 给 batch queue 增加 per-run ROI、持久化配置与文件校验；另有下采样图磁盘缓存和 dataset-loading 加速。**可实际测试；B。**

## 5. Viewer / Editor / Web / Mobile / XR

- LichtFeld Editor 的 SAM2.1 点/框提议减少外部抠图往返；tensor 原位回写对 VkSplat 共享存储尤其关键，建议加入“删除/恢复 Gaussian 后 opacity 是否一致”回归。
- visloc Web viewer 新增 class/instance overlay，但普通 PLY viewer 可能忽略自定义属性。
- Arcturus 可接 SOG/Gaussian XR；当前 loader 只用 DC color，Web/XR 发布需验收 full-SH PLY 与 DC-only SOG 的视觉差异。
- SuperSplat、移动端和 WebXR 本窗口无新功能变化。

## 6. Compression / Format / LOD / Streaming

- Arcturus 形成 **COLMAP → full-SH PLY / SOG** 路径：SOG 用于分发，PLY 作为高保真母版；只读 DC 的 XR loader 不应宣称完整保留视角相关外观。
- visloc 的 `class`、`class_confidence`、`instance` 和 logits 是 PLY 扩展属性，不是 KHR_gaussian_splatting、SPZ 或 SOG 标准字段；转换可能静默丢语义。
- 未发现 SPZ、SOG、glTF、OpenUSD、3D Tiles 或 MPEG GSC 的新正式版本/决议；SOG v3 前一日状态不重复。无新 LOD、chunking 或 streaming 实现。

## 7. Training / Reconstruction / SLAM / Robotics / Mapping

- visloc 将 semantic cross-entropy 加入同一优化循环，默认权重 0.02；提升需以约 2× 训练时间换取。复现应记录类数、SAM3 prompts、weight、CUDA ABI 13、场景和 held-out 切分。
- `gsplat_photos --back-images` 将前后镜头建成 rig，并通过 `image_frames.txt` 固定。作者称 FIORD Building_In front held-out +0.67 dB，MeetingRoom 基本持平；主要价值是正确接入 >180° 数据，而非已证明普适画质跃升。
- Spirula `matches.bin` v5 记录 fingerprint 和标定旋转。作者在 4,412 帧 360 capture 上解释旧缓存导致的 time offset 差异（约 -30.8 ms vs -34.5 ms）；新路径让缓存命中可解释。
- 固定 SLAM/robotics/mapping 仓库未检出更高优先级新增。

## 13. 今天最值得实际测试 / 部署

1. **Arcturus AV1 3DGS Pipeline**：适合已有兼容 AV1 Camera 录制。门槛是 `uv`/Python、可用 trainer，以及 Linux NVIDIA、Apple Silicon/Metal 或 Vulkan/CUDA 其中一路。收益是标定、尺度、COLMAP、训练和 provenance 一条链。先保留 full-SH PLY，再单独验收 DC-only XR SOG。

3. **LichtFeld SAM2.1 mask + undo 回归**：适合现有 LichtFeld NVIDIA 工作站。选玻璃/行人/反光数据，验证原分辨率 mask、`.licht` 重开、undo/redo 后 VkSplat opacity 与最终 Gaussian 数；360/视频批处理团队可改测 Spirula `matches.bin` v5 + per-run ROI。
