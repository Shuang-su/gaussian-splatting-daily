### P1｜SuperSplat Viewer 1.43.1：SOG v3 stochastic 正确性与 Quest WebGPU WebXR 同时修复

- **版本 / 来源**：[`v1.43.1`](https://github.com/playcanvas/supersplat-viewer/tree/v1.43.1)，版本 commit [`f1866b0`](https://github.com/playcanvas/supersplat-viewer/commit/f1866b08f014e4d6fccf017ad06a6024e0bc1b64)，[PR #363](https://github.com/playcanvas/supersplat-viewer/pull/363)。MIT；Node.js ≥20；PlayCanvas Engine `^2.24.0`。
- **代码变化**：`packedActive()` 现在同时要求 quats texture 才判定为 SOG v2，避免 SOG v3 被按 v2 layout 重打包而乱码；projector cache 的 alpha byte 改用 SOG v3 编码 `alpha=(1.25b/255)^2`，raster 加入与 Engine 一致的 >1 alpha plateau/core 与扩大 quad 逻辑。
- **实际影响**：SplatTransform 3.11 默认写出的 SOG v3 可在 stochastic 模式下正确读取，decimated LOD 最高 1.5625 opacity 不再被截到 1；作者的全 1.5625 alpha 场景中，与 sorted renderer 的平均绝对差从 13.96→11.38（远景）、15.32→12.87（近景）。
- **Quest**：移除强制 WebGL 和 `?webgpu` opt-in；维护者已在最新版 Quest Browser 验证 WebGPU WebXR。XR stereo 的 stochastic renderer 与 Firefox 未测。Pixel 7 Pro 的 interleaved coverage 中位 GPU 时间增加约 0.43–0.50 ms（约 1.5%），per-pixel 模式基本不变。
- **判断**：SOG v3、stochastic、LOD 和 Quest XR 用户应立即升级测试；生产部署前补 Quest stereo、Firefox 与显存释放回归。**可运行性：可实际测试；可信度 A/B。**

### P1｜Spirula Studio 主干：SfM 两视图验证和 Vulkan 训练热区提速，并加入训练结束钩子

- **来源**：[PR #326](https://github.com/harry7557558/spirula-studio/pull/326)，merge [`e55731d`](https://github.com/harry7557558/spirula-studio/commit/e55731d50a3e84ab7243596126ac978bcb73a7e3)；训练 commit [`34f81ef`](https://github.com/harry7557558/spirula-studio/commit/34f81ef79f4e0b87a2f954d754370dabe2ff60b8)；结束命令 commit [`484da3b`](https://github.com/harry7557558/spirula-studio/commit/484da3b0fdab6004dde1fc9f7a4595eaf32a78c6)。GPL-3.0；Windows/Linux/macOS；Vulkan 推荐，CUDA 为 legacy backend。
- **SfM**：按 descriptor distance 排序、前 100 次采用 PROSAC 风格渐进采样、零分配 inlier mask、缓存转置、低于 4 个 fundamental inlier 时跳过 homography，并修复低 inlier ratio 的自适应停止溢出。PR 的单线程合成 4K 测试报告 4.58–5.25×，重 outlier recall 61.1%→99.5%；平面场景 5.15→6.64 ms，说明并非所有输入都加速。
- **训练热区**：`34f81ef` 把 Vulkan PCA 邻居选择 4.65→3.81 ms/pass；RTX 3070 Laptop、2594×1681、fp16 的多尺度 SSIM 栈 16.1→12.1 ms/call；garden 场景 uniform PPISP backward 的 grid+RGB 4.65→1.31 ms/step。均为组件级 benchmark，不能写成整场训练同比。
- **自动化**：`--finish-command` 在训练完成或失败时直接执行外部程序，将一行 `{message}` 作为单一参数；手动停止不触发、无 shell 解析。这适合通知、上传或后处理，但用户输入仍应做 allowlist。
- **判断**：值得在 Vulkan 训练机上用自有数据复测；当前是主干 commit，稳定 release 仍是 2026.10.30，生产应锁 SHA。**可运行性：可实际测试；可信度 B。**

### P1｜PlayCanvas Engine 提供 `app.precompile()`，WebGPU 首帧 shader/pipeline stall 可前置并行化

- **来源**：[PR #9997](https://github.com/playcanvas/engine/pull/9997)，merge [`93b5104`](https://github.com/playcanvas/engine/commit/93b5104e5a05562887f2182ae5c99645f2d0c448)。
- **架构**：新 `AppBase#precompile({frustumCulling})` 构建下一帧但不绘制，通过专用 precompile pass 收集 shader/pipeline；WebGPU 使用 `createRenderPipelineAsync` 并按逻辑处理器限制 4–32 并发，WebGL 使用 `KHR_parallel_shader_compile` 加 1 像素 warm-up。提供 start/progress/end 事件和统计。
- **作者口径**：M4 Max 冷缓存样例中 WebGPU load 9.9 s→1.3 s（仅可见）/2.3 s（全部）；car showcase 首帧 9.4→2.1 s。WebGL 全量预编译 4.0→4.1 s，收益主要是把后续 40–70 ms/material 的 stall 提前处理。CameraFrame 后处理在首版仍未完全覆盖，随后 [PR #9999](https://github.com/playcanvas/engine/pull/9999) 扩展到相关 pass。
- **对 WebGS 的影响**：复杂 Viewer/Editor 可把 material、stochastic、post-effect pipeline 的首帧卡顿移到加载页；不改变 splat sorting、projection 或运行时 FPS。**可运行性：可实际测试；可信度 B。**

### P1｜LichtFeld Studio 增加 RGB / Depth / Normal 视口模式

- **来源**：[PR #4043](https://github.com/MrNeRF/LichtFeld-Studio/pull/4043)，merge [`393aa42`](https://github.com/MrNeRF/LichtFeld-Studio/commit/393aa427407b2983af5c131575f57e11267e29dd)。
- **新增**：原 depth-map 按钮改为 Render modes selector；Normal 模式从 alpha-weighted depth 在 GPU 重建 camera-space surface normal，拒绝 depth discontinuity，并绕过 exposure、tone mapping、PPISP 和 environment compositing。支持 perspective、orthographic、equirectangular；独立 Gaussian PLY、无 dataset 也可用。
- **工程影响**：项目会保存显示模式，但 selector 展开状态不保存；Normal 在无 splat 时不可用。190 个 Python 测试、23 个 focused native tests 与 10 个 locale completeness 通过。
- **判断**：对几何诊断、floaters/表面断裂定位和 standalone PLY 检查很有价值，但 normal 是由深度重建的诊断视图，不是训练输出的真实法线。**可运行性：可实际测试；可信度 B。**

### P2｜SplatTransform 将 SOG v3 portable blind texture 上限从 10 修正为 9

- **来源**：[PR #377](https://github.com/playcanvas/splat-transform/pull/377)，merge [`546c372`](https://github.com/playcanvas/splat-transform/commit/546c372ad7b03eda8bb4be98611d877c08ddd7b4)。
- **原因**：WebGL2 只保证 16 个 texture units；SOG v3 + SH 本身占 6、Engine 再占 `sogCodebook`，10 个 blind textures 会需要 17 个。writer 现在从第 10 个开始告警，避免生成不具可移植性的资产。
- **另一个修正**：文档把 SH palette 默认值改为实际公式——Gaussian 数向下取 2 的幂并封顶 65,536，而不是“每 1024 Gaussian 一个 entry”；算法本身没变。
- **判断**：无需单独为此升级版本，但构建 SOG 自定义属性管线时应把 9 作为 WebGL2 可移植上限。**可运行性：可实际测试；可信度 B。**

### P2｜FastWild-GS 与 GEMOR-GS 是今日最值得跟踪的两篇研究信号

- [FastWild-GS](https://arxiv.org/abs/2611.13808) 把 in-the-wild 每图外观压缩为 128D token + 六个通道变换参数；论文报告 PhotoTourism 8.8 分钟/场景、相对 AsymGS 23×，但未找到可运行官方仓库。

- **可信度 A（原论文）；可运行性：论文无代码。** 性能数字均为作者口径，未作第三方复现。

## 10. 研究论文

<!-- arxiv-baseline:start -->

### P2｜FastWild-GS: Minutes-Scale In-the-Wild Gaussian Splatting via Compact Per-Image Appearance Adaptation

<!-- arxiv:2611.13808 -->

- **arXiv**：[2611.13808](https://arxiv.org/abs/2611.13808)；**论文无可运行官方代码**。
- **核心**：每图 128D appearance token + 六参数通道变换，小 MLP 预测 Gaussian 颜色，并把相同变换用于 densification/pruning 打分，避免把曝光/光照差异误判为重建误差。
- **作者口径**：PhotoTourism 8.8 分钟/场景、NeRF-OSR 9.7 分钟/场景；相对 AsymGS 23× 仅在论文比较设置下成立，需 GPU、场景和质量指标完整复核。

### P2｜RF3DGS: Reflection-Free 3D Gaussian Splatting with Self-Priors

<!-- arxiv:2611.13772 -->

- **arXiv**：[2611.13772](https://arxiv.org/abs/2611.13772)；**论文无代码**。
- **核心**：先用几何先验获得粗反射自由 depth，再多视图 warp 汇聚低强度 photometric prior 生成 transmission pseudo-label，并用 Adaptive Twin Rendering loss 保留细节。
- **价值**：博物馆、橱窗等反射场景值得跟踪；新 benchmark 与 Unity 合成数据仍需公开实现验证。

### P2｜Marrying Capacity and Precision for Efficient 2D Gaussian Image Representation

<!-- arxiv:2611.13784 -->

- **arXiv**：[2611.13784](https://arxiv.org/abs/2611.13784)；**论文无代码**。
- **核心**：CP-GS 在同一 serialized-size 预算下共同选择 Gaussian 数量与属性量化精度，并按内容把 Gaussian 从冗余区重分配到高需求区域。
- **边界**：这是 2D Gaussian image representation，不是直接可用的 3DGS codec；其 rate-distortion 联合分配思想可迁移参考，但不能当作 SPZ/SOG 替代。

### P2｜DepthGS: Depth-Guided Gaussian Splatting with Adaptive Regularization for High-Quality Surface Reconstruction

<!-- arxiv:2611.13628 -->

- **arXiv**：[2611.13628](https://arxiv.org/abs/2611.13628)；另有 IEEE TPAMI DOI `10.1109/TPAMI.2026.3751295`；**论文无可运行官方代码**。
- **核心**：从单视图/多视图 depth discrepancy 与 reconstruction error 的关系出发，自适应调节 normal constraint，并加入相邻视图 depth consistency。
- **数据集**：DTU、Mip-NeRF360、Tanks and Temples；论文声称兼顾 surface reconstruction 与 NVS，暂无权重/脚本供复核。

### P2｜GEMOR-GS: Global Extrinsic-calibration-refined Mapping and Online Relocalization for 3D Gaussian-Splatting SLAM

<!-- arxiv:2611.13528 -->

- **arXiv**：[2611.13528](https://arxiv.org/abs/2611.13528)；**论文无代码**。
- **核心**：离线 LiDAR-camera 外参、keyframe/Gaussian 交替全局优化、最终重建，以及 XFeat bypass map + RANSAC-PnP + Gaussian RGB-D warp 的在线重定位。
- **作者口径**：相对 Gaussian-LIC2 约 +9 dB PSNR，held-out 重定位 86–100%；高度依赖外参质量，不应脱离标定条件引用。

### P2｜RetinexGS: Retinex-Inspired Gaussian Splatting for Low-Light RAW Reconstruction

- **arXiv**：[2611.13280](https://arxiv.org/abs/2611.13280)；**论文无代码**。

- **作者口径**：5 个场景相对 LE3D / RawNeRF 平均 sRGB PSNR +2.18 / +2.71 dB；RTX 4090、2016×1512 报告 91–145 FPS。需在相同 RAW pack/ISP 和迭代数下复核。

## 13. 今天最值得实际测试 / 部署的项目

1. **SuperSplat 3.8.0 + Viewer 1.43.1**
   - **为什么**：一个修复 Editor/Engine 2.24 的阻断性回归，一个修复 SOG v3 stochastic/alpha>1 并打通 Quest WebGPU XR；组合收益直接影响导入、编辑、发布和 XR。
   - **门槛**：Editor Node ≥20.19、Viewer Node ≥20、Engine 2.24；准备 Chrome/Edge 157 Windows、SOG v2/v3、alpha 1.5625 LOD、Quest Browser 与 Firefox。
   - **预期收益**：避免黑屏/空模型/文件读取静默失败；SOG v3 不再乱码，LOD opacity 与 Quest WebGPU 路径恢复正确。

2. **Spirula Studio `e55731d` + `34f81ef`**
   - **为什么**：同时触及 SfM verification 与 Vulkan training hot path，且有明确组件 benchmark；finish command 还能接入训练完成通知/后处理。
   - **门槛**：从源码锁定 SHA；Vulkan 推荐；准备 planar、重 outlier、4K 高匹配数数据，以及自有 RTX/AMD/Apple 测试机。
   - **预期收益**：减少大图 pair verification 与损失/PPISP 开销；验证时分别记录 SfM、每 step、端到端训练时间和质量，避免把局部倍数误当整体倍数。

3. **LichtFeld Studio RGB/Depth/Normal 视口模式**
   - **为什么**：无需 dataset 的 standalone PLY 也能检查相机空间法线和深度断裂，适合训练结果验收。
   - **门槛**：native build/CUDA 环境；准备平面、细结构、discontinuity、perspective/ortho/equirectangular 测试场景。
   - **预期收益**：更快定位 floaters、几何折断、曝光/后处理干扰；明确 normal 是深度重建诊断图而非 ground-truth normal。
