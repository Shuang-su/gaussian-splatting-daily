## 2. SuperSplat / PlayCanvas 工具链

### 低通滤波：修正单位错误，并下放到每个资源

[PR #9916](https://github.com/playcanvas/engine/pull/9916) / [commit e1b031d7](https://github.com/playcanvas/engine/commit/e1b031d79dfa366f5cfc0924161d2b8eacd040b7) 发现 Engine 协方差以“半像素平方”为单位，旧常量实际上只给出约 0.075 px²，而 3DGS 论文采用 0.3 px²。修复同时覆盖 quad、GPU sort 和 shadow 的 WebGL2/WebGPU 路径。维护者参考图上给出 bicycle 28.4→43.2 dB、dense 33.5→43.8 dB、lioness AA 38.2→49.1 dB；M4 Max 1080p 的 CPU-sort frame time 为 1.09–1.22×、GPU-sort 为 1.00–1.25×。这组数字只证明指定场景的质量/成本权衡。

[PR #9921](https://github.com/playcanvas/engine/pull/9921) / [commit 6559612f](https://github.com/playcanvas/engine/commit/6559612fd45ee7b7053b17d30017f722d67f4bdc) 把 AA 选择从场景全局开关改为每资源自动检测：PLY header 支持 Postshot antialiased 1、Brush/SplatTransform SplatRenderMode: mip，SOG 与 LOD meta 读 model，SPZ 读 header。混合场景通过 work-buffer center 低位携带标志；维护者在 M4 Max WebGPU、两个 1.9M 场景上测得约 +1.7% GPU time，单一模式不增加 shader variant。

[PR #9928](https://github.com/playcanvas/engine/pull/9928) / [commit 91e44738](https://github.com/playcanvas/engine/commit/91e447380123d567e6a0b94766cf7010e4457e7e) 新增 antiAliasFilterSize，默认 0.3；Mip-Splatting、Brush mip 与 Spirula mip 可设 0.1。维护者对 0.1 reference 报告正确设置 47.3 dB，对固定 0.3 为 39.9 dB。Viewer 获得 Auto/On/Off 与 filter-size 控件。

### 远景阈值：少剔除，换回图像能量

[PR #9927](https://github.com/playcanvas/engine/pull/9927) / [commit 2eb9d556](https://github.com/playcanvas/engine/commit/2eb9d556c4ff5c80fc97838d2e53fcadf40b8e79) 将默认 minContribution 从 3 改为 2。维护者表中 bicycle far PSNR 37.0→41.2、能量 0.71→0.87，lioness far 41.8→47.2、0.77→0.89。近景保留 splat 增加 15–20%，远景增加 70–103%；它是质量默认值修正，不是免费性能优化。

### API 文档与版本边界

[PR #9917](https://github.com/playcanvas/engine/pull/9917) / [commit 029b1960](https://github.com/playcanvas/engine/commit/029b19606059070550968158deb5a8cea564141e) 导出并文档化 GSplat resource 类，包括 compressed/octree 资源；加载资源的 aabb 是只读，运行时覆盖应使用 component customAabb。它降低 TypeScript/API 猜测成本，但不改变 SOG/SPZ/PLY 编码。

## 3. 可实际运行的开源项目

### UnityGaussianSplatting 2.0.0：运行时更直接，编辑能力外移

[v2.0.0 README](https://github.com/aras-p/UnityGaussianSplatting/blob/v2.0.0/readme.md) 改为运行时直接读取 PLY/SPZ，路径可以是 StreamingAssets、相对/绝对路径或 URL；SPZ 支持 v1–v4 与 SH0–3，zstd 由 C#/Burst TinyZZZ 处理。多个对象进行场景级全局排序，新的 GaussianSplatRenderingOptions 统一渲染设置；stochastic 模式不排序，提供 None、Simple Accumulation、Reprojected 三种时间策略。

这是不兼容工作流调整：旧版编辑、cutout、导出与大部分 debug mode 被删除，作者明确建议使用 SuperSplat 编辑。BiRP 最低 Unity 2022.3，URP/HDRP 要 Unity 6；只支持 DX12、Metal、Vulkan，DX11 不支持；移动/Web 未测试，VR 代码也可能已坏。SPZ 的抗锯齿标记与扩展不受支持。

作者在 6.1M bicycle、1200×797 上报告 RTX 3080 Ti 6.3 ms、M4 Max 12.8 ms。内存口径为无 SH 28 B/splat，SH1/2/3 为 36/48/60 B，再加 sorted 44 B 或 stochastic 28 B；SH3 sorted 约 104 B/splat。README 同时说明不会再做显著开发，长期采用前要评估维护风险。

### Gaussian Splat Lite 1.6.2：tag 与主线分开看

[release commit 04d4871e](https://github.com/WilliamLiu-1997/Gaussian-Splat-Lite/commit/04d4871ec0ed952b6c8e0acb444dbdb2c5946f74) 将 Rust/WebGPU 径向排序从平方距离改为实际相机距离，避免 fastSort 的 key boundary 在近区过度压缩。安装仍是 npm install gaussian-splat-lite three，开发/构建需 Node.js ≥22.12，运行可选 WebGPU/WebGL2。

tag 后 [commit f04a964c](https://github.com/WilliamLiu-1997/Gaussian-Splat-Lite/commit/f04a964c7cea243d55a0dfc8d40fdb6648021bd0) 让 viewer 的 SOG/LCC2 environment toggle 正确调用 source settings，默认关闭；[commit 9f8d1562](https://github.com/WilliamLiu-1997/Gaussian-Splat-Lite/commit/9f8d1562009c816cd3bcdd8115dd7b88ba296292) 用 MessageChannel 轮询 WebGL frame fence，避开嵌套 setTimeout(0) 最小延迟。后两项不属于 1.6.2，生产集成需锁 SHA或等下一 release。

### SCARF：今天最完整的研究复现实物

[SCARF 仓库](https://github.com/MAdrid1011/SCARF) 提供 Docker quick workflow、模型 adapter、RTL/Chisel 与评估脚本；[Zenodo v1.0.4](https://doi.org/10.5281/zenodo.22434931) 是 MICRO 2026 Artifact Available / Functional / Results Reproduced 对应归档。外部数据和 checkpoint 不随源码重分发，首次运行仍需联网解析 quick checkpoint。它适合验证 generalizable 3DGS encoder 系统优化，不是通用 rasterizer、训练器或可直接购买的 ASIC。

## 4. 4D / Dynamic Gaussian

## 6. Compression / Format / LOD / Streaming

- **SPZ**：Unity v2.0.0 可直接读 v1–v4、SH0–3，但不支持 SPZ AA 标记/扩展；同一资产在 Unity 与 PlayCanvas 间可能不一致。
- **格式感知 AA**：PlayCanvas 从 PLY comments、SOG/meta、LOD-meta 与 SPZ header 自动选择 AA，并允许 filter size 0.1/0.3。它改的是渲染语义读取，不是压缩标准。
- **SOG/LCC2**：GSL main 的 environment 开关只改变 viewer source setting；没有改 LCC2/SOG 编码、LOD cut 或随机访问定义。
- **EGSC**：PWA 展示 T/UWA 050-2026 bitstream 的浏览器交付与离线缓存，但未附 encoder、跨场景率失真表或 GPU 解码 benchmark，暂不能认定为通用标准落地。
- **其他标准**：compressed PLY、glTF Gaussian extensions、OpenUSD、3D Tiles、MPEG GSC、Khronos/W3C WebGPU 本窗口未核实到新批准版本。没有把 SCARF 的 34.5× ASIC/GPU 能效比较误写为压缩或通用渲染 34.5×。

## 7. Training / Reconstruction / SLAM / Robotics / Mapping

### Insta360 工厂标定进入原生重建入口

[visloc-rs ce3a4690](https://github.com/rsasaki0109/visloc-rs/commit/ce3a46903d203ba5d3183cfb2fa3686705b7189c) 解析 .insp 照片中的相机/镜头工厂参数，为前后鱼眼分别拟合 OPENCV_FISHEYE，并限制到 100° 时做到作者报告的 ≤0.06 px 拟合误差。CLI 增加 --max-angle、--mask-black、--alpha-mask、--save-eval；输出可直接进入 Gaussian/mesh 重建，不必先烘焙去畸变全景。

FIORD 200° MeetingRoom_In 前镜头 800px held-out 图像圈内，作者报告 PSNR 25.4→29.6 dB。它比上一日报的“粗略鱼眼 BA + lens-aware TSDF”更上游：先从相机文件拿到初值，再选择是否联合优化和 CUDA/WGPU 融合。应跨不同 Insta360 型号、固件和裁剪设置验证。

### UniGS-SLAM：语义与 Gaussian 解耦，但代码未核实

[UniGS-SLAM](https://arxiv.org/abs/2611.02051) 用独立 sparse voxel map 存开放词汇语义与观察 provenance，让重建更新后可修订历史语义贡献；语义反过来引导 Gaussian filtering 与局部表面细化。论文在 Replica、ScanNet、KITTI-360 上报告相对最快对比 semantic SLAM 2.37× reconstruction speedup。项目页已公开，但未核实到官方代码/权重，不能写成已可部署。<!-- arxiv:2611.02051 -->

固定检查 [nerfstudio-project/gsplat](https://github.com/nerfstudio-project/gsplat)、[WebODM/OpenSplat](https://github.com/WebODM/OpenSplat)、[graphdeco-inria/gaussian-splatting](https://github.com/graphdeco-inria/gaussian-splatting) 与 LichtFeld Studio：除 LichtFeld [commit af961fa3](https://github.com/MrNeRF/LichtFeld-Studio/commit/af961fa3a7bdd40580069aea4dd5026ca71aeff7) 修正整数 reduce 的 max/min identity 外，无新正式 release。当前调用者为 float，该改动不改变现有结果，属 P2 防御性修复。

## 8. Avatar / Human / Generative 3D

[GSExplorer](https://arxiv.org/abs/2611.01543) 用持久 3D Gaussian world state 给条件视频生成器提供多模态渲染条件，再把生成视频送回 SLAM reconstruction；inconsistency filtering 避免冲突内容污染场景，cross-chunk BA 处理长期对齐。论文构造 293K 训练对并报告 481 帧离开再返回 rollout 的一致性。未核实公开代码/权重，属于论文无代码。<!-- arxiv:2611.01543 -->

[VLSplat](https://arxiv.org/abs/2611.01939) 把 vision-language 场景理解与 3DGS 相连；[官方代码](https://github.com/yuntaeJ/VLSplat) 已有三阶段 pipeline，训练要求单 GPU ≥24 GB、PyTorch 2.4.1/CUDA 12.1；预处理依赖较新的 Python/PyTorch、SAM3/Hugging Face 授权，部分语言路径可用 OpenRouter。仓库未提供明确预训练权重，根目录未见独立 LICENSE，README 指向原 3DGS 非商业研究许可；因此是“有代码、无权重/许可边界待确认”。<!-- arxiv:2611.01939 -->

窗口内未发现同时具备代码+权重且可直接跑的新 Gaussian avatar/human 项目。GSExplorer 是世界生成，VLSplat 是场景理解；均不应归为人像 avatar release。

## 13. 今天最值得实际测试 / 部署

### 1) UnityGaussianSplatting 2.0.0 的 PLY/SPZ 直读与 stochastic

- **为什么**：去掉预转换与逐对象排序，工作流变化最大。
- **门槛**：Unity 2022.3 BiRP 或 Unity 6 URP/HDRP；DX12/Metal/Vulkan；同一场景的 PLY/SPZ v1–v4 与旧版 asset。
- **测试**：URL/本地/StreamingAssets、SH0–3、多个对象全局排序、sorted/stochastic 三种 temporal mode、SPZ AA 差异、内存峰值；VR 独立测试。
- **预期收益**：运行时更直接、跨对象混合更正确；代价是编辑/导出迁移到 SuperSplat，且后续维护有限。

### 2) PlayCanvas Engine 91e44738 之后的 AA + minContribution=2

- **为什么**：同一天修正滤波单位、按资源自动 AA、训练滤波尺寸与远景能量损失，直接影响细线、毛发、远景和混合格式场景。
- **门槛**：锁 main 至少 91e44738；准备 reference、AA/非 AA 的 PLY/SOG/SPZ；WebGL2/WebGPU 双后端。
- **测试**：Auto/On/Off、0.1/0.3、Postshot/Brush/SplatTransform metadata、混合资源、shadow；阈值 2/3 的 PSNR/LPIPS/能量、projector/sort splat 数、GPU time、显存，覆盖桌面与 Android。
- **预期收益**：消除旧 0.075 px² aliasing 并减少远景能量缺失；预计会增加部分场景 GPU 工作，不承诺提速。

### 3) visloc-rs Insta360 工厂标定 → BA → lens-aware TSDF

- **为什么**：把 .insp 工厂参数、可选 native BA 与鱼眼 CUDA/WGPU 几何路径连成无需预烘焙去畸变的 360° pipeline。
- **门槛**：Rust 1.88+；真实 Insta360 .insp，多机型/多固件；CUDA 或 wgpu 可选，留出精确标定/ground truth 对照。
- **测试**：工厂参数与手工标定的 reprojection/held-out PSNR、前后镜头、100°/200° mask、黑边/alpha；固定与 refine-camera BA；CPU/GPU TSDF mesh F1、时间和显存。
- **预期收益**：减少 360° 资产进入 3DGS 的标定和去畸变摩擦；25.4→29.6 dB 仅作为作者单场景复验目标。
