### P0｜SOG v3 rotation 布局切换：Engine 2.24.1 / Viewer 1.43.2 / SplatTransform 3.11.2 必须成套升级

- **时间 / 来源**：2026-11-12；Engine [PR #10007](https://github.com/playcanvas/engine/pull/10007) / merge [`7c1b28f`](https://github.com/playcanvas/engine/commit/7c1b28f030f7fbe3928f92b48da83e0fd3323823)，SplatTransform [PR #379](https://github.com/playcanvas/splat-transform/pull/379) / merge [`849c456`](https://github.com/playcanvas/splat-transform/commit/849c456f6ba1049af4e9818ef116b1485bdb11a6)，Viewer [PR #365](https://github.com/playcanvas/supersplat-viewer/pull/365) / merge [`dcc1f8b`](https://github.com/playcanvas/supersplat-viewer/commit/dcc1f8bdf3c7afc2605b6fde65feccdd399d4413)，SplatTransform dependency sync [PR #380](https://github.com/playcanvas/splat-transform/pull/380)。
- **代码变化**：SOG v3 的 24-bit exponential-map rotation 从 `means_l`、`means_u`、`scales` 的 alpha 通道移到独立 `quats.webp` 的 RGB；这些纹理和 `quats` 的 alpha 都固定 255。原因是 WebKit + WebGPU 即使请求不预乘，也会预乘解码图像，破坏原先藏在 alpha 里的 rotation byte。
- **兼容性边界**：Engine 2.24.1 和 Viewer 1.43.2 只读新布局；SplatTransform 3.11.0/3.11.1 写出的“无 `quats.webp`、rotation 在 alpha”的过渡 SOG v3 会加载失败，需从原 PLY/SPZ 或仍能读取旧布局的环境重新转换。SOG v2 不受影响。
- **格式/性能影响**：SOG v3 + SH 从 6 张增至 7 张纹理；portable blind-texture 警戒线随之从 9 调整为 8。source texture memory 与 v2 相当；官方 PR 在 Chromium WebGPU/WebGL2 上验证，新 Safari 路径仍应补测。
- **判断**：这是会改变资产兼容矩阵的 P0。生产 CDN 不应混用旧 writer 与新 reader；先做资产清单、版本钉死、批量重转和 Safari/WebGPU 回归。**可运行性：生产升级前必须测试；可信度 A/B；MIT。**

### P0｜SuperSplat 3.8.1 修复 3.8.0 的 opacity 读写错误与 alpha>1 导出

- **版本 / 来源**：tag [`v3.8.1`](https://github.com/playcanvas/supersplat/tree/v3.8.1)，版本 commit [`919f0e5`](https://github.com/playcanvas/supersplat/commit/919f0e5d60a94470ed8ebcbc7353a29d0a4344f0)，[PR #1103](https://github.com/playcanvas/supersplat/pull/1103)，merge [`f18fc3a`](https://github.com/playcanvas/supersplat/commit/f18fc3acac6731be1f9776d09d2cfa06d71c7323)。MIT；Node.js ≥20.19；PlayCanvas 2.24.1；SplatTransform 3.11.2。
- **根因**：3.8.0 已升级到 SplatTransform 3.11，但 Editor 仍把 chunk opacity slot 当 logit；slot 实际已是 linear opacity。结果是大多数低 opacity splat 被画到 0.5–0.73，出现 haze/floaters；透明度导出和 minimum-opacity filter 也错误。
- **修复**：颜色纹理直接读 linear opacity；透明 grade 直接相乘；PLY 在存在 alpha>1 时写 `opacity_linear`；projected cache 使用 SOG v3 编码 `alpha=(1.25b/255)^2`，最高 1.5625，并加入与 Engine 一致的 plateau core。Histogram 现在显示真实 opacity。
- **实测范围**：维护者在 695K splat PLY 与 347K decimated SOG v3 上对比 sorted/stochastic、anti-aliasing 和 PLY round-trip；未验证“原生 AA 训练场景”和 minimum-opacity filter 的端到端行为。
- **判断**：使用 3.8.0 的团队应直接升 3.8.1，不要仅替换 viewer。**可运行性：可实际测试；可信度 A/B。**

### P1｜LichtFeld Studio 合入 per-camera pose refinement

- **来源**：[PR #4048](https://github.com/MrNeRF/LichtFeld-Studio/pull/4048)，merge [`99e61d3`](https://github.com/MrNeRF/LichtFeld-Studio/commit/99e61d3636ce94b50ed845d5eb6b373f6a989cd6)。GPL-3.0；native/CUDA；FastGS pinhole 路径；默认关闭。
- **架构**：`--pose-opt` 为每个相机联合优化 6-DoF pose；FastGS preprocess backward 新增 pose gradient，梯度覆盖 projected center/covariance、depth、normal 和 SH view direction；单独 Adam-style state、学习率/启停/half-life、prior 与相邻帧 smoothness。输出 `cameras_refined/` COLMAP text 和 `pose_refinement.tsv`。
- **边界**：目前只支持 pinhole/FastGS；distorted dataset 需 `--undistort`；`--gut` 明确拒绝，因为 gsplat/GUT 路径还没有 camera-pose gradient。
- **作者口径**：80 帧合成 recovery 中 rotation median 0.5°→0.075°、center 0.03→0.0072 scene units；1433 帧 4K woodland、RTX 5090、8M splats 报告 held-out PSNR +0.075 dB、LPIPS -0.004、训练耗时约 +2%。均需用自有 SfM 噪声复核。
- **判断**：对无人机/视频序列的小 pose drift 很有价值，建议先在保留 validation view 的数据上 A/B，而不是默认全量开启。**可运行性：研究级可实际测试；可信度 B。**

### P1｜LichtFeld GUT mip filter 真正生效，并修正 FastGS backward

- **来源**：[PR #4067](https://github.com/MrNeRF/LichtFeld-Studio/pull/4067)，merge [`155329c`](https://github.com/MrNeRF/LichtFeld-Studio/commit/155329cc690f8777aded21ea08586e309efd0e3d)。
- **代码变化**：此前 `--gut --enable-mip` 静默忽略 filter。现在按相机投影为每个 Gaussian 计算覆盖 0.1 px² 的 isotropic world variance，forward/backward/POPSpa 都使用 `sqrt(s²+sigma²)`，并保持 integrated opacity。支持 pinhole、distorted、fisheye、equirectangular。
- **FastGS 修复**：近退化 splat 的 backward opacity compensation 与 forward 对齐；`dilation_scale` 进入 backward，避免 forward/backward kernel 不一致。
- **作者口径**：1/4 训练、1/8 评分时 GUT 从 26.10→27.48 dB，接近默认 rasterizer 27.47 dB；filter on 的 GUT step 约慢 9%，5M splats 多约 40 MiB。filter off 图像 bit-identical。
- **判断**：多相机模型/缩放渲染用户值得马上测试；质量收益与额外训练成本要一起记录。**可运行性：可实际测试；可信度 B。**

## 2. SuperSplat / PlayCanvas 工具链

今天的四仓变化必须作为一条资产协议迁移处理：`splat-transform 3.11.2 writer → Engine 2.24.1 reader → Viewer 1.43.2 → SuperSplat 3.8.1`。

- **Editor**：3.8.1 不只是 dependency bump；它修复 3.8.0 对 true opacity 的误解。Selection、histogram、projected picking、透明 grade、minimum-opacity filter 与 PLY round-trip 都要回归。Depth picking 的 blend weight仍封顶 1，避免 alpha>1 改变 pick 权重。
- **Viewer**：1.43.2 通过 `meta.version === 2` 判定 v2 packed path；SOG v3 保持 Engine 的 format-read chunks，避免把有 `quats.webp` 的 v3 误判为 v2。`/viewer` package 的 peer range升到 Engine `^2.24.1`。
- **SplatTransform**：3.11.2 的 HTML export 内嵌 Viewer 1.43.2；单文件和 streamed SOG v3 均已由维护者测试。SOG v3 + SH 现在占 7 textures，blind property budget需按 8 条 portable 上限规划。
- **WebGPU/WebGL/Safari**：迁移动机正是 Safari/WebKit WebGPU premultiplication；PR 只报告 Chromium WebGPU/WebGL2对比，Safari 26+ 必须作为发布门禁。
- **LOD/streaming**：decimated level 的 alpha>1 能量保持与 `quats.webp` layout 均已覆盖；chunking/网络协议未改。缓存层应把 `meta.json` 和所有 WebP 视为同一不可拆分版本集，避免 CDN 混旧文件。
- **SPZ/PLY/GLB/glTF**：SPZ、GLB/glTF 没有新标准变化；PLY 主要变化是 alpha>1 时输出 `opacity_linear`。旧 SOG v3 若只有成品没有源 PLY，应先保留旧 reader 环境做转存。
- **camera/path、Publish API、shared viewer settings、WebXR**：本窗口无新接口；昨天已归档的 Quest WebGPU与发布能力不重复。

## 6. Compression / Format / LOD / Streaming

1. **SOG v3 breaking transition**：格式版本号仍叫 v3，但物理纹理布局发生变化；仅靠 `version: 3` 无法区分 3.11.0/3.11.1 过渡资产与 3.11.2 新资产。工程上必须记录 writer version 或检查 `quats.webp`。
2. **WebKit premultiplication**：把离散 rotation byte 从其他纹理 alpha 拆出，是兼容性修复，不是压缩率突破；不要把 texture 数增加写成更省显存。
3. **Alpha > 1**：3.8.1 让 decimation/merge 后的 opacity energy在 Editor、Viewer、PLY export间保持一致，上限 1.5625。
4. **LOD / streaming**：新 layout已覆盖 streamed SOG v3；协议、range request、random access与 chunk size未改变。
5. **SPZ / compressed PLY / glTF / OpenUSD / 3D Tiles / MPEG GSC**：实时检索未发现窗口内新正式规范、tag或互操作实现。
