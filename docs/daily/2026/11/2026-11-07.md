## 2. SuperSplat / PlayCanvas 工具链

### Engine：SOG v3 已从提案走到 reader 实现，但还不是“全生态已升级”

- [5c474f78 / PR #9873](https://github.com/playcanvas/engine/commit/5c474f78bb3ea31ce773eaffcf9fff5a1086c018)：loader 接受 SOG v2/v3，拒绝未知版本；v3 rotation 从独立 `quats.webp` 改为 24-bit exponential map，塞入 `means_l/means_u/scales` 未用 alpha 通道；opacity 使用平方编码并可到 1.5625；支持第 4 band SH 与更大 SH palette。>1 opacity 由不扩 footprint 的 opaque core 携带合并后的“质量”，主要解决深层 LOD 变薄/露洞。
- [f1c076c1 / PR #9960](https://github.com/playcanvas/engine/commit/f1c076c1347d11a4a0d60f8a9969a2fb69dd4374)：`meta.blind` 变为 blind texture 列表，每张纹理按 RGBA 字节顺序打包多个字段；每字段生成 `SOG_BLIND_<name>` define 与 `getBlind_<name>()` accessor。数据只在 GPU 读取，不再在 `decompress()` 展开为 CPU columns；纹理加载失败会清理资源并明确报错。
- [97472071 / PR #9962](https://github.com/playcanvas/engine/commit/9747207195f82c20eabdc990351b460725828a71)：`modifySplatColor` 把 alpha 降到 `alphaClip` 以下时，在 GPU sort 前直接剔除，避免分配 slot/cache/sort key。对大面积 selection/filter/hide 的 WebGPU 场景有直接收益，但没有给出统一百分比。
- [f6aa19b4 / PR #9964](https://github.com/playcanvas/engine/commit/f6aa19b4f9db09a1296657328cd28cf82dae03c9)：统一 GS 抗锯齿默认 filter size 从 0.3 px² 改为 0.1 px²，匹配 Mip-Splatting、Brush mip 和 SOG v3 opacity profile 的口径。旧项目若依赖 0.3 视觉，应显式设置并做截图回归。
- [a000424d / PR #9966](https://github.com/playcanvas/engine/commit/a000424d04a1f9a07e139c353b7ff39c623181a7)：删除隐藏的 legacy GS picking example；这是示例清理，不等于移除统一渲染器 picking。新增 [villa sales demo](https://github.com/playcanvas/engine/commit/5bf06fc842ecbc1d328cdc59e6ce7b09170aac1f) 展示 depth-tested mesh overlay、场景/列表 picking、fly-to/orbit 和 SOG 场景交互，模型本身为 CC-BY-NC-4.0。

**对 Editor / Viewer / SplatTransform 的现实影响：** 窗口内 [SuperSplat editor](https://github.com/playcanvas/supersplat) 没有新 commit；Viewer 与 SplatTransform 只有 Node 26 CI/依赖更新（[Viewer 10b6f81a](https://github.com/playcanvas/supersplat-viewer/commit/10b6f81a2479bb8fe40c1beacf7f64c15ea77518)、[SplatTransform fc5bbd63](https://github.com/playcanvas/splat-transform/commit/fc5bbd632c25f9173ba819264723466ae8296e65)），没有用户态 GS 功能。SOG v3 尚未成为 SplatTransform 默认输出，v2-only reader 必须拒绝 v3；当前最稳策略是保留 v2 canonical asset，同时在 staging 测 v3 reader、blind field shader 和 deep-LOD opacity。SPZ/PLY/GLB/glTF、camera/path、publish API、shared viewer settings、XR 与 editor selection 本窗口无直接新增。

## 3. 可实际运行的开源项目

### Gaussian-Splat-Lite v1.7.0

[v1.7.0 release commit](https://github.com/WilliamLiu-1997/Gaussian-Splat-Lite/commit/7774bdd759a42e3601f606ba98fe03bd1641bada) 对 Three.js WebGPU/WebGL2 viewer 是实际 breaking update：RAD/SOG 的共享 SH palette 贯穿普通加载与 streaming，不再在 CPU/GPU 展开为 per-splat SH；同一内存预算可容纳更多流式细节。为保证 palette 不被 load-time transform 破坏，`postDecode` 移除 `alpha/color/sh`，仅保留 position/scale/quaternion/opacity；颜色编辑应改用 mesh property 或 SDF。许可 Apache-2.0，安装 `npm install gaussian-splat-lite three`，应先用同一 SOG/RAD 记录首帧、峰值 CPU/GPU 内存、SH 视角变化和 LOD pop。

## 6. Compression / Format / LOD / Streaming

- [SOG v3 proposal #362](https://github.com/playcanvas/splat-transform/issues/362) 的关键变化已在 Engine reader 实现：rotation 纹理从 20→16 B/splat（无 SH）或 24→20 B/splat（有 SH）的格式侧设计；opacity 最高 1.5625；SH 1–4 bands、24-bit labels；typed blind textures；`extras/comments` 元数据。注意这些是格式设计数字，不是端到端显存/带宽 benchmark。
- **兼容性**：v2-only reader 必须拒绝 v3；v3 reader 可继续读 v2。没有证据表明 SuperSplat Editor/Viewer、第三方 Three.js/Unity/Godot reader 已全部支持。上线资产建议 v2/v3 双产出并把 version 放入 CDN cache key。
- **GSL v1.7.0**：保留 RAD/SOG SH codebook，减少展开内存；streaming 的 memory budget 因而更有效。它没有宣称支持 PlayCanvas SOG v3，不能把“共享 palette”误写为 v3 兼容。
- **HIBS**：闭式、shape-preserving merge 构建 beta-splat LOD hierarchy；输出 `hierarchy.ply` + `hierarchy_shape.npz`，或 embedded checkpoint。标准 3DGS viewer 若不理解 beta shape 只能看到退化表示。
- SPZ 4、compressed PLY、KHR_gaussian_splatting、OpenUSD、3D Tiles、MPEG GSC 与 WebGPU 标准在窗口内没有新的正式批准版本。

## 7. Training / Reconstruction / SLAM / Robotics / Mapping

### 固定相机遮罩：很小的输入改动，直接修掉 360° 重建中的伪内容

[visloc-rs 70bc595c](https://github.com/rsasaki0109/visloc-rs/commit/70bc595c86c75cfbb70aee5f3d2eb6017716a9e0) 的 `--camera-mask` 只需一张与相机坐标固定的 mask；与逐图 mask 同时使用时，只要任一 mask 排除像素就剔除，`--flip-mask` 对两者一起翻转。作者 FIORD 200° 实验的 mask 只占 image circle 1.8–2.0%，却改善两个室内场景的大角度 holdout；这说明 tripod 不只是渲染瑕疵，也会污染 geometry/appearance supervision。建议把它纳入 360 rig 的 canonical calibration assets。

### 可跑研究代码

- [AffineGS](https://github.com/eldentse/AffineGS)：Ubuntu、RTX 3090、Python 3.8、PyTorch 2.1.2/CUDA 12.1，依赖 Nerfstudio 1.1.3、gsplat 1.0.0 和 `opencv-contrib` guided filter；无需 sensor depth，用 edge-aware spatial affine field 校正 Depth-Anything-V2 disparity。项目页报告 MuSHRoom mesh F-score 0.71 vs DN-Splatter 0.28、depth error 6× lower 和 sparse LLFF 最多 +4 dB；都是作者口径，先复验自己的室内/少视角数据。
- [P-MGS](https://github.com/yuting01234/P-MGS)：CUDA toolkit + C++ compiler，编译 `simple-knn` 与 `diff-gaussian-rasterization`；支持 NeRF Synthetic/DTU，训练后生成 mesh binding 并执行 affine deformation transfer。代码真实可跑，但外部 motion asset 不随仓库提供。
- [MOMASPLAT](https://arxiv.org/abs/2611.08372)：3DGS + feed-forward geometry foundation model + kinematics action retargeting，为 mobile manipulation 生成含动态物体交互的新视角 demonstration。论文称五个真实任务平均成功率超过最强 baseline 两倍；官方 repo 当前主要是项目网站，未发现可运行训练代码，仍为论文无代码。

固定检查 [nerfstudio-project/gsplat](https://github.com/nerfstudio-project/gsplat)、[WebODM/OpenSplat](https://github.com/WebODM/OpenSplat) 与 [graphdeco-inria/gaussian-splatting](https://github.com/graphdeco-inria/gaussian-splatting)：窗口内没有新的 main commit、release 或安全公告。

## 8. Avatar / Human / Generative 3D

### InstantHand：今天最完整的新 avatar artifact

[InstantHand code](https://github.com/coolho1129/InstantHand) + [Hugging Face checkpoints](https://huggingface.co/coolho1129/InstantHand) 已能用仓库 example 跑 `python demo.py --ids all`。full 权重 1.4 GB 自带冻结 DINOv3，light 0.2 GB 需另取 DINOv3；必须用项目修改版 rasterizer，因为 Reliability-gated Appearance Transfer 要每个 Gaussian 的 rendering contribution。输入自己的照片还需 mask 与 WiLoR JSON。论文/项目属于 NeurIPS 2026；受 MANO、DINOv3、rasterizer和权重条款影响，整体仅适合非商业研究。

### EDGAR：代码公开，但关键权重仍受限

[EDGAR code](https://github.com/kwanyun/edgar-code) 包含训练、单图推理及 RGBAvatar/CAP4D adapter；通过 one-step diffusion + Sapiens identity features + 6-expert MoE 修复 avatar rendering，再用多视图 pseudo-target 优化底层 avatar，使最终播放不需要逐帧 diffusion。环境 Linux/Python 3.10/PyTorch 2.3.1/CUDA 12.1；但 six-expert checkpoint 与数据在 private GitHub repo，未授权用户会看到 404。许可含 NVIDIA 非商业研究/评估条款，当前应标记“代码可审计，权重不可公开即取”。

## 13. 今天最值得实际测试 / 部署

1. **PlayCanvas Engine SOG v3 staging matrix**：从同一 PLY 生成/准备 v2 与 v3 SOG，覆盖 opacity>1 的 deep LOD、SH4、多个 typed blind fields、缺纹理报错、WebGL2/WebGPU 截图和内存；同时确认 v2-only viewer 明确拒绝 v3。门槛是 Engine main build 与自备 v3 test asset；收益是提前验证格式迁移，不污染生产 canonical asset。
2. **Gaussian-Splat-Lite v1.7.0**：选一个带 SH codebook 的大 SOG/RAD，固定 camera path，对比 1.6.x/1.7.0 的峰值 JS heap、GPU texture bytes、首帧、detail residency、视角依赖颜色与 `postDecode` API。门槛低（Node 22.12、Three.js 0.186、WebGPU/WebGL2）；预期收益是流式内存下降，但必须处理 breaking API。
3. **InstantHand public checkpoint**：优先用 1.4 GB full checkpoint 跑仓库 samples，再用 3–5 张自有手图检查 mask/WiLoR 输入、手指边缘 alpha、背面 completion、animation seam 与显存。门槛是 CUDA 11.8、MANO 许可/下载和修改版 rasterizer；收益是今天最完整的单图 Gaussian hand avatar artifact。
