## 2. SuperSplat / PlayCanvas 工具链

**SplatTransform 的 3.7→3.8 是一天内的第二次实际迁移。** [v3.8.0 Release](https://github.com/playcanvas/splat-transform/releases/tag/v3.8.0) 收入两项业务相关改动。

1. [#336](https://github.com/playcanvas/splat-transform/pull/336) 在 `.splat` writer 量化四元数前归一化；过去逐分量 `q*128+128` 后截断，使非单位四元数的方向错误。作者对 1,074,761 行真实 PLY 测得 41.32% 行有分量越过 ±1、160,489 行角度误差超过 5°；修后这项计数为 0，p99 从 13.61° 降到 1.41°。这仅是该数据集与 `.splat` 写入路径的测量，SOG/compressed PLY writer 原本已经归一化。转换器 README 仍把 `.splat` 写成只读，实际命令路径存在，文档需跟进。
2. [#339](https://github.com/playcanvas/splat-transform/pull/339) 移除 `--lod-errors`、生成 error table 的 GPU pass 与 manifest 的 `errors/lodErrors` 新写入。这是 [Engine #9584](https://github.com/playcanvas/engine/pull/9584) 改为纯距离 LOD 的下游清理。旧 manifest 带 `errors` 仍可加载；若脚本还传 `--lod-errors`，现在会报未知选项。PR 报告 836 项测试通过；未声称整套 SOG 下载体积或帧率普遍提升。

[SuperSplat Editor](https://github.com/playcanvas/supersplat/commit/7d0cc6807f845c70add3604033c0d9705c7986b8) 的 `package.json` 升到 **3.5.0**，依赖将 SplatTransform 3.6.4→3.7.0、Engine 2.22.4→2.22.6；查到的 Release 列表最新仍是 v3.4.2，**不能把主分支版本号当正式 Release**。这一依赖更新不包含今天 Transform 3.8.0 的修复；在 Web 编辑器看到的具体版本仍需按部署包核验。

## 13. 今日最值得实际测试与趋势判断

1. **转换正确性**：用未归一化旋转的训练 PLY 跑 SplatTransform 3.7.0 与 3.8.0，比较 `.splat` 方向误差；检查现有管线是否仍传 `--lod-errors`。只在相同输入、相机和解码器下评价。
2. **生产稳定性**：在 LichtFeld `master` 与先前安装包上重现 headless 导出失败、MCMC 3DGUT growth、场景 restore；同时在 Spirula 新 Release 做分区/合并与断点续训 PLY→SuperSplat 导入。训练精度、峰值 VRAM 和失败退出码都应记录。
3. **Web/XR/动态内容**：Viewer 1.36.0→1.36.2 测标注/相机行为，Engine 新 main 测 Quest XR 双启动、退出、头动剔除；Mobile-4DGS 先验证公开 WebGL 场景在目标手机浏览器的首屏、内存和稳定帧，再计划自采训练。

**短期判断**：过去几天的重心已从“单个 splat viewer 能打开”移向可持续生产：格式写入 correctness、分区训练、稳定导出、XR 生命周期和明确 LOD 策略。论文里的压缩/生成/碰撞方向仍需代码、模型、许可和真实设备验证后再升级为项目路线。
