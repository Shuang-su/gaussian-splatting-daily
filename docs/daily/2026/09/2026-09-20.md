旧路径：

```text
每一步
↓
读取 PNG
↓
decode
↓
undistort
↓
float32 image
↓
Host → GPU
```

新路径：

```text
训练前
↓
4 threads
↓
所有图片 decode + undistort 一次
↓
uint8 保存在 Host RAM

训练时
↓
uint8 Host → GPU
↓
GPU 上 /255 → float
```

所以 Host→GPU 每个像素的传输量理论上从 float32 RGB 的 12 bytes 降到 uint8 RGB 的 3 bytes。

### 对格式转换尤其重要的是数值语义终于固定

glTF 里：

**Scale 是线性值。**

```text
>= 0
```

不是经典 INRIA PLY 常见的 log scale。

**Opacity 是 0–1 线性 normalized 值。**

不是训练模型常见的 opacity logit。

所以 PLY → KHR glTF 必须类似：

```text
PLY scale log
→ exp()
→ KHR SCALE

PLY opacity logit
→ sigmoid()
→ KHR OPACITY
```

不能原样拷 byte。

Rotation 也按 glTF quaternion 约定；SH degree 0 必须存在，基础 extension 定义到 degree 3。[原始聊天工具引用，需补一手链接](https://chatgpt.com/share/6abb77e3-2854-83ee-a59d-1b8d31259f88)

### 为什么这对 Metaflow 比“多支持一个格式”更重要

我们以后可以把格式层更明确地划分：

```text
训练 / research
→ PLY

Web streaming
→ SOG / SSOG

轻量交换
→ SPZ

标准 runtime / scene interchange
→ KHR_gaussian_splatting GLB

大型 DCC / VFX
→ OpenUSD
```

而且 GLB 不再是：

> “某个社区 draft”。

它已经是：

> **Khronos ratified KHR extension。**

官方 ratification 同时列出的已知实现包括：

- CesiumJS；
- Cesium Native；
- JSplat；
- `3dgs_ply2gltf`。[原始聊天工具引用，需补一手链接](https://chatgpt.com/share/6abb77e3-2854-83ee-a59d-1b8d31259f88)

shadows / AO / indirect lighting
        ↓

。[Niantic Spatial, Inc.](https://www-website-dev-tf1.eng.nianticspatial.com/blog/introducing-gaussian-splat-relighting)

deferred/frame graph effects

# 13. 今天最值得实际测试 / 部署的 3 项

### ① `KHR_gaussian_splatting` round-trip —— 今天第一优先

既然正式 Ratified，建议马上建立：

```text
PLY
↓
canonical Gaussian
↓
KHR_gaussian_splatting GLB
↓
再导入
```

测试矩阵：

```text
position
rotation
linear scale
linear opacity
SH degree 0–3
colorSpace
node transform
```

尤其要验证：

```text
PLY log-scale → exp → glTF linear scale
PLY opacity logit → sigmoid → glTF 0..1 opacity
```

以及 quaternion 顺序。

然后至少用两个独立 reader：

- CesiumJS / Cesium Native；
- JSplat / 3dgs_ply2gltf compatible tool；

做交叉验证。

**预期收益：** 一旦这条过了，Metaflow 可以把 GLB GS 从“实验兼容格式”升级为正式标准 interchange。

禁止：

## 今日结论

今天最重要的不是又一个新的 Gaussian 论文，而是三个“工业化层”的变化同时出现。

**第一，标准层终于需要纠正记录：`KHR_gaussian_splatting` 已经正式 Ratified。** 这意味着 glTF Gaussian 现在有了一个稳定的、厂商共同认可的基础语义，而不再只是互相试验的 draft。

**第二，SuperSplat Viewer 正从“可嵌入 Viewer”继续变成“真正可编程 Viewer component”。** #302 给出来的 seek、walk、movement、annotation、XR API，正是 Metaflow 要减少 DOM hack 和深 fork 所缺的一层。

**第三，训练和产品化都开始围绕“复用已有工作”优化。** gsplat 在复用已解码图像，Spirula 在复用已有 Gaussian，LichtFeld 在保证编辑后的 SOG 和项目写入一致性，Niantic 则在复用同一份 geometry 生成不同光照条件。

整体趋势已经非常明显：

> **3DGS 生态正在从“训练一个漂亮模型”转向“标准化资产 + 可编程运行时 + 可恢复项目 + 可增量训练 + 可配置现实场景”。**
