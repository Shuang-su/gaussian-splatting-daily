# metaflow horizon 内容、写作与排版规范

适用范围：日报阅读版、论文解读、工具解读、周报和专题。本文是人工编辑、每日任务与发布校验共同采用的编辑契约。任务切换与运行验收以实际发布记录为准。

## 读者与信息层次

同时服务想快速了解动态的读者、需要判断采用条件的创作者，以及准备复现的开发者。速览回答“发生什么、影响什么”；正文解释背景、变化和实际含义；可展开深读保存参数、实验口径与复现步骤。不要把重要的版本状态、依赖、许可限制或尚未复现的事实藏进折叠区。

第一次出现且影响理解的术语先用中文解释，再给简称。例如“层次细节（LOD）”“球谐系数（SH）”。项目专名、API 和格式名遵循官方拼写；文件名、参数和命令使用行内代码或代码块。中英文、中文与数字之间保留适当空格；单位和百分比按其约定书写，不用自动替换破坏 URL、代码或数学表达式。

## 标题、导语与段落

标题写具体对象及变化，避免只有项目列表、P0/P1、抽象价值判断或内部研究栏目。摘要与标题分工：标题指出核心变化，摘要补充影响与另一条主线。不要重复一遍标题，也不要在新闻中用作者口吻假装亲测。

一段围绕一个意思展开。先给可核验事实，再解释用途或影响，最后交代必要条件；根据内容调整顺序。不能为满足字数机械拆段，也不能把所有版本号、平台和参数塞进首段。长度提示只是复查线索。

正文使用 H2 组织独立问题或主要事件，H3 解释其下的方法和步骤，避免跳级。日报阅读版每个 H2 对应一个稳定事件；更细的结构放在 H3 或深读中。编号列表用于有先后关系的步骤；无序列表用于并列信息；可用自然段说清的内容不改写为表格。

## 五种文章的行文逻辑

| 类型 | 核心问题 | 推荐顺序 | 必须说明 |
|---|---|---|---|
| 日报 | 今天发生什么，谁受影响 | 核心变化 → 用途或背景 → 条件与状态 → 来源；简讯可压缩为一段 | 观察日期、正式版或分支、是否独立复现、补收与纠错 |
| 论文解读 | 解决什么问题，方法为何可能有效 | 问题 → 核心机制 → 实验对象和比较 → 限制 → 可复现入口 | 作者报告与本地结果分开，数据集/设备/基线/指标口径，代码和权重状态 |
| 工具解读 | 对工作流有什么改变，怎样判断适合自己 | 使用场景 → 关键机制 → 参数或操作 → 验证方法 → 适用范围 | 固定版本、平台与依赖；教程步骤是否实际执行；许可证不能由仓库公开推断 |
| 周报 | 一周变化之间有什么联系 | 本周判断 → 2–4 条相关主线 → 后续核对重点 → 日报入口 | 实际覆盖日期和缺期；不能把每天标题拼成正文；未结束的一周不冒充完整周报 |
| 专题 | 一个跨工具问题如何理解与判断 | 问题边界 → 解释框架 → 来源支持的例子 → 对比或检查方法 → 适用条件 | 不同来源的版本和时间、判断依据；方案与已完成验证分开 |

表中的顺序是编辑起点，不是固定段落或字数配额。模板在 `docs/templates/`，发布前删除模板提示，并补齐真实元数据。

## 来源与事实边界

优先正式发行说明、固定提交、官方文档和论文。链接紧邻它支持的结论；多项独立变化需要各自来源，不能用项目主页暗示已核对全部实现。论文标题保留中文阅读标题，同时把原文中可验证的英文题名保存在搜索元数据中。

“已有网页”“已有仓库”“代码已公开”“可运行”“在目标设备上验证”是不同状态。参数、速度、画质和内存收益必须交代条件。下载字节、驻留缓存、进程内存与显存不互换；作者数字明确归属。历史报告保留当时观察点，不把今天找到的材料无提示地倒填为当时已知事实。

AI 参与整理或撰写时，说明辅助范围、核验范围及未执行的实验。少数派平台的投稿和 AI 内容政策是参考站自身规则；高斯日报不冒充其投稿，也不把其审核结论套用到本项目。

## 深读块

仅允许以下容器语法；不接受自定义 HTML、属性、脚本或其他指令。

```markdown
:::details[参数与实验条件]

保留完整、可复制的参数，并解释它影响什么。风险与关键前提应同时出现在可见正文中。

:::
```

原生 `details / summary` 支持鼠标、键盘和无脚本阅读。嵌套标题仍保留锚点，定位时展开父级。打印时自动展开，打印结束后恢复原先状态。不要将文章唯一结论仅放在深读块中。

## 图片、图注与封面

图片应帮助说明操作、机制或结果；没有合适证据时可以没有配图。优先对应版本的一手图示。每条主要事件记录“采用/未采用及原因”，不以图片数量决定质量。

项目图不能被用于证明未展示的更新或性能结论。面向读者的图注只说明画面内容并给出来源，不附加“历史素材”“非本次更新截图”等编辑过程说明；素材版本、采用理由与核验记录保存在仓库变更文档中。示意图可以由 ImageGen 生成，但需明确是示意图，不能伪装成软件实测、论文结果或产品官方素材。不得生成无法核验的数值图来填补证据。

事件图片置于相关完整段落之后，使用 `afterParagraph` 指定从 1 开始的正文段落序号；未指定时放在事件末尾。图注包含画面含义、出处及必要限制。封面保留现有日历和标题分区，所有尺寸断点使用相同语义，不让竖图撑开整个头部。媒体清单及容量规范继续遵循 `docs/daily-event-authoring.md`。

## 研究记录与阅读版

`docs/daily/YYYY/MM/YYYY-MM-DD.md` 仍是规范研究记录。阅读版存放于 `docs/reading/YYYY-MM-DD.md`，通过 `report` 和原文件完整字节的 SHA-256 绑定，不覆盖原文、不改首次论文归档日期、事件身份、RSS GUID 或旧锚点。

v2 事件记录原研究块的 `sourceRefs`、主来源、内容类型和四维标签。`sourceRefs` 来自 Markdown AST 内容块的实际 key，不能手造；可通过 `site/lib/editorial.ts` 的 `sourceBlocks` 读取。只修改阅读版不重新计算研究文件哈希。研究内容确实改动时，先核对差异，再重建绑定，不能只更新哈希绕过过期检查。

重复监控栏目、无变化记录和历史技术细节继续在“研究归档”保留；阅读版重组并不代表删除研究范围。`paperTitles` 是阅读或目录标题，`paperOriginalTitles` 保存原文可证实的题名，不能把栏目名当作论文题名。

独立文章位于 `docs/articles/`，必须有 genre、title、summary、date、author、topics、related、sources、disclosure。专题使用 genre=topic；论文与工具分别使用 paper / tool。相关事件必须存在于真实日报中。周报位于 `docs/weekly/`，绑定该 ISO 周所有现有日报的日期与内容哈希，发行日期必须晚于该周结束日。

## 校验与编辑复查

构建硬校验：身份/锚点唯一、原文哈希匹配、事件与正文对应、研究块可定位、来源在规范原文中、许可的深读语法、相关事件存在、周报绑定完整、导出链接与资源可用。`check_editorial.py` 进行前置摘要和覆盖检查；完整块映射仍由 TypeScript 内容构建验证。

`npm run lint:editorial --prefix site` 在硬校验后列出长段、笼统标题和密集行内参数等建议。告警不自动删内容，也不通过关键词判断“好文章”。编辑还要核对事实归属、术语、时间、许可和因果关系；自动化不能证明这些语义正确。

交付前至少运行：

```sh
python3 scripts/validate_daily.py --all
python3 scripts/check_editorial.py --all
npm run lint:editorial --prefix site
npm test --prefix site
npm run typecheck --prefix site
npm run build --prefix site
python3 scripts/verify_export.py
```

浏览器核对桌面、平板横竖屏与手机：标题换行、正文行长、来源与图注、表格局部横向滚动、深读键盘操作、目录锚点、搜索与旧链接。检查浅色、暗色和减少动态效果设置。浏览器尺寸模拟不能代替真实 iPad/iPhone 的触摸、Safari 返回手势和显示效果验收。

## 正文脚注与发布后修订

正文可以使用标准 Markdown 脚注。脚注用来补充术语、背景或数据比较口径，引用链接仍应贴近对应的事实。读者必须能在正文看到会影响判断的发布状态、兼容条件、限制和更正后的结论。用短而稳定的脚注标识，并逐一检查跳转和返回位置。

发布后如果补充新的材料、修正重要事实或改变建议，在「更新」中注明日期、涉及的问题和变化依据，提供可核查来源。正文同步修正受影响的表述，更新区交代读者以前看到的内容发生了什么变化。日报阅读版的修订记录使用稳定的条目 ID，保留原研究文件的字节绑定。旧研究文件本身确需更正时，按研究记录的更正流程处理。

同一问题的多项相关进展可以在一个 H2 下用具体 H3 展开，例如同时变化的格式写入器和读取器。需要独立定位、讨论或归档的事件保留自己的 H2 和稳定身份。样本和统计口径见 [2026 年 11 月参考研究](changes/20261113-reader-upgrade/content/reference-study.md)。

## metaflow horizon 编辑契约（2026-11-13 起）

总品牌为 metaflow horizon，“高斯日报”是每日栏目。范围包括高斯、摄影测量、扫描、NeRF、空间 AI、XR、工具、作品与行业应用。选题按读者影响、新颖性和证据质量排序，开源、可编译或能立即部署不再决定新闻优先级。相关领域内容可独立成文，无需附加与三维工作流的关联说明。

采用少数派公开规范中适合本刊的内容与排版原则：不预设读者具有专业知识；写明具体问题、变化和用途；核对事实归属，保留必要限制；专名、数字、标点、空格和链接一致；语义标题组织段落；图文相邻，图注说明画面及出处。本文是本刊自己的编辑规则，少数派的投稿、精选、报酬与平台审核制度不迁入本项目。

参考来源于 2026-11-13 重新读取：[少数派风格指南](https://manual.sspai.com/rules/manual-of-style/)、[作品审阅规则](https://manual.sspai.com/rules/rules-of-review/)、[文章创建与编辑](https://manual.sspai.com/guides/using-the-editor/)。

主标题交代事件，摘要补充影响；避免标题堆项目名，或摘要继续堆文件名、版本号和参数。重点正文至少解释对象、变化、读者影响与条件；用连贯段落展开，不能把原始研究机械压成两段。需要更新、重转、购买或改变流程的建议必须限定对象，并说明依据。性能提升必须带测试条件和作者归属。

同一事件可以将多个项目的配套变化合并解释，但保留稳定身份、旧锚点和各自来源。简讯允许简短，重要事件不能因字数预算而消失。原研究范围作为后台检查清单，不要求读者逐一阅读固定 13 栏。工具、App 和商业服务可进入头条，论文无代码不自动降级。

应用栏目使用 app 类型，提供平台、费用口径、核对日期、限制及 experience。researched 表示资料核验，tested 仅用于确实完成体验的内容；没有体验不得使用评测结论或第一人称操作描述。动态价格写核对日期，无法确认就明确不确认。

来源记录使用 data/source-registry.json 与 data/research/YYYY-MM-DD.json。每个候选明确 included、merged、deferred 或 excluded 及理由，重要事件不得静默 deferred。与主题无关、证据不足或重复的排除必须有证据；来源访问失败与未检查都不能变成无新增。X 原帖保存具体状态链接与可见范围，不能只列账号主页。每天检查增量窗口并重叠回看 7 天；来源发现链接与最终事实来源同时保留。

阅读稿通过 sourceHash 绑定原稿，通过 supplements 的 path、sha256 绑定补充记录。补充记录标明 report 与 addedAt，保留原事件日期；发布后实质修订进入 update-N 修订区。固定旧提交提供原版入口，不能修改哈希来掩盖内容变化。已读记录、论文首次归档与 RSS 身份保持稳定。

编辑自查分为两次：先核对事实、来源、日期和采用条件，再以普通读者身份检查标题、摘要、术语、段落及信息遗漏。自动校验只保证结构与映射，不证明文章语义正确。内部缺口清单保存在仓库；正文只展示会影响读者判断的限制。
